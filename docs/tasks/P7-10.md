### Product fixes (each with its regression test)

1. **The context-menu submenus never opened** (`fix(ui)`,
   `52db77c`): `PanelClassic::context_menu` drew one level and closed
   on any row click, so a context menu's submenu rows showed their ▸
   but the children were unreachable. The drawn levels now follow a
   state chain (`context_chain`) like the menu bars: a click opens the
   submenu at once, a hover after the submenu delay, a leaf click
   dispatches and closes. Regression tests:
   `menus::a_context_menu_submenu_opens_its_children` and the
   `menus::every_context_menu_opens_and_dispatches` sweep (which the
   fix made pass).
2. **The Panel Classic theme lacked tokens the widgets read**
   (`fix(ui-spec)`, `99f96a1`): `page.shadow` (the canvas fell back to
   its egui default) and the whole Panel Modern metric vocabulary
   that `Metrics::from_theme` reads against every theme (it silently
   used the widget defaults). Both additions are value-neutral
   (`#eaeaea` is the fallback colour; the metrics are the
   `Metrics::default()` numbers). Regression test:
   `theme_tokens::every_theme_token_the_widgets_read_exists_in_both_themes`.

### Findings and open issues

1. **The Panel Modern command-bar labels wrap** (visible in the
   goldens): a large split's label row (label + ▾) is wider than the
   width `measure_widths` measures (`text + 8`, no arrow or padding
   allowance), and the atoms' text renders wider than `text_width`'s
   fixed 12 px measure, so labels such as "Paste" and "Font Size"
   wrap vertically. The controls all dispatch correctly (the sweeps
   pass); the look needs the P7-14 fix pass. Regenerate the goldens
   after it.
2. **The QAT customise dropdown cannot open through the registry**:
   `view.qat.customize` is a Phase 7 stub, so the button renders
   disabled and its display-only menu (the current items, checked) is
   unreachable in the app (P7-07 drives it with a test resolver).
   Decide whether a menu opener should render enabled without a
   command (`modern::the_quick_access_toolbar_dispatches_and_opens`
   pins today's behaviour).
3. **Panel Modern option rows dispatch without the `value` argument**
   (P7-09's "not yours" list): a combo's choice reaches the command as
   the item's own id with empty args, while the Panel Classic menus
   carry `value`. The sweep asserts the command id there; the fix
   belongs with the command descriptions work.
4. **The toolbar popups' submenus open on a stateless hover**
   (`toolbar::draw_popup_level`): moving the pointer into a child
   level closes it, the bug class the context-menu fix addressed. The
   committed toolbars have no enabled nested rows, so the sweep passes;
   the fix is to give the popups the `context_chain` treatment.
5. **The right-click routing gap** (P7-09 open issue 3) stays: the
   shell routes the canvas, Shift+F10 and the Shapes window, and
   `contexts::menu_for` maps the other targets (page tab, window
   title, ...). The sweep opens every committed context menu through
   the same widget seam the shell draws with.
6. **The kittest node rectangles cannot pin exact widget positions**:
   `Node::rect` is the accesskit subtree bounds (transformed, wider
   than the widget for the painted atoms). The placement test
   therefore checks the placement model with the real theme metrics
   plus the rendered one-widget-per-control ordering.
7. **`egui_kittest::Harness::run` never settles with an open
   tooltip** (it repaints): the test rigs run `run_steps`, and the
   frame clock advances 1/60 s per frame for the submenu hover delay.
8. **The floating toolbars' windows cover the docked rows and eat
   clicks** at their default positions; the toolbar sweep hides them
   (`menus::show_all_docked`).
9. The `layout_v2` fuzz target found no product crash in 500 runs of
   its seeds (its one "crash" was the harness dropping unapplied
   `TexturesDelta`, fixed in the target). It shares the scratch
   workspace pattern with `loader_fuzz`.

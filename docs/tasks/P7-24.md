### Why P7-21's tests passed while the controls did nothing (acceptance)

1. **P7-21's tests never drove the UI input path.** Its suites
   dispatched commands over a prepared session (proving the command
   layer), and its widget tests drove `PanelClassic` standalone with no
   canvas underneath, so a picker click had nothing to leak to.
2. **The app read raw pointer input in the canvas with no layer
   check.** `tool_events` in `canvas.rs` took every press over the
   canvas viewport, so a press on a picker or menu popup also reached
   the canvas under it: the pointer tool's press handler cleared the
   selection, then the format command ran a moment later with "no
   selection" and did nothing. That is why every colour, line, font
   and size control looked dead. Item 0's fix is P7-22's
   `press_lands_on_canvas` gate (`layer_id_at` is `None`, the canvas
   layer, or a Tooltip layer) on `PointerDown` and `DoubleClick`.
3. **Item 1's own gaps** (fixed in `18956f6`/`d7df846`): the Format
   menu had only dialog stubs; Panel Modern's Line split Weight/
   Dashes/Arrows submenus were empty `List` items; disabled controls
   showed their reason only as hover text (`on_disabled_hover_text`
   does not call `describe_for_accessibility`, so the reason is now
   also the accessible description).

### Decisions (reopened none; details the note did not record)

- **Item 11 rung order**: the page's own cell → its style chain → the
  background page (recursive, capped at 4) → the Letter fallback. The
  model's `resolve_page_cell` has no background rung (ADR 0019), so
  the dialog adds it; see Open issues for the canvas.
- **Format Painter routing** covers the Pointer tool only: with a copy
  recorded, the other tools keep drawing. A release over empty page
  applies nothing and keeps the copy.
- **The transparency preview colour** is the selection anchor's
  resolved `FillForegnd` (neutral grey when unreadable), not a fixed
  swatch: the goal says "the fill colour".
- **`cancel` flag on `tools.format_painter`** rather than a new
  command id (the registry row already exists).

### Test harness findings (for whoever writes the next canvas test)

- A synthetic click must put press and release in **one frame** (one
  harness run steps the clock past egui's click time).
- Egui's triple-click rule: an earlier click inside
  `max_double_click_delay` turns the double click's second click into a
  triple click (`click.count == 3`, so `double_clicked_by` stays
  false). `double_click_at` drains the window with 60 runs first.
- The in-place editor's field is `Role::MultilineTextInput` named
  "Text" (the earlier hand-off note said `Role::TextInput`).
- "No Fill" on a clicked shape removes its interior hit target (the
  later canvas clicks land on empty page): use a light swatch when a
  later click must hit the shape.
- A picture shape's placeholder mark sits at its centre: sample its
  fill away from the middle.

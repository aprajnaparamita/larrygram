## Why

The P7-37 review (2026-11-03) found that `DocumentSession::dirty` is
never set in production code: only saves clear it. The master
confirmed it, and also that `app.quit` checks nothing. So closing an
edited drawing, choosing Quit, pressing Cmd+Q or closing the window
all discard unsaved work without a word.

## Goal

1. **One rule for "changed since save"** (ADR 0040 amendment). A
   session is changed when its change counter differs from the counter
   recorded at the last open or save. Every edit, undo and redo moves
   the counter, so `dirty` becomes a derived read (`is_dirty()`), not a
   flag anyone must remember to set. Undoing back to the saved state
   still reads as changed (simple and safe; say so in the ADR). A
   fresh `file.new` drawing with no edits is not changed. The P7-37
   undo group's `unsaved` snapshot uses the same rule, so a cancelled
   empty text box leaves the drawing unchanged.
2. **Close asks.** `file.close` on a changed drawing, from an
   interactive source, shows the confirm dialog with three choices:
   Save, Don't Save, Cancel. Save runs the normal save (Save As for a
   drawing with no path) and closes only if it succeeds. Programmatic
   sources keep today's rule (no dialog; `confirm` decides).
3. **Quit asks.** `app.quit`, `file.exit`, Cmd+Q (Ctrl+Q off macOS) and
   the window's close button go through one path: for each changed
   drawing in turn, the same three-way dialog; Cancel stops the quit.
   The window close request is cancelled while a dialog is open (eframe
   `ViewportCommand::CancelClose` on `close_requested`). On macOS,
   Quit from the app menu takes the same path.
4. **Show it.** The window title, and the document tab where there is
   one, mark a changed drawing (our own marker, for example a dot
   before the name). Check how the title is set today and keep one
   place for it.

## Tests

- **Commands**: `is_dirty` after open, after each kind of edit, after
  undo and redo, after save and save-as, after a cancelled undo group;
  `file.close` on a changed drawing from each source kind.
- **Real input** (egui_kittest, full shell, Panel Modern and Panel
  Classic): edit a shape, then close from the File menu or backstage:
  the dialog appears; Cancel keeps it open and changed; Don't Save
  closes it; Save writes the file (a temp path through the test file
  picker) and closes. The same through Quit with two changed drawings,
  including Cancel on the second. The window close request with a
  changed drawing is cancelled and shows the dialog. The title shows
  the marker after an edit and loses it after a save.

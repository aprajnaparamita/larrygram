## Why

The P7-37 review (2026-11-03) found that `DocumentSession::dirty` is
never set in production code: only saves clear it. The master
confirmed it, and also that `app.quit` checks nothing. So closing an
edited drawing, choosing Quit, pressing Cmd+Q or closing the window
all discard unsaved work without a word.

## Goal

1. **One rule for "changed since save"** (ADR 0040 amendment). A
   session is changed when its change counter differs from the counter
   recorded at the last open or save. Every edit, undo and redo moves
   the counter, so `dirty` becomes a derived read (`is_dirty()`), not a
   flag anyone must remember to set. Undoing back to the saved state
   still reads as changed (simple and safe; say so in the ADR). A
   fresh `file.new` drawing with no edits is not changed. The P7-37
   undo group's `unsaved` snapshot uses the same rule, so a cancelled
   empty text box leaves the drawing unchanged.
2. **Close asks.** `file.close` on a changed drawing, from an
   interactive source, shows the confirm dialog with three choices:
   Save, Don't Save, Cancel. Save runs the normal save (Save As for a
   drawing with no path) and closes only if it succeeds. Programmatic
   sources keep today's rule (no dialog; `confirm` decides).
3. **Quit asks.** `app.quit`, `file.exit`, Cmd+Q (Ctrl+Q off macOS) and
   the window's close button go through one path: for each changed
   drawing in turn, the same three-way dialog; Cancel stops the quit.
   The window close request is cancelled while a dialog is open (eframe
   `ViewportCommand::CancelClose` on `close_requested`). On macOS,
   Quit from the app menu takes the same path.
4. **Show it.** The window title, and the document tab where there is
   one, mark a changed drawing (our own marker, for example a dot
   before the name). Check how the title is set today and keep one
   place for it.

## Result

### What changed (items 1 to 4)

1. **One rule for "changed since save"** (ADR 0040 amendment
   2026-11-03). `DocumentSession::dirty` is gone;
   `DocumentSession::is_dirty()` derives the answer from
   `changes != saved_changes` (`saved_changes` is the counter recorded
   at the last open or save; `mark_saved()` records one). Every edit,
   undo and redo moves the counter already (ADR 0040 rule 3), so
   nothing has to remember to set anything, undoing back to the saved
   state still reads as changed (the ADR says so on purpose), and a
   fresh `file.new` drawing is not changed. The P7-37 undo group's
   `unsaved` snapshot takes the same derived read when the group
   opens, and `cancel_group` restores its verdict: a cancelled empty
   text box leaves the drawing unchanged.
2. **Close asks.** `file.close` on a changed drawing from an
   interactive source returns `UiRequest::ConfirmClose` and the
   shell's dialog has the three choices Save, Don't Save, Cancel (the
   labels are short command labels; the prompt text is ours). The
   answers re-dispatch the command: Save as `file.close` with `save`
   (the normal save body — Save As through the picker for a drawing
   with no path — and the close runs only when the save succeeded, the
   wasm download payload passing through), Don't Save as `confirm`,
   Cancel as nothing. `confirm` and `save` are mutually exclusive.
   Programmatic sources keep their rule: no dialog, `confirm` closes
   without asking.
3. **Quit asks.** `app.quit`, `file.exit`, the Cmd+Q (Ctrl+Q off
   macOS) chord and the window's close button go through one walk in
   the shell: for each changed drawing in turn the same dialog, each
   answered drawing closed by the same `file.close` answer commands.
   Cancel stops the walk with the remaining drawings open and changed;
   a cancelled or failing save stops it too. The window close request
   is cancelled while the walk is up or has something to ask
   (`ViewportCommand::CancelClose` on `close_requested`), and the walk
   completes with the viewport close. The chord is one `Ctrl+Q`
   OWN_SHORTCUTS row (our own binding). On macOS, Quit from the app
   menu takes the same path: `apps/larrygram/src/macos_terminate.rs`
   (the ADR 0074 `NSObject` method injection) answers
   `applicationShouldTerminate:` with `NSTerminateCancel` and queues a
   quit, which the next frame drains as one `app.quit` dispatch
   (`Source::Menu`). That path also ends in a graceful event-loop
   exit, so eframe's settings flush runs on the app-menu Quit too.
4. **Show it.** `Shell::title_text` is the one place the marked name
   is computed: our own marker, a dot before the name ("• Untitled"),
   and every layout's title bar draws it. `Shell::window_title`
   composes the OS title ("• Untitled - Larrygram"; the app name alone
   with no document) and `Shell::sync_window_title` sends one
   `ViewportCommand::Title` per change.

### Open issues

- **The document tab where there is one.** No layout draws a document
  tab today (both Panel layouts show the document name in their title
  bars). The marker flows through the single `title_text`, so a future
  document tab picks it up there; the Window menu's document rows and
  the File view's Info page keep the plain name.
- **The web app** (`larrygram-web`) has no window close and no
  app-menu Quit: `app.quit`, `file.exit` and Ctrl+Q run the same walk,
  so unsaved work is asked about, and the completion's viewport close
  is a no-op in the web backend (the tab stays open). A drawing close
  works as on the desktop, and the Save answer hands the package back
  as the browser download (ADR 0036) before the drawing closes.
- A save dispatched **while a shell undo group is open** now ends the
  group first (see the deviations); the ADR rule restores the
  snapshot's verdict in every case the app can reach. The command seam
  alone still allows a save inside a group — its cancel restores the
  verdict the group saw, which can differ from the file the mid-group
  save wrote. Unreachable from the app; named in the ADR.
- `default_save_name` (`crates/commands/src/builtins/file.rs`) warns
  `dead_code` in the wasm build (pre-existing: only the desktop
  no-target save uses it). The wasm step prints the warning and
  passes.
- The quit walk closes each answered drawing as it goes (the task's
  own dialog behaviour, "Don't Save closes it; Save writes the file
  and closes"), so Cancel on a later drawing leaves the earlier
  answered ones closed. Pinned by
  `quit_asks_about_each_changed_drawing_and_cancel_stops_it`.

## Facts (master, 2026-10-25)

Observed behaviour of Visio (AGENTS.md section 4); the repo records
the facts only:

- A `.vsdx` package does not open without a windows part. The
  smallest accepted form is three entries, all required together:
  1. a part `/visio/windows.xml` whose root is `<Windows/>` in the
     namespace `http://schemas.microsoft.com/office/visio/2012/main`
     (an empty element is enough; no `Window` child is needed);
  2. a relationship from the document part to it, type
     `http://schemas.microsoft.com/visio/2010/relationships/windows`;
  3. an `Override` for `/visio/windows.xml` with content type
     `application/vnd.ms-visio.windows+xml`.

  Style sheets, document properties, a theme and masters are not
  needed for the file to open. None of the eleven
  `corpus/fixtures/render-*.vsdx` files has the windows part, and our
  writer has no notion of it, so a document Larrygram creates from
  nothing, or an imported `.vsd` saved as `.vsdx` (P8-09), most likely
  does not open either.
- A page referenced through another page's `BackPage` is drawn behind
  it only when it is marked `Background="1"`. In
  `render-background-pages.vsdx` page 1 is referenced but not marked,
  so it is an ordinary page and nothing is composited, while our
  renderer composites it.

## Goal

1. **The writer emits the windows part when the package has none**:
   the part, the relationship and the content-type override above,
   with the next free relationship id. A package that already has a
   windows part keeps it byte for byte. Check [MS-VSDX] for what it
   says about the windows part and cite it in the ADR amendment.
2. **Background pages are consistent on write**: decide, against
   [MS-VSDX], what the writer does when a page is referenced as a
   `BackPage` but not marked `Background` (mark it, or warn and leave
   it). Write the decision into the ADR amendment.
3. **The fixtures**: the builders produce the windows part, and
   `render-background-pages` marks its background page the way Visio
   does. Regenerate the fixtures, their fuzz-seed copies and the
   goldens that change; look at every changed PNG and name it in the
   Result. `ATTRIBUTION.md` and `corpus/PROVENANCE.md` rows stay as
   they are unless a file is added or renamed.
4. **A structural test** (`crates/vsdx/tests/package_completeness.rs`): every
   package our writer produces in the test suite (a new document, an
   edited corpus file, an imported `.vsd` saved as `.vsdx`, every
   fixture) has the three entries above, and every page referenced as
   a `BackPage` is a background page.
5. **ADR**: amend the Phase 2 writer ADR (or write a new one) with
   the windows-part rule and the background-page rule, citing
   [MS-VSDX] where it states them and observed behaviour (AGENTS.md
   section 4) for the rest.

### What changed

- **The windows part on write** (`crates/vsdx/src/write/mod.rs`): both writers
  run `ensure_windows_part`. A package with no windows part (none named
  `/visio/windows.xml`, none with the windows content type) gets the three
  entries: an empty `Windows` root in the Visio namespace, a relationship from
  the document part with the next free relationship id, and the `Override`
  with `application/vnd.ms-visio.windows+xml`. A package that already has a
  windows part keeps it exactly as it is; only a missing relationship or a
  missing override is added.
- **Background pages are consistent on write. Decision: mark it.** [MS-VSDX]
  `Page_Type` requires `BackPage` to name a page whose `Background` value is
  true, and Visio silently draws nothing behind a reference to an unmarked
  page, so the writer marks what it references: `Background="1"` on the target,
  keeping a `true` spelling, flipping a false one, at the first element of a
  repeated `ID` (the page the reader resolves to). "Warn and leave it" was
  rejected: it writes packages Visio misdraws and the writer has no warning
  stream.
- **The reader consumes the derived mark** (`crates/vsdx/src/read/mod.rs`, see
  Deviations): `Background` on a page another page references is not preserved
  (the model holds the reference, the writer writes the mark again); a mark on
  a page nobody references stays preserved verbatim.
- **One deflate pass** (`crates/vsdx/src/package/write.rs`, the master's note):
  the zip writer's own deflate is measured where it lands (at a sync flush, a
  few bytes short of the finished stream, so the cap test can only err in the
  safe direction) and only an entry the reader's compression-ratio cap refuses
  is thrown away and rewritten, stored. Each part is deflated once instead of
  twice. `flate2` is no longer used by the crate directly; the dependency stays
  to pin its pure-Rust backend for zip (ADR 0014).
- **Fixtures** (`crates/vsdx/tests/common/mod.rs`): every well-formed fixture
  carries the windows triple, and `render-background-pages.vsdx` marks its
  background page `Background="1"` the way Visio writes it. All 22 committed
  fixtures regenerated, plus the four seed copies in
  `crates/render/fuzz/corpus/render_document/`. `ATTRIBUTION.md` and
  `corpus/PROVENANCE.md` rows unchanged (no file added or renamed).
- **Tests**: `crates/vsdx/tests/package_completeness.rs` (11 tests: the triple
  and the mark rule on new documents of all three kinds, every fixture as
  built and as written again, corpus writes unedited and edited, an existing
  windows part untouched and a second write byte-identical, the mark rules
  `None`/`0`/`true`, and the reader's consumption), unit tests in
  `write/mod.rs` (15 new), and `crates/commands/tests/package_completeness.rs`
  (the `.vsd` import case, the committed fixture plus every corpus `.vsd` the
  alpha imports).
- **ADR 0073** records both rules and amends ADR 0018 with a pointer;
  `docs/sources.md` row 27 and the local `reference/SOURCES.md` section P8-20
  record the sources. [MS-VSDX] says nothing about the windows part: 2.3.1 (Part
  Enumeration) does not list it and states all other parts are unused and must

  the Microsoft Learn schema rows of `docs/vsdx-inventory.md`. The background

### Open issues

- **Model: a `Background` flag on `Page`** would make the mark fully lossless
  (an unreferenced mark lives in `Preserved`, a referenced page's mark is
  writer-owned) and would let the renderer honour it: our renderer still
  composites a `BackPage` reference even when the target is unmarked, the
  discrepancy with Visio the task Facts record. Belongs with the renderer's
  mark handling, not this task.
- **Duplicate or unparsable page `ID`s**: the writer marks the first element
  with the referenced `ID` (the page the reader resolves to), but the reader's
  id list in `read_pages` compacts unparsable ids and can resolve a `BackPage`
  to a different list position. Pre-existing; flagged here for the next reader
  task.
- The ignored wide-corpus sweep (`crates/vsdx/tests/wide_corpus.rs`, the
  `roundtrip` column) may record differences for files whose `BackPage` names
  an unmarked page (the writer marks it) or which lack the windows part (the
  writer adds it). A re-run by the next researcher would quantify it.

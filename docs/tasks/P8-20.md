## Facts (master, 2026-10-25)

Observed behaviour of Visio (AGENTS.md section 4); the repo records
the facts only:

- A `.vsdx` package does not open without a windows part. The
  smallest accepted form is three entries, all required together:
  1. a part `/visio/windows.xml` whose root is `<Windows/>` in the
     namespace `http://schemas.microsoft.com/office/visio/2012/main`
     (an empty element is enough; no `Window` child is needed);
  2. a relationship from the document part to it, type
     `http://schemas.microsoft.com/visio/2010/relationships/windows`;
  3. an `Override` for `/visio/windows.xml` with content type
     `application/vnd.ms-visio.windows+xml`.

  Style sheets, document properties, a theme and masters are not
  needed for the file to open. None of the eleven
  `corpus/fixtures/render-*.vsdx` files has the windows part, and our
  writer has no notion of it, so a document Larrygram creates from
  nothing, or an imported `.vsd` saved as `.vsdx` (P8-09), most likely
  does not open either.
- A page referenced through another page's `BackPage` is drawn behind
  it only when it is marked `Background="1"`. In
  `render-background-pages.vsdx` page 1 is referenced but not marked,
  so it is an ordinary page and nothing is composited, while our
  renderer composites it.

## Goal

1. **The writer emits the windows part when the package has none**:
   the part, the relationship and the content-type override above,
   with the next free relationship id. A package that already has a
   windows part keeps it byte for byte. Check [MS-VSDX] for what it
   says about the windows part and cite it in the ADR amendment.
2. **Background pages are consistent on write**: decide, against
   [MS-VSDX], what the writer does when a page is referenced as a
   `BackPage` but not marked `Background` (mark it, or warn and leave
   it). Write the decision into the ADR amendment.
3. **The fixtures**: the builders produce the windows part, and
   `render-background-pages` marks its background page the way Visio
   does. Regenerate the fixtures, their fuzz-seed copies and the
   goldens that change; look at every changed PNG and name it in the
   Result. `ATTRIBUTION.md` and `corpus/PROVENANCE.md` rows stay as
   they are unless a file is added or renamed.
4. **A structural test** (`crates/vsdx/tests/package_completeness.rs`): every
   package our writer produces in the test suite (a new document, an
   edited corpus file, an imported `.vsd` saved as `.vsdx`, every
   fixture) has the three entries above, and every page referenced as
   a `BackPage` is a background page.
5. **ADR**: amend the Phase 2 writer ADR (or write a new one) with
   the windows-part rule and the background-page rule, citing
   [MS-VSDX] where it states them and observed behaviour (AGENTS.md
   section 4) for the rest.

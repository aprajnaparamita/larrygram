## Why

The user's manual pass of the `.dmg` built at `514e45b` (2026-10-31),
in Panel Classic. P7-19 reported whole-tile drag and search as done,
yet the user saw neither in the app. Find out why the tests passed,

## Goal

1. **Shapes window, whole tile:** the user's first pass ran a stale
   build; the second pass (2026-10-31, at `514e45b`) shows the whole
   tile working. Keep it working: one real-input test per layout if
   none exists, then move on.
2. **Search for Shapes** filters the tiles as the user types, in both
   layouts; an empty result says so.
3. **Menu hints** (the tooltips of menu items) appear next to the item
   under the pointer, not at the far left of the window.
4. **Shape Data pane** with nothing selected: it lists "Name Page-1"
   twice and shows dashes under Size & Position. Show the page's data
   once, and hide or label the Size & Position rows when there is no
   shape.
5. **"Selected 0 shapes"** appears both in the title strip and in the
   status bar; keep it in the status bar only.
6. **Switch layouts from Panel Classic:** View offers Panel Modern and
   Panel Classic as radio items (`view.ui_layout.*`), and Panel Modern
   offers the same switch (View tab or File > Options). Check both
   directions.
7. **Settings:** the Options window is reachable from Tools > Options
   in Panel Classic (`tools.options.preferences` links to it), from
   File > Options in Panel Modern, and from Cmd+, and Larrygram >
   Settings… in the macOS app menu. The window offers the layout
   choice. If a native app-menu item needs `unsafe` beyond ADR 0074's
   exception, ship Cmd+, and list the menu item under Open issues.

## Result

Done. All seven items are fixed or (where they already worked at
`514e45b`) pinned with real-input tests, each in **both** curated
layouts (Panel Classic and Panel Modern), driven through the full
`Shell` with `egui_kittest` (pointer events, typed text, key chords;
never a direct widget call). The tests are
`crates/ui/tests/phase7/manual.rs`.

1. **Whole tile** — already worked at `514e45b` (the user's first
   pass ran a stale build). Kept working: `a_tile_drag_from_the_
   picture_and_from_the_label_each_drop_a_master` drags one master by
   its preview and one by its label in each layout and checks the
   dropped pin.
2. **Search** — already worked at `514e45b`. `typed_search_filters_
   the_tiles_and_an_empty_result_says_so` types into the search box
   (a `TextInput` node) in each layout: the tiles filter as the text
   lands and "No shapes match the search." shows for a miss.
3. **Menu hints** — `panel_classic/menu.rs` showed the hint with
   `on_hover_text`, which egui anchors at `BOTTOM_START` of the row:
   below the row's left edge, the window's far left for the left-hand
   menus. Now `on_hover_text_at_pointer` (next to the item under the
   pointer). A real-input hover test checks the hint's rect is within
   24 pt of the pointer for a Panel Classic menu-bar row and for a
   context-menu row in both layouts (the shell's right-click router
   draws the context menus through these rows in every layout).
4. **Shape Data / Size & Position** — with nothing selected the Size
   & Position pane listed the page's Width/Height as "—" and repeated
   the "Name Page-1" row that Shape Data already showed. Now the
   page's data shows once (Shape Data) and the Size & Position pane
   hides its rows behind a "No shape selected." label
   (`size_position_entries` returns no rows without an anchor shape).
5. **"Selected 0 shapes" twice** — the title strip repeated the last
   command message beside the status bar. `Shell::title_status`
   returns only the half-typed shortcut chords (P4-14's feature); the
   message shows in the status bar only. Tested with the `Ctrl+A`
   chord (`edit.select_all`) in both layouts.
6. **Layout switch** — Panel Classic's View menu gains "Panel Modern"
   and "Panel Classic" as radio rows over `view.ui_layout.*`
   (`kind: check`, mutually exclusive through a shell-side
   `CheckedState`; the gutter draws a radio dot for these rows).
   Panel Modern switches back through File > Options. The test walks
   Classic -> Modern -> Classic through real clicks.
7. **Settings** — `tools.options.preferences` was a stub row (the
   Tools > Options click did nothing); it now returns the same
   `UiRequest::ShowOptions` as `app.office.center.options`. The
   Options window opens from Tools > Options (menu click), from File
   > Options (Panel Modern), and from Cmd+, (a new `Ctrl+,` binding
   in the shortcut table; `Ctrl` covers Cmd on macOS). The test also
   pins the window's layout choice. The native "Larrygram >
   Settings…" app-menu item needs `unsafe` beyond ADR 0074's
   exception and is listed under Open issues.

**Why P7-19's tests passed (items 1 and 2).** The user's first pass
ran a stale build, made before P7-19's changes landed: the code in
the tree was correct (P7-19's tests drive the real shell), but the
`.dmg` predates it, which is also why the second pass at `514e45b`
shows the whole tile working. For the search, P7-19's test
(`the_header_row_collapses_and_the_search_filters`) additionally
called `shapes_window_mut().set_search(...)` directly instead of
typing into the search box — the direct-call gap the master notes
name — so it could not have caught an input-path breakage even in a
current build. The new tests type real text through the harness.

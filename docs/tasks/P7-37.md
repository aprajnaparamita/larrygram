## Why

From the master's review of P7-29 (2026-11-02):

- While the user types in a new text box made with the Text tool, the
  text controls stay disabled. The box is not a shape until it
  commits, so Bold, the font and the alignments can't be used
  mid-typing. P7-29's goal named this case ("while its text is being
  edited").
- P7-29 added 84 near-identical `Allow` entries (21 commands × 4
  contexts) to `crosscheck.rs`.

## Goal

1. **A new text box can be formatted while it is typed.** With the
   Text tool, click or drag on empty page and type. The text controls
   are enabled, and choosing Bold, a font size or an alignment applies
   it to the box's text (cells and picture) while it is typed.

   **Approach (master's decision, 2026-11-03): create the shape when
   the box opens, inside an undo group** (ADR 0040, amendment
   2026-11-03).
   1. Add the undo group to `UndoStack`: `begin_group`, `end_group`,
      `cancel_group`, as the amendment says, with unit tests (empty
      group, cancel restores the document and its unsaved-changes
      state, undo ends an open group, no nesting).
   2. When the Text tool opens a new box, the shell opens a group and
      dispatches `insert.drawing.text_box` with `allow_empty: true`.
      The shape now exists and is selected, and the editor switches to
      editing it, the P7-29 path for an existing shape. From then on
      `editing_text`, `can_format_text` and the format commands work
      unchanged; do not special-case a pending box in `format.rs`.
   3. On commit with text, the shell writes the text the usual way,
      then calls `end_group`: one undo step, labelled as the insert.
   4. On commit with no text, by any path, the shell calls
      `cancel_group`: no shape, no undo entry, the document unchanged
      and not marked as changed.
   5. Every way the editor can end closes the group: commit, Escape,
      the P7-25 click elsewhere, a command bar or menu click, a layout
      switch, closing the document. List them in the Result with the
      test that covers each.

   `insert.drawing.text_box` without `allow_empty` behaves exactly as
   today (an empty text is no shape), so programmatic callers don't
   change. P7-25's commit-before-click rule still holds.
2. **One allowlist rule.** Replace P7-29's 84 `Allow` entries with
   one rule that covers the 21 text commands in those four contexts,
   with the same reason text. The check keeps catching anything else.

### Item 1: a new text box can be formatted while it is typed

The master's approach (create the shape when the box opens, inside an
undo group) is implemented end to end.

- **Undo groups** (`crates/commands/src/undo.rs`, ADR 0040 amendment
  2026-11-03): `UndoStack::begin_group(label, unsaved)` collects every
  push into one pending step (groups do not nest; a second begin is an
  error), `end_group()` pushes them as one `CompositeEdit` under the
  label (an empty group pushes nothing), `cancel_group(ctx)` reverts
  them in reverse with the recording gate closed and returns the
  unsaved-changes state the group saw at begin, and `undo`/`redo` end
  an open group first. `clear` drops a group with everything else. The
  `AppCtx` wrappers (`app.rs`) take the stack out and put it back by
  `SessionId` (the `with_undo` borrow split) and restore
  `DocumentSession::dirty` on cancel. Unit tests: empty group, folded
  step (reverse undo, forward redo), cancel restores the document and
  answers the unsaved state, undo/redo end the group, no nesting,
  clear drops the group, the wrappers fold and cancel and name their
  session.
- **`insert.drawing.text_box` takes `allow_empty`**
  (`crates/commands/src/builtins/insert.rs`): with the flag an empty
  text still opens the box (shape + one undo step, no text); without
  it an empty `text` is no shape and no undo entry.
- **The shell opens the box as a shape** (`crates/ui/src/shell.rs`,
  `text_edit.rs`): consuming the tool's `PendingBox` now runs
  `insert.drawing.text_box` with `allow_empty: true` inside a fresh
  group and opens the editor on the shape (`TextEditor::begin_box`:
  `shape` for `editing_text`, `can_format_text` and the format
  commands, `pending` bounds for the box-filling field and the P7-26
  click backstop). Commit writes the text the usual way
  (`edit.select` + `shape.set.text`) and calls `end_group`: one undo
  step labelled "Insert Text Box". Commit with no text calls
  `cancel_group`: no shape, no undo entry, the document unchanged and
  not marked as changed. `format.rs` is untouched; the old
  pending-insert path (`text_insert_intents`) is gone.

**Every way the editor can end closes the group** (item 5), each with
its test:

| Ending | Test |
|---|---|
| commit with text (the write, then `end_group`) | `a_new_text_box_commits_as_one_undo_step` and `a_new_text_box_can_be_formatted_while_it_is_typed` (both layouts) |
| commit with no text (`cancel_group`) | `a_new_box_committed_empty_leaves_no_shape_and_no_undo_entry` (both layouts) |
| Escape (commits per ADR 0044) | `a_new_text_box_commits_as_one_undo_step` (Escape is its commit) |
| the P7-25 click elsewhere | `a_click_elsewhere_commits_the_box_and_the_next_click_opens_another` (both layouts) |
| a command bar or menu click (the outside press commits) | `a_new_text_box_can_be_formatted_while_it_is_typed` (Bold, size, alignment) and `the_undo_button_removes_the_whole_new_box` (both layouts) |
| a layout switch | `a_layout_switch_commits_the_new_text_box` (Panel Classic's View menu row by real input; the dispatch path in both layouts) |

Beyond the list: `text.cancel` cancels the group
(`Shell::dispatch_intent`), undo/redo end the group first

### Deviations and notes

- **Empty text without `allow_empty`.** The task records today's
  behaviour as "an empty text is no shape"; a probe showed the command
  actually created a shape for an explicit empty `text` (the shell was
  what skipped the insert). The task's rule is implemented: an empty
  `text` is no shape and no undo entry. An **absent** `text` still
  inserts a shape (unchanged; programmatic callers such as the
  Shapes-window drop never pass `text`). No caller passed an empty
  `text`, so nothing observable changes.
- **The rule covers 17 commands, not 21** — the P7-29 block held 17
  text commands x 4 contexts = 68 entries (not 84); the rule covers
  exactly those pairs.
- **What folds into the commit step.** The text write dispatches in
  the frame's commit, before the commands of the click that ended the
  edit, so the group is exactly "the insert, the format commands and
  the final text write" for the formats applied while the group is
  open (the keyboard shortcuts). A format **click** ends the edit
  first (the P7-29 rule: "the click commits the typed text and records
  the format on it") and its own edit is the next undo step, as in the
  P7-29 behaviour the task keeps unchanged.
- The Undo button draws disabled ("Can't Undo") while the group is
  open — its steps are not on the stack yet; the click still commits
  (the outside-press rule) and the next undo removes the whole box.
  Cmd+Z while a text edit has focus defers to egui's buffer undo (the
  shortcut table's `defers_to_egui` rule, unchanged).
- `DocumentSession.dirty` is never set by production code today
  (nothing marks a document changed on an edit). `cancel_group`
  restores it as the ADR says and the empty-commit test asserts it
  stays false; a future marker of `dirty` gets the restore for free.
  Open issue for the master.
- One contract test moved with the behaviour: the P7-26 case
  `a_click_inside_the_new_text_box_keeps_editing_it`
  (`crates/ui/tests/phase7/text_fixes.rs`) now asserts the box is a
  shape from the click (its rule — the click inside keeps editing and
  opens no second box — is unchanged).
- New dependencies: none.

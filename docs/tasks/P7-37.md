## Why

From the master's review of P7-29 (2026-11-02):

- While the user types in a new text box made with the Text tool, the
  text controls stay disabled. The box is not a shape until it
  commits, so Bold, the font and the alignments can't be used
  mid-typing. P7-29's goal named this case ("while its text is being
  edited").
- P7-29 added 84 near-identical `Allow` entries (21 commands × 4
  contexts) to `crosscheck.rs`.

## Goal

1. **A new text box can be formatted while it is typed.** With the
   Text tool, click or drag on empty page and type. The text controls
   are enabled, and choosing Bold, a font size or an alignment applies
   it to the box's text (cells and picture) while it is typed.

   **Approach (master's decision, 2026-11-03): create the shape when
   the box opens, inside an undo group** (ADR 0040, amendment
   2026-11-03).
   1. Add the undo group to `UndoStack`: `begin_group`, `end_group`,
      `cancel_group`, as the amendment says, with unit tests (empty
      group, cancel restores the document and its unsaved-changes
      state, undo ends an open group, no nesting).
   2. When the Text tool opens a new box, the shell opens a group and
      dispatches `insert.drawing.text_box` with `allow_empty: true`.
      The shape now exists and is selected, and the editor switches to
      editing it, the P7-29 path for an existing shape. From then on
      `editing_text`, `can_format_text` and the format commands work
      unchanged; do not special-case a pending box in `format.rs`.
   3. On commit with text, the shell writes the text the usual way,
      then calls `end_group`: one undo step, labelled as the insert.
   4. On commit with no text, by any path, the shell calls
      `cancel_group`: no shape, no undo entry, the document unchanged
      and not marked as changed.
   5. Every way the editor can end closes the group: commit, Escape,
      the P7-25 click elsewhere, a command bar or menu click, a layout
      switch, closing the document. List them in the Result with the
      test that covers each.

   `insert.drawing.text_box` without `allow_empty` behaves exactly as
   today (an empty text is no shape), so programmatic callers don't
   change. P7-25's commit-before-click rule still holds.
2. **One allowlist rule.** Replace P7-29's 84 `Allow` entries with
   one rule that covers the 21 text commands in those four contexts,
   with the same reason text. The check keeps catching anything else.

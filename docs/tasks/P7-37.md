## Why

From the master's review of P7-29 (2026-11-02):

- While the user types in a new text box made with the Text tool, the
  text controls stay disabled. The box is not a shape until it
  commits, so Bold, the font and the alignments can't be used
  mid-typing. P7-29's goal named this case ("while its text is being
  edited").
- `shape_has_text` reads only the shape's own text. An instance whose
  text comes from its master counts as having none, so its text
  controls are wrongly disabled.
- P7-29 added 84 near-identical `Allow` entries (21 commands × 4
  contexts) to `crosscheck.rs`.

## Goal

1. **A new text box can be formatted while it is typed.** With the
   Text tool, click or drag on empty page and type. The text controls
   are enabled, and choosing Bold, a font size or an alignment applies
   it to the box's text (cells and picture). Do one of two things:
   - create the text shape when the box opens, and remove it on commit
     if it is still empty;
   - or create it at the first format command.

   Either way:
   - a box committed empty leaves no shape and no undo entry;
   - one undo after a commit removes the whole new box (shape, text
     and format);
   - P7-25's commit-before-click rule still holds.

   Say in the Result which approach you took and why.
2. **Inherited text counts.** `shape_has_text` is true when the
   shape's text comes from its master. Use the model's existing
   inherited-text lookup; if there is none, say so and read the
   master's text the way the renderer does.
3. **One allowlist rule.** Replace P7-29's 84 `Allow` entries with
   one rule that covers the 21 text commands in those four contexts,
   with the same reason text. The check keeps catching anything else.

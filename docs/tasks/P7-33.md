## Goal

A user can see and edit connection points the way the spec describes:

- **See**: points render as small markers on the shape when the
  View > Visual Aids > Connection Points toggle is on (the pinned
  Phase 7 id `tools.connection.points`), and also while a connector
  drag or end drag is near the shape (the connector tool's hover
  state). A point being deleted shows in the delete colour (magenta
  in Visio; our theme's equivalent) before the delete.
- **Add**: the Connection Point tool (`tools.connection.point`, Home >
  Tools) active, Ctrl+click on the shape adds a point at that local
  position and selects it.
- **Move**: tool active, Ctrl+drag moves the selected point.
- **Delete**: tool active, click a point to select it, Delete key
  removes it.
- Every change edits the shape's `Connection` section rows through the
  model mutation API and is one undoable command. Points inherited
  from a master materialise into the instance's own `Connection`
  section on the first edit (the instance's rows win, ADR 0013).
- Point types (`Type`, `DirX`, `DirY`) are preserved untouched on
  move; add writes an inward, directionless point (the documented
  default).

## Interfaces

```rust
// crates/model/src/connection.rs (write API, ADR 0039 style)

impl Document {
    /// Adds a connection point to `shape` at the local point and
    /// returns the new row's `IX`. Materialises inherited rows into
    /// the shape's own section first (so the row indexes are the
    /// shape's own). Never panics; a stale shape id is an error.
    pub fn add_connection_point(&mut self, shape: ShapeId, point: Point) -> Result<i32, Error>;

    /// Moves the row `ix` to the local point, keeping `Type`,
    /// `DirX`/`DirY` and the row name. Unknown `ix` is an error.
    pub fn move_connection_point(&mut self, shape: ShapeId, ix: i32, point: Point) -> Result<(), Error>;

    /// Deletes the row `ix`. Deleting the last row keeps the empty
    /// section. Unknown `ix` is an error.
    pub fn delete_connection_point(&mut self, shape: ShapeId, ix: i32) -> Result<(), Error>;
}
```

```rust
// crates/commands/src/builtins/connection_points.rs
// Ids follow ADR 0006 (`connector.point_*`); the tool itself and the
// visibility check are the pinned Phase 7 ids `tools.connection.point`
// and `tools.connection.points`, which this task implements.

/// `connector.point_add`: args `shape` (Visio id), `x`, `y` (local
/// inches); one undoable edit; returns the new `IX` in the outcome.
pub(crate) fn run_add(ctx: &mut AppCtx, inv: &Invocation) -> Result<Outcome, CommandError>;
/// `connector.point_move`: args `shape`, `point` (row `IX`), `x`, `y`.
pub(crate) fn run_move(ctx: &mut AppCtx, inv: &Invocation) -> Result<Outcome, CommandError>;
/// `connector.point_delete`: args `shape`, `point`.
pub(crate) fn run_delete(ctx: &mut AppCtx, inv: &Invocation) -> Result<Outcome, CommandError>;
```

The tool state machine gains a `ConnectionPoint` tool with the three
gestures; Esc returns to the Pointer Tool (the existing tool-switch
rules).

      exact rows.

      arguments.
- [ ] Visibility tests: the toggle shows/hides the markers; hover

      the Connection Point tool, add a point to a shape, glue a
      connector end to it, move the point (connector end follows on
      re-route), delete the point (connector end falls back per
      ADR 0084 rule 2), undo each step.

## Goal

1. **1-D selection.** A selected connector (`is_connector`) shows a
   begin handle and an end handle only: no resize box, no rotation
   handle. A glued end's handle and a free end's handle look
   different. Use our theme colours, for example a filled accent for
   glued and a hollow one for free. A selected ordinary shape is
   unchanged.
2. **End drags.** Pressing an end handle and dragging moves that end.
   On release:
   - over a connection point (snap distance): point glue;
   - over a non-connector shape: dynamic glue;
   - over empty page: free at the release point.

   Alt suppresses glue. The other end stays as it was. One
   `connector.move_end` per drag, one undo step.
3. **Hover feedback.** During an end drag, and while drawing with the
   Connector tool, the target highlights: the shape's outline for
   dynamic glue, the single point for point glue, nothing when the
   end would be free. The connection points of the shape under the
   pointer show as markers whether or not the view check is on.
4. **Programmatic contract.** `connector.move_end` with all arguments
   applies directly. Without them it fails with a clear error and
   opens no dialog (AGENTS.md section 6).
5. **Arrow keys unglue.** With one or more connectors selected, an
   arrow key unglues both ends of each (formulas and records, as
   P7-31 stores them) and nudges them, in one undo step. Shift+arrow
   nudges by one pixel. Ordinary shapes nudge as today.

## Interfaces

```rust
// crates/commands/src/builtins/connector_ends.rs

/// `connector.move_end`: one undoable move of one connector end.
///
/// Arguments: `connector` (Visio id), `end` ("begin" | "end"), `x`,
/// `y` (page inches), optional `target` (Visio id) and optional
/// `point` (connection row ix). `target` with `point` is point glue,
/// `target` alone dynamic glue, neither a free end at `x`,`y`.
/// Resolves with `larrygram_geom::glue`, writes the end (P7-31's
/// `write_connector_end` and the record) and re-routes that connector,
/// all in one edit.
pub(crate) fn run_move_end(ctx: &mut AppCtx, inv: &Invocation) -> Result<Outcome, CommandError>;
```

```rust
// crates/render/src/overlay.rs (extended)

/// What a dragged connector end will glue to, and the points to show.
pub struct GlueFeedback {
    /// The target's outline (page space) for dynamic glue.
    pub outline: Option<Vec<Point>>,
    /// The single highlighted point for point glue.
    pub point: Option<Point>,
    /// Connection points to show as markers (page space).
    pub markers: Vec<Point>,
}
```

Fit `GlueFeedback` into the overlay's existing mark types; do not add
a second overlay path in `canvas.rs`.

## Tests

- **Commands**: `connector.move_end` for point glue, dynamic glue and
  a free end; one undo restores the cells, formulas and records; a
  missing argument is an error with no dialog request.
- **Real input** (egui_kittest, full shell, Panel Modern and Panel
  Classic). Draw a connector between A and B with the Connector tool,
  then select it by clicking on its line. Then:
  - check, through the rendered picture and the handle code, that it
    shows two end handles and no resize box, and that the glued-end
    marker differs from a free end's;
  - drag its end handle from B onto C's connection point. During the
    drag, the picture shows C's points and the highlighted point.
    After release, check the cells, formula and record name C;
  - drag the same end to empty page and check the end is free (no
    record, literal cells) where it was released;
  - press an arrow key with the connector selected, and check both
    ends are free and moved by one nudge;
  - undo each step.

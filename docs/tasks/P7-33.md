## Goal

1. **1-D selection.** A selected connector (`is_connector`) shows a
   begin handle and an end handle only: no resize box, no rotation
   handle. A glued end's handle and a free end's handle look
   different. Use our theme colours, for example a filled accent for
   glued and a hollow one for free. A selected ordinary shape is
   unchanged.
2. **End drags.** Pressing an end handle and dragging moves that end.
   On release:
   - over a connection point (snap distance): point glue;
   - over a non-connector shape: dynamic glue;
   - over empty page: free at the release point.

   Alt suppresses glue. The other end stays as it was. One
   `connector.move_end` per drag, one undo step.
3. **Hover feedback.** During an end drag, and while drawing with the
   Connector tool, the target highlights: the shape's outline for
   dynamic glue, the single point for point glue, nothing when the
   end would be free. The connection points of the shape under the
   pointer show as markers whether or not the view check is on.
4. **Programmatic contract.** `connector.move_end` with all arguments
   applies directly. Without them it fails with a clear error and
   opens no dialog (AGENTS.md section 6).
5. **Arrow keys unglue.** With one or more connectors selected, an
   arrow key unglues both ends of each (formulas and records, as
   P7-31 stores them) and nudges them, in one undo step. Shift+arrow
   nudges by one pixel. Ordinary shapes nudge as today.

## Interfaces

```rust
// crates/commands/src/builtins/connector_ends.rs

/// `connector.move_end`: one undoable move of one connector end.
///
/// Arguments: `connector` (Visio id), `end` ("begin" | "end"), `x`,
/// `y` (page inches), optional `target` (Visio id) and optional
/// `point` (connection row ix). `target` with `point` is point glue,
/// `target` alone dynamic glue, neither a free end at `x`,`y`.
/// Resolves with `larrygram_geom::glue`, writes the end (P7-31's
/// `write_connector_end` and the record) and re-routes that connector,
/// all in one edit.
pub(crate) fn run_move_end(ctx: &mut AppCtx, inv: &Invocation) -> Result<Outcome, CommandError>;
```

```rust
// crates/render/src/overlay.rs (extended)

/// What a dragged connector end will glue to, and the points to show.
pub struct GlueFeedback {
    /// The target's outline (page space) for dynamic glue.
    pub outline: Option<Vec<Point>>,
    /// The single highlighted point for point glue.
    pub point: Option<Point>,
    /// Connection points to show as markers (page space).
    pub markers: Vec<Point>,
}
```

Fit `GlueFeedback` into the overlay's existing mark types; do not add
a second overlay path in `canvas.rs`.

### What landed

1. **1-D selection.** A selected connector (`is_connector`) shows a
   begin handle and an end handle only: no resize box, no rotation
   handle and no outline. The anchors are the drawn route's end
   points; a glued end draws a filled accent marker, a free end a
   hollow one (`handles::end_handles`, `handles::end_handle_at`, the
   `OverlayMark::Handles` mark's new `ends` field, the one
   `draw_overlay` path in `canvas.rs`). A selected ordinary shape is
   unchanged.
2. **End drags.** A press on an end handle starts the drag
   (`HandleKind::ConnectorEnd`, wired in `tools/pointer.rs`); the
   release dispatches exactly one `connector.move_end` per drag, one
   undo step: point glue over a connection point (snap distance),
   dynamic glue over a non-connector shape, a free end at the release
   point. Alt suppresses glue; the other end keeps its own glue.
3. **Hover feedback.** While drawing with the Connector tool and while
   dragging an end, the hovered target highlights:
   `render::GlueFeedback` (the target's outline for dynamic glue, the
   single highlighted point for point glue) and the hovered shape's
   connection points as markers, drawn through the overlay's one draw
   path (P7-34 reuses `GlueFeedback`). The markers show whether or
   not the view check is on, and while Alt suppresses glue.
4. **`connector.move_end`** (`crates/commands/src/builtins/connector_ends.rs`):
   strict arguments (`connector`, `end`, `x`, `y` required; `target`
   and `point` optional) — a missing or bad argument is a clear
   `InvalidArgs` error with no dialog request. The run resolves both
   ends with `larrygram_geom::glue`, writes the end and its record
   (P7-31) and re-routes the connector (`Scope::Forced`) folded into
   one edit. The endpoint cells are written in the parent's
   coordinates (`x`,`y` arrive in page inches); the group test pins
   that mapping.
5. **Arrow keys.** With connectors selected an arrow key unglues both
   ends of each and nudges them in one `shape.move` edit (ADR 0084
   rule 1's move rule: the path translates, each end whose target
   does not move comes loose, formulas and records together). One
   undo step restores the glue and the points.
   Shift+arrow nudges one screen pixel at the current zoom; the plain
   step is `NUDGE_IN` (1/8 in, ours: the allowed sources do not
   document Visio's). Ordinary shapes keep today's arrow behaviour
   (see the deviations).

### Deviations

- **Where the arrow keys dispatch.** `arrange.nudge` is a stub today
  (the parity matrix says "stub"; verified empirically: arrow keys
  move nothing). "Ordinary shapes nudge as today" is therefore read
  literally: the step fires only when the selection contains a
  connector, moves the selected connectors only (a mixed selection's
  ordinary shapes keep today's behaviour), and the pressed arrows are
  consumed so the `arrange.nudge` stub does not fire beside it and
  note an error. The step runs at the shell's shortcut seam
  (`Shell::arrow_nudge_delta` / `nudge_connectors`, beside the
  Shapes-window arrow handling); nothing else there changed. If the
  master wants the ordinary nudge implemented too, that is a separate
  task over `arrange.nudge`.
- **The plain nudge step is ours.** Only Shift+arrow (one pixel) is
  documented; `NUDGE_IN` = 1/8 in is our choice, documented in
  `shell.rs` and tested.
- **`HandleKind` lost its `Hash` derive** (it carries
  `larrygram_model::ConnectorEnd` now, which is not `Hash`); nothing
  hashed it.
- **Wiring outside the owns list** (each a few lines, none a second
  overlay path): `tools/pointer.rs` (the end-handle press, the two
  drag arms, `overlay_for_shapes` delegating to
  `handles::selection_overlay`), `tools/text_block.rs` (three no-op

  the `GlueFeedback` and end-handle drawing in `draw_overlay`, the

  `GlueFeedback` re-export).
- **Data plumbing for the new command id**: `xtask/src/extract/commands.rs`

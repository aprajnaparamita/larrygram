## Goal

The R9 review's items, by number:

1. **The target dir (blocker).** `Layout::real()` reads
   `target_directory` from `cargo metadata --no-deps --format-version 1`
   (xtask already runs `cargo metadata` in `util.rs`; reuse it), so
   `CARGO_TARGET_DIR`, `CARGO_BUILD_TARGET_DIR` and `build.target-dir`
   are all honoured. The test checks that the dist dir is
   `<that dir>/dist`. Run the xtask tests once with
   `CARGO_TARGET_DIR=/Volumes/Dara/larrygram/target/xcheck` set (a
   per-crate `cargo test -p xtask`) to show they pass under it, and say
   so in the Result.
2. **macOS tester steps.** Lead with: open the app once, then System
   Settings > Privacy & Security > Open Anyway. Right-click > Open only
   as the note for macOS 14 and earlier. The
   `xattr -dr com.apple.quarantine /Applications/Larrygram.app`
   fallback last, with one line on what it does.
3. **Naming the build.** Testers report the release tag, not just the
   About version. The release notes template prints the tag and the
   full commit SHA (`GITHUB_SHA`). testers.md says to copy the tag from
   the release page. Embedding the SHA in About is R11.
4. **Tag and version agree.** A first step in `release.yml` fails, with
   a clear message, when the tag is not `v` plus the workspace version.
   Read the version through `cargo metadata`, not by parsing
   `Cargo.toml` text. A `workflow_dispatch` run without a tag skips the
   check and makes no release.
5. **Linux install steps** (INSTALL.txt and testers.md): `mkdir -p`
   for each target directory; `update-desktop-database` after copying
   the desktop file (skip quietly if the tool is missing); the two
   `xdg-mime default` lines, as an optional step "to make Larrygram
   the default for .vsdx and .vsd"; and a note that `~/.local/bin`
   must be on `PATH` for the desktop entry to start it.
6. **Tar headers.** Entry mtimes come from `SOURCE_DATE_EPOCH` when it
   is set (the workflow sets it from the commit time), otherwise the
   current time. Add directory entries. The read-back test checks
   both.
9. **No build cache for releases** (master's decision). `release.yml`
   drops `Swatinem/rust-cache`: shipped builds start clean. `ci.yml`
   keeps its cache.

Also run `actionlint .github/workflows/*.yml` (installed) after the
workflow edits and put the output in the Result.

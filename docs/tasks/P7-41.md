## Why

The P7-37 review (2026-11-03) found that formatting by mouse ends the
typing. A click on Bold, a size or an alignment counts as a press
outside the editor (the P7-29 rule), so it commits:

- on an empty new box, Bold closes the editor, the group is cancelled
  and the box is gone; the next keystrokes go nowhere;
- after typing, Bold closes the editor and the stack reads
  `["Insert Text Box", "Bold"]`; every later format click adds a step.

Cmd+B works (the editor stays open, one step). The P7-37 test checked
only the first undo label, so it passed with four steps.

## Goal

1. **Format clicks don't commit** (review 1). A click on a control
   whose command is a text-format command (the `TEXT_CONTROLS` set the
   P7-37 allowlist rule names, or what `can_format_text` gates, one
   source of truth either way) does not end the edit, for a new box and
   for an existing shape's edit alike. The command applies to the
   shape being edited, the editor keeps keyboard focus and the caret,
   and for a new box the edit lands in the open group. Popups and
   dropdowns for those commands (the font size list, the colour
   picker) behave the same: choosing a value keeps editing.
2. **Tests that would have caught it** (review 2). In both layouts, by
   real input:
   - Text tool click, Bold before typing, type, Escape: the text is
     bold, the editor stayed open after Bold, and the stack is exactly
     `["Insert Text Box"]`;
   - type, Bold, type more, a font size from the list, Escape: still
     editing after each click, all text kept, one step;
   - the same on an existing shape's edit: one step per format click
     (as Visio), the editor still open;
   - Cmd+B while typing folds into the group (the path the review
     probed by hand).
   Assert the full undo label list and the editing state after every
   click.
3. **Save while typing** (review 5). Check whether Cmd+S, Save As,
   export and print dispatch while the editor has focus. Any `file.*`
   command commits the open box first, so a save never writes an
   empty box. Test it.
4. **No hand-kept trigger list** (review 6). Replace
   `TEXT_BOX_TRIGGERS` with a rule: every command commits the editor
   first except the text-format set of item 1 and the editor's own
   commands. A test pins that a new `file.*` or layout command
   commits.
5. **Undo while a box is open** (review 7). `can_undo` reports true
   while a non-empty group is open, and Undo commits the box and then
   undoes it whole.
6. **A failed cancel** (review 8). If a revert inside `cancel_group`
   fails, push the edits that were not reverted as one step labelled
   as the group, report the error, and leave the stack consistent.
   Unit test with a failing edit.
7. **The new shape's id** (review 9). `insert.drawing.text_box`
   returns the new shape's id in its outcome; `open_text_box` uses it
   instead of the selection anchor.
8. **ADR 0040** (review 10). The amendment shows the real
   signatures: `UndoStack::begin_group(label, unsaved)` and
   `AppCtx::begin_group(session, label)`.
9. **The editor sits on the text** (P7-38 review). In the website's
   text-editing shot, the in-place editor's overlay is smaller than the
   shape's drawn text and offset from it, so the text shows twice. Find
   out first whether it depends on the display scale: render the open
   editor at 1× and at 2× (the screenshot rig renders at 2×; the
   goldens never show an open editor). Then make the overlay's box,
   font size and first baseline match the drawn text at both scales,
   and add a golden of the open editor at each.

## Result

Done (2026-11-03, `agent/P7-41`). Items 1 to 9:

1. **Format clicks don't commit.** The commit-on-outside-press rule
   (`crates/ui/src/text_edit.rs`) now exempts a press on a text-format
   control (its recorded widget rect, `keep_editing_rect`, one call per
   control in `panel_classic/toolbar.rs` and `panel_modern/controls.rs`'s
   `put`) or in a popup, menu or palette layer (`layer_id_at` over
   `Order::Foreground`, the pattern `panel_modern/controls.rs` already
   used). The editor re-takes the keyboard with its caret untouched
   (`TextEditor::refocus`) after those presses and after every
   text-format command dispatch. The classic font and size boxes keep
   the keyboard for their own typing (they are text fields); the editor
   takes it back when the value applies.
2. **Tests that would have caught it** (`text_controls.rs`, both
   layouts, real input): Bold before typing (text bold, editor open,
   stack exactly `["Insert Text Box"]`); typing around Bold, a size
   from the list and an alignment click with the caret kept
   (`"abcdeXf"`); one step per format click on an existing shape's edit
   (`["Bold", "Set font size", "Write shape text"]`); Cmd+B folding
   into the group. The undo button test now pins item 5's one-click
   removal.
3. **Save while typing.** Cmd+S (`file.save`) and Cmd+P (`file.print`,
   a stub) are global bindings and dispatch while the editor holds the
   keyboard; Save As and export have no chord and dispatch from the
   File menu / File view, where the press rule ends the edit first.
   Tests assert the **saved .vsdx** (`larrygram_vsdx::read_document`):
   it carries the committed box and never an empty one.
4. **No hand-kept trigger list.** `TEXT_BOX_TRIGGERS` is gone;
   `builtins::ends_text_editing` is the rule (every command commits the
   open edit first except `format::TEXT_TABLE` — the same table the
   registry registers, so one source of truth — and the editor's own
   `text.*` commands). It covers `app.quit`, `file.exit` and the window
   close request (which is not a command; `show_in` commits before
   `begin_quit`, P7-42 review minor 6). The layout and `file.*` pin
   tests are `a_layout_switch_commits_the_new_text_box`,
   `closing_the_document_closes_the_new_box_first` and the item 3 tests.
5. **Undo while a box is open.** `can_undo` counts a non-empty open
   group; Undo commits the box and undoes the folded step whole (the
   unit test `can_undo_counts_a_non_empty_open_group` and the reworked
   undo-button test).
6. **A failed cancel.** `cancel_group` stops at the first failing
   `revert`, pushes the edits that were not reverted as one step
   labelled as the group (their undo finishes the rollback), returns
   the error, and never restores the saved state on that path (the
   restore-the-earlier-state logic stays). Unit tests:
   `a_failed_cancel_keeps_the_unreverted_edits_as_one_step`,
   `a_failed_cancel_at_the_first_revert_keeps_every_edit`.
7. **The new shape's id.** `Outcome::shape` carries it;
   `insert.drawing.text_box` (and the other creation commands) set it
   and `open_text_box` opens the editor on it instead of the selection
   anchor.
8. **ADR 0040.** The amendment shows the real signatures
   (`UndoStack::begin_group(label, unsaved)`,
   `AppCtx::begin_group(session, label)`) and the items 5 and 6 rules.
9. **The overlay sits on the text.** Investigated first: the mismatch
   is scale-independent (the field drew in the UI font over a box
   anchored at the block origin, while the drawn text is placed and
   sized by its own layout — smaller and offset at 1x and 2x alike).
   The overlay now follows the drawn glyphs: its box is the measured
   ink box of the glyph outlines (`text_ink`, the png backend's glyph
   chain, bounded at 512 glyphs), its font size is the first line's
   drawn size at the canvas zoom, its text sits on the drawn first
   baseline (the egui ascent is measured), its family is the drawn
   family when the theme registered it (Segoe UI text draws in the same
   Selawik face then), and the field's margin is zero. Goldens
   `text-editor-open-1x.png` / `text-editor-open-2x.png` (ATTRIBUTION
   rows added) show the match at both scales. Pending text boxes keep
   their plain box-filling field (no drawn text to match).

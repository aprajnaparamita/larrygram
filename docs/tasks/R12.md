## Why

The master's review of R11 (2026-11-03) found that
`larrygram_commands::build::build_id()` runs `git rev-parse --short
HEAD` **at runtime**, in the process's working directory, and that
`about::show` calls `version_line()` on every frame. So:

- while the About window is open, the UI thread starts a `git`
  process on every frame;
- an installed app started from inside another repository shows that
  repository's commit;
- on a Mac without the Command Line Tools, running `git` opens the
  system's "install developer tools" dialog when the user opens About.

The runtime `LARRYGRAM_BUILD_SHA` lookup has the same problem in a
smaller form: a stray variable in the user's environment changes the
id.

## Goal

1. **The id is a build-time constant.** `build_id()` returns
   `option_env!("LARRYGRAM_BUILD_SHA")`, shortened and checked as
   today, else `dev`. No process is started and no environment is read
   at runtime. Remove `git_short_sha`, `sha_from` and
   `runtime_build_sha`. Keep `resolve`/`shorten` (or their successor)
   unit-tested. The version line may be a `&'static str` or computed
   once; it is not recomputed per frame.
2. **Shipped builds set it.** `cargo xtask dist <mac|windows|linux>`
   sets `LARRYGRAM_BUILD_SHA` for its cargo build from
   `git rev-parse --short HEAD` in the workspace root, run once by
   xtask. If git is missing or fails, it builds without the variable
   (the id reads `dev`) and prints one line saying so. `release.yml`
   keeps setting it from `GITHUB_SHA`. Unit-test the xtask side with
   the existing fake `Sys`.
3. **Development builds read `dev`.** Plain `cargo build` and
   `cargo run` show `1.0.0-alpha.1 (dev)`. Say in `testers.md` that a
   tester's build always shows a commit id and that `dev` means a
   local build.
4. **The Windows build tools only on Windows.** Move `resvg` and
   `winresource` to `[target.'cfg(windows)'.build-dependencies]` (the
   cfg is the build host there), gate `mod icon` and its use in
   `build.rs` the same way, and print
   `cargo:rerun-if-changed=build.rs` on every host, so the script is
   not re-run on every file change. Check that `cargo build -p
   larrygram` on this Mac no longer compiles `winresource`
   (`cargo tree -e build -p larrygram`).

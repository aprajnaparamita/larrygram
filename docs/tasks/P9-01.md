## Background

- KICKOFF.md, "Phase 9: Agents": a JSON control channel and an MCP
  server that expose every registered command, document inspection and
  render-to-PNG, so an agent can drive the app and check its own work.
  Documented in `docs/agents.md` and `docs/control-protocol.md`.
  Tests: protocol tests and an end-to-end script that builds a
  flowchart over MCP and checks the result.
- AGENTS.md section 6: one command registry (`crates/commands`); menus,
  the command bar, shortcuts, the CLI, the JSON control channel and
  MCP all dispatch by command id through it; programmatic calls never
  open dialogs. Layering: `control` is L5 (ADR 0002), above `commands`
  (L4) and below `ui` (L6) and the apps (L7).
- What exists: the registry and its command ids, enabled predicates
  and undo (`crates/commands`); the CLI (`apps/larrygram-cli`:
  `inspect`, `render`, `export`); rendering to PNG and SVG
  (`crates/render`); the document model (`crates/model`); the Phase 5
  flowchart test (`apps/larrygram/tests/flowchart.rs`), which the
  end-to-end script mirrors over MCP.
- `crates/control` is an empty placeholder today.

## Goal

Plan Phase 9 so that as many workers as possible run at once on
disjoint files, the way P8-01 planned Phase 8.

1. **Plan (`docs/plans/phase-9.md`)**: scope, the deliverables above,
   what is out of scope for the alpha, the exit criteria, and the task
   split with crate ownership, dependencies and waves.
2. **ADRs for the decisions**, at least:
   - **Transport and framing** of the control channel: stdio,
     a local socket, or both; JSON-RPC 2.0 or a smaller framing;
     request ids, notifications, errors, versioning and capability
     negotiation.
   - **Session model**: a headless session (a document and the
     registry without a window, from the CLI) and attaching to the
     running desktop app; how the two share one implementation; one
     document or several; how the app's undo stack sees remote edits.
   - **The command surface**: listing commands with their ids, labels,
     argument schemas and enabled state; invoking one; what a command
     that would open a dialog does when called remotely (AGENTS.md:
     never opens one; it takes arguments or returns an error).
   - **Document inspection**: pages, shapes, cells, text, selection,
     as stable JSON; how large documents are paged or filtered.
   - **Render-to-PNG**: page, region, scale, returned as bytes or a
     file path; limits on size.
   - **MCP**: which MCP protocol version, which server crate (check its
     licence against `deny.toml` and its maintenance), and how MCP
     tools map onto the control channel (one implementation, two
     front ends); tool naming and schemas.
   - **Security**: local only by default, no network listener without
     an explicit opt-in, authentication for a socket, which commands
     are allowed remotely (file paths, overwrites), limits on request
     size and rate, and never-crash rules for hostile input.
3. **The stubs** in `crates/control`: the public types (requests,
   responses, errors, the session trait or struct, the MCP tool
   table) and function signatures, each a "not implemented" stub with
   a test of its contract, so the Phase 9 workers fill them in without
   changing signatures.
4. **Task files** `docs/tasks/P9-02.md` onwards, in the house format
   (see `docs/tasks/P8-02.md` and later): role, depends, parallel-safe,
   tier, Launch block, Owns, Inputs, Goal, Master notes, Acceptance
   criteria, Result. Include the test-engineer task (protocol tests,
   the fuzz target for request parsing, the end-to-end MCP flowchart),
   the three audits (review, coverage, clean room) and the fix and
   report task, numbered after the implementation tasks.
5. **The documentation outline** of `docs/agents.md` and
   `docs/control-protocol.md` (headings and what each section will
   hold); the implementation tasks fill them in.

## Master notes

- Phase 9 implementation starts after R7; this task only plans.
- No hosted services: everything runs on the user's machine.
- New dependencies: permissive licences only (`deny.toml`); prefer
  well-maintained crates; name each in the Result with its licence.
- The registry is the single source of truth for what a remote caller
  can do: no second list of commands.

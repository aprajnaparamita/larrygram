## Goal

1. **The header.** Keep `version` and add the magic check
   (`"Visio (TM) Drawing\r\n\0"` before the version byte); wrong magic
   is `Error::NotAVisioFile`.
2. **`read_chunks`.** Flatten the `VisioDocument` stream into `Chunk`
   values in stream order, nesting level preserved. Resolve pointer and
   list redirection to the offsets they name, each offset at most once
   (visited set), so pointer cycles terminate. Apply the per-version
   header rules (versions 6 and 11 differ) and the per-version payload
   framing. Compressed blocks go through
   `container::decompress` where the format marks them.
3. **The record ids.** The `Record` id table in this module, derived
   from the reference, with a comment naming the source (ADR 0069).
4. **Degrade, never crash.** A record cut short or nonsensical is
   skipped with a `crate::ImportWarning` and the walk continues at the
   next recoverable boundary (ADR 0071); `Limits::max_chunks` and
   `max_chunk_level` are enforced.
5. **Tests.** Hand-built streams for both versions: header parse,
   record walk, list redirection, pointer cycles, truncated records,
   lying lengths, level caps. A corpus smoke test: each of the five
   files yields a non-empty chunk list.

## Result

Filled in by the worker at hand-off (P8-03, branch `agent/P8-03`).

### What was built

`crates/vsd-binary/src/chunks.rs` (the `read_chunks` stub is gone; no
`Err(Error::NotImplemented)` remains in it). `version`, `FormatVersion`,
`Record` and `Chunk` are kept.

- **The header.** `version` now checks the Visio magic
  (`"Visio (TM) Drawing\r\n\0"` before the version byte): a wrong magic is
  `Error::NotAVisioFile`, a short stream is `Error::Invalid`, and the
  version byte goes through `FormatVersion::from_byte` (6 and 11 read,
  everything else `Error::UnsupportedVersion`).
- **`read_chunks`.** Flattens the `VisioDocument` stream into `Chunk`
  values in pointer order, nesting level preserved. It reads the trailer
  pointer at `0x24`, then follows each pointer list: the order array
  first, then the rest of the table. A pointer target is one region of
  the stream at an absolute offset; the high nibble of `Format` decides
  between a blob record (`0x0`, `0x4`, `0x5`: one `Chunk` whose kind, id
  and level come from the pointer; `0x5` also holds a nested pointer
  list, except a colour table) and a chunk-record stream (`0x8`, `0xc`,
  `0xd`). Each offset resolves at most once (visited set), so pointer
  cycles terminate. Compressed regions (`Format` bit 1) go through
  `container::decompress` (ADR 0068).
- **The per-version framing.** The 19-byte record header
  (`chunkType`, `id`, `list`, `dataLength` u32s, `level` u16,
  `unknown` u8) and the payload framing of the reference's two header
  readers (`VSD6Parser::getChunkHeader` for version 6,
  `VSDParser::getChunkHeader` for version 11) live in `trailer_len`.
  Padding between records is skipped as the reference skips it.
  `Chunk::data` is the declared payload plus the trailing region the
  framing rules add.
- **The record id table.** The full `VSDDocumentStructure.h` id table
  (86 record kinds) as `Record` constants with the reference note, and
  `Record::name` returning the format identifier (ADR 0069: ids and
  names derived from the reference, nothing else sees the raw ids).
- **Degrading, never crashing.** A record cut short or whose length runs
  past its region is skipped with a warning and the walk continues at
  the next recoverable boundary (the next pointer target). A record id
  wider than u16 is skipped with a warning and the walk continues at the
  next record. A pointer out of the stream, a truncated pointer list and
  an out-of-scope pointer format warn and skip. A repeated target offset
  warns `Dropped` and is walked once. When nothing at all can be read the
  result is `Error::Invalid`. `Limits::max_chunks` and
  `Limits::max_chunk_level` are hard caps (`Error::LimitExceeded`);
  pointer-list nesting is additionally bounded at 256 levels (AGENTS.md
  section 6), dropped with a warning.
- **List records (P8-04 open issue 1, master request).** A list record
  of the `0x64..=0x76` family keeps the end of its child-id list past
  the declared payload length, in the trailing region (every corpus
  file: a six-row geometry list has four ids in the payload and two in
  the trailer). `Chunk::data` spans that trailing region: the framing
  rules already cover it in every corpus record (checked over all 381
  list records of the five corpus files; the frame equals the child list
  plus its 4-byte separator), and `list_extent` now grows a record whose
  list header names more than the rules cover, so the whole child-id
  list is always inside `data`. Three tests pin the contract, including
  the exact corpus shape (4 ids in the payload, 2 in the trailer).

### Validation against the reference

The walk was compared record by record against an instrumented build of
the libvisio oracle (a private dev build with prints in
`getChunkHeader`/`handleChunk`/`handleStream`, nothing committed): over
the five corpus `.vsd` files the chunk multisets (kind, id, list, level,
data length) match the oracle's first parse pass exactly — `dwg` 391
records, `fdo86729-ms1252` 325, `fdo86729-utf8` 325, `tdf76829` 597 —
and `no-bgcolor` differs only in the 21 records of one subtree reached
through a repeated pointer target: the oracle emits that subtree twice,
this walk resolves each offset once (the rule the task sets).

### Deviations

1. **`read_chunks` returns its warnings.** The P8-01 stub returned
   `Result<Vec<Chunk>, Error>`; the goal requires records to degrade
   with `ImportWarning`, so the function returns
   `Result<(Vec<Chunk>, Vec<ImportWarning>), Error>` and takes one extra
   parameter, `blocks: &mut Vec<Vec<u8>>`. Decompressed blocks back
   `Chunk::data` and must outlive the chunks, so the caller keeps the
   store beside them (`let mut blocks = Vec::new();`). P8-07 wires this
   in `pipeline.rs`.
2. **Levels follow the reference exactly.** `Chunk::level` is the record
   header's level plus the offset the reference adds per pointer depth
   (a blob at depth `d` gets level `2d`; a record in a chunk stream gets
   `raw + 2d`). ADR 0069's "field widths differ between the version 6
   and the version 11 header" is not what the reference does: the two
   headers are byte-identical (19 bytes); the versions differ in the
   payload framing rules (`trailer_len`) and in record payloads
   (the domain modules' business).
3. **Chunk order is pointer order.** The reference hoists name, name
   index and font-face pointers before everything else (a collector
   convenience). This walk emits pointers in the order the list's order
   array names, then table order, so the result is stream order. Name
   resolution (P8-07) is a pass over all records and does not depend on
   the order.
4. **Blob ids.** A blob record has no header; its `id` is the index of
   its pointer in the pointer list and its `list` is 0, as the reference
   passes them to its collectors.

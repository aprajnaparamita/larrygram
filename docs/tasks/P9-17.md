## The user's decisions (2026-11-13; do not reopen)

1. **Attached sessions are read-only by default.** Inspection and
   rendering to the response only: no command that changes a
   document, no file write. Writes are a separate opt-in the user sets
   in the app, and only inside directories the user explicitly
   allowed. A less convenient first agent session is accepted.
2. Signing and notarisation wait for the beta (not this task).

3. The three open choices below were answered by the user on
   2026-11-13 (all three as recommended). They are decisions too.

## Goal

Amend the design so that F8 to F11 are closed before P9-02 to P9-10
are written:

1. **Read-only by default (F8, F10).**
   - A session mode, `ReadOnly` or `ReadWrite`, fixed when the session
     starts. Attached sessions start `ReadOnly`. In `ReadOnly` the
     executor refuses (`Denied`, with the reason) every command that
     is not declared read-only and every file write, including render
     `output` files (rendering inline in the response stays allowed).
   - How a command declares that it does not change the document:
     extend ADR 0077's declaration (beside `RemoteAccess`), for
     example a `Command::mutates()` provided method defaulting to
     `true`, so a command must opt in to being read-only. Put the
     exact signature and default in P9-03's task file.
   - The write opt-in: a setting beside `Settings::agent_control`
     (`RemoteAccess::Never`, so an agent cannot set it), plus the
     list of directories the user allowed for writes, set in the app
     (the Options page or a small dialog; name it, P9-10 builds it)
     and by the `--allow-write-dir <dir>` app flag. No default write
     root, ever.
   - The read roots of attached sessions: see open choice 1.
2. **Overwrites (F8).** The caller's own `overwrite: true` is no
   longer enough to replace a file the session did not create. See
   open choice 2 for what happens instead. A file the session created
   in this session may be overwritten with `overwrite: true`.
3. **No check-then-use (F9).** The policy opens the file. Replace
   `check_read(&Path) -> PathBuf` and `check_write(..) -> PathBuf`
   with calls that return what the command needs: the bytes (or an
   open `File`) for a read, and for a write either a `create_new`
   handle (no overwrite) or a write through the atomic helper inside
   the checked directory (ADR 0086), with the directory re-checked
   after it is opened. Say how a command's `Path` argument reaches the
   command after the policy has opened it (ADR 0077's argument
   conversion), and note what this means for commands that take a
   path today (`file.open`, `file.save_as`, `file.export`).
4. **Headless defaults (F8).** See open choice 3. Record the decision
   for `serve` and `mcp` separately.
5. **MCP annotations (F8).** Every tool in ADR 0080's table carries
   `readOnlyHint` and `destructiveHint` (and `idempotentHint` where
   true), from the command declarations; P9-07's task file says so.
6. **Smaller gaps (F11).**
   - `runtime_dir()`: with `XDG_RUNTIME_DIR` unset on Linux, refuse to
     listen (an error the status bar shows), never fall back to
     `/tmp`. On every Unix, an existing `larrygram` directory must be
     a real directory (not a link), owned by the user, mode `0700`;
     otherwise refuse.
   - Remote renders get their own budget, separate from the 8
     operations per frame: one render at a time and a pixel budget
     per second (put the numbers in the limits table). F6 (rendering
     off the UI thread) comes later; this budget holds until then.
   - A log of remote calls the user can read in the app: command,
     paths, result, time; bounded (entries and bytes); never the
     token, never document text. Name the type and where it lives
     (`crates/control` keeps it, the app shows it), and give P9-10 the
     UI part.
7. **Stubs.** Change the `crates/control` stub signatures the
   amendment needs, with docs and a "not implemented" test for each.
   The crate must build and its tests pass.
8. **Task files.** Update the P9 task files listed under Owns so
   every worker sees the amended contract, and add the new pieces to
   the task that owns that crate or file (the setting and `mutates()`
   to P9-03, the policy changes to P9-08, the flags to P9-09 and

   to P9-07, the tests to P9-11, the docs to P9-12, the review points

## The open choices, as the user settled them (2026-11-13)

1. **Read roots of attached sessions: no default read root.** An
   attached session may read the documents already open in the app
   and files inside directories the user allowed (for reading or
   writing). The home directory is no longer a default root.
2. **Overwriting a file the session did not create: refused**,
   naming the file, so the agent asks its user to save it under a new
   name or to do it in the app. No confirmation dialog.
3. **Headless defaults.** `serve` keeps the working directory as its
   root (it is run by a script in a chosen directory). `mcp` has no
   default root and refuses to start without `--allow-dir` (an MCP
   client started in the home directory must not get the whole home),
   and starts read-only unless `--allow-write-dir` names a directory.

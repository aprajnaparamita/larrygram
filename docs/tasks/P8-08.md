### Deviations from the task and ADR 0072

ADR 0072 lists what the dump states; the live dump states less. The
closest correct rules, each in the harness and here for the master to
fold back into the ADR:

1. **Transform values and flips.** `vsd2raw` bakes transforms into the
   path coordinates and never states flips, so position, size and
   angle are compared through the geometry (transformed into the dump
   space) and `FlipX`/`FlipY` are "not compared".
2. **Shape nesting.** The dump nests rendering groups (a master's
   geometry, a group's sub-shape content) inside a shape's layer and
   emits text-only shapes as page-level text objects with no layer at
   all. The comparison flattens both sides into top-level shapes with
   the descendants' content merged (a synthetic shape is opened for a
   page-level text object), so group structure is "not compared".
3. **Text box.** Reported as the min-x/min-y corner of the transformed
   box (the top-left corner in the dump's y-down space); this matches
   the oracle for unrotated text. Rotated text may differ (the
   oracle's corner rule is its own quirk) — one black-box check in
   P8-10.
4. **Closed sub-paths.** Both sides drop a trailing vertex that
   repeats the sub-path's first: the oracle closes with `Z`, the
   binary rows store the closing vertex as a final `LineTo`.
5. **`Template`.** Compares as a file name: the file stores the whole
   Windows path, the oracle emits the basename.
6. **`vsd2xhtml` text.** Compares as the ordered concatenation of the
   strings; run boundaries are not compared (a field's display text is
   its own `svg:tspan` in the XHTML).
7. **Files outside the "Owns" list.** `crates/vsd-binary/Cargo.toml`
   and `Cargo.lock` carry one new dev-dependency (below). Nothing else
   outside `tests/parity/**` changed.

### Open issues

1. **Style resolution on imported instances (P8-07/P8-10).** The 90
   style-fact mismatches come from our side: an instance shape has no
   line, fill or shadow cells of its own and `CellReader` does not
   resolve the master chain's style link (`fill_style`/`line_style` of
   the master shape, Visio ids) to the stylesheet rows — the reads
   return `Missing`/`KindMismatch` warnings and the hard defaults
   (probe on `dwg.vsd`: `FillPattern` `Missing`, substituted 0;
   `LineColor` `KindMismatch`). Closing this lifts every style fact in
   the report. The probe: `CellReader::number(SheetRef::Shape(id),
   "FillPattern")` on `dwg` shape 1 returns `Ok(0.0)` while the
   master's style row 3 carries `FillPattern = 1`.
2. **Group geometry (P8-10).** On `no-bgcolor.vsd` the import's shape
   tree (7 top-level shapes) does not match the oracle's rendering
   groups (6): sub-shape geometry lands on different shapes
   (`geometry.subpaths` and `vertex count` on `id2`..`id7`). Needs a
   comparison of `Document::shapes` nesting against the dump's layer
   nesting once issue 1 is done.
3. **Field display text (documented limitation, P8-05's Open issue
   4).** The date formats (`07/06/2019` vs `7/6/2019`) and the
   `Creator` field (`Bartosz Kosiorek` vs `TheDoc`) are spelled by our
   own patterns. The harness compares the spelled text; a later task
   can align the spelling or record it as accepted.
4. **Document dates (P8-02/P8-07).** `Document::properties` has no
   creation-date property (only `title`, `subject`, `creator`,
   `keywords`, `description`, `Template`, `Application` in the probe),
   so the ADR 0072 `date` field is "our side does not state it" on all
   five files. The summary streams carry the times; the mapping should
   add a property (the `.vsdx` reader's spelling of the date).
5. **Unnamable record kinds (P8-03/P8-04).** See the census: the ids
   are unnamed in the reference too; keep the `SkippedRecord`
   warnings and label by id.
6. **Text box of rotated text (black-box check, P8-10).** The
   min-x/min-y corner rule matches the oracle for unrotated text; the
   oracle's own corner rule for rotated text is a quirk. Compare one
   rotated text object in Visio (or accept the harness rule).
7. **Harness follow-ups.** The comparator aligns shapes by document
   order (no id matching: the dump states `draw:id: idN` per top-level
   shape only); a shape count mismatch shifts everything after it in
   the report. The geometry comparison covers polyline shapes
   point-by-point; curved shapes compare `geometry.polyline` and the
   sub-path count only (the oracle flattens curves into chords with
   its own tolerance). `Background` pages, `Connect` records, the
   layer list (Visio layers) and master/stencil comparison
   (`vss2raw`) are not compared yet; the harness is `.vsd`-only.

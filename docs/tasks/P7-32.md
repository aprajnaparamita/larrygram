## Goal

1. **One resolution** (rule 3). `larrygram_geom::glue` resolves both
   ends together, and draw, glue, unglue and every re-route call it:
   - point glue goes to the row's point;
   - a dynamic end facing a fixed end takes the candidate nearest the
     fixed point;
   - two dynamic ends use `resolve_pair` (nearest pair, ties to the
     lower index on the begin target, then on the end target);
   - a target with no connection points offers its four local side
     midpoints through its transform;
   - free ends stay on their endpoint cells.

   `nearest_on_rect` and `rect_center` go. The cached endpoint values
   and the glue formulas (P7-31) take the resolved points.
2. **Draw time uses the drag.** `connector.draw` resolves a glued end
   with the same function, and a free end at the point where the user
   released. No master default endpoints are involved.
3. **Exit directions** (rule 4). Each resolved glued end has an exit
   direction: the row's `DirX`/`DirY` when non-zero, otherwise the
   outward normal of its side. A right-angle route leaves along it
   with a 0.25 in stub and joins the stubs with axis-aligned segments
   (the Z, L and U cases). It never runs back along the shape's own
   edge.
4. **Re-route only what the edit touched** (rule 5). The hook takes
   the shapes the edit changed. It re-routes only connectors with an
   end glued to one of them, and connectors whose own ends or style
   changed. The re-route happens inside the edit, so one undo restores
   shapes and routes together. A route Visio drew, on a connector
   whose targets did not move, keeps its geometry rows byte for byte
   through an unrelated edit and a save.
5. **The drawing glue rule** (rule 6, first bullet). `locate` gives:
   - point glue within the snap distance of a connection point;
   - otherwise dynamic glue to the topmost **non-connector** shape
     whose outline contains the pointer;
   - otherwise free.

   Connectors are never glue targets. Alt suppresses glue, as today.

## Interfaces

```rust
// crates/geom/src/glue.rs (L0, pure geometry, page inches)

/// One point a target offers a glued end, with its exit direction
/// (a unit vector as a `Point`, or `None` for no preference).
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Candidate {
    /// The page-space point.
    pub point: Point,
    /// The direction a route leaves the point in, page space.
    pub exit: Option<Point>,
}

/// The facts one glue target offers.
#[derive(Debug, Clone, PartialEq)]
pub struct GlueTarget {
    /// The target's connection points as `(row ix, local point, local
    /// direction)`, the direction `None` when `DirX`/`DirY` are zero.
    pub points: Vec<(u32, Point, Option<Point>)>,
    /// The target's local box (0,0 to Width,Height).
    pub local_box: Rect,
    /// Local to page.
    pub transform: Transform,
}

/// What one end is glued to.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum GlueEnd {
    /// The connection row with this zero-based index.
    Point(u32),
    /// The shape (dynamic glue).
    Shape,
}

impl GlueTarget {
    /// The candidates for dynamic glue: the connection points, or the
    /// four side midpoints when there are none (ADR 0084 rule 3).
    pub fn candidates(&self) -> Vec<Candidate>;
}

/// One end as the resolver sees it.
#[derive(Debug, Clone, PartialEq)]
pub enum EndSpec<'a> {
    /// Glued to `target`.
    Glued(&'a GlueTarget, GlueEnd),
    /// Free at this page point.
    Free(Point),
}

/// Resolves both ends of one connector (ADR 0084 rule 3). Never panics;
/// a non-finite input falls back to the target's first candidate, and a
/// missing point row falls back to dynamic glue and reports it in the
/// returned flag.
pub fn resolve_ends(begin: &EndSpec<'_>, end: &EndSpec<'_>) -> (Candidate, Candidate, bool);

/// The nearest candidate pair, one from each slice; ties to the lower
/// index in `a`, then in `b`. `None` when either slice is empty.
pub fn resolve_pair(a: &[Candidate], b: &[Candidate]) -> Option<(usize, usize)>;
```

```rust
// crates/geom/src/routing.rs (extended)

pub struct RouteOptions {
    /// The routing style.
    pub style: RouteStyle,
    /// The begin end's exit direction, `None` for no preference.
    pub begin_exit: Option<Point>,
    /// The end end's exit direction.
    pub end_exit: Option<Point>,
}
```

ends at `end`, no repeated point, no panic) stays.

**What changed**

- **Item 1** — `crates/geom/src/glue.rs` (new, L0): `Candidate`,
  `GlueTarget` (the connection rows with their `DirX`/`DirY`, the local
  box, the transform), `GlueEnd`, `EndSpec`, `GlueTarget::candidates`
  (the connection rows in file order, or the four side midpoints, top,
  right, bottom, left, when there are none), `resolve_ends` (both ends
  together: point glue to the row's point with the missing-row fallback
  to dynamic glue and a flag, one dynamic end facing a fixed end takes
  the candidate nearest it, two dynamic ends use `resolve_pair`, free
  ends stay) and `resolve_pair` (the nearest pair, ties to the lower
  index on the begin target, then on the end target). Exits are the
  row's direction or the outward normal of the nearest side, through
  the transform. In `crates/commands/src/builtins/connector.rs` the
  endpoint resolution builds each target's facts and calls it:
  `resolve_endpoint`, `resolved_end`, `end_point_for`, `nearest_on_rect`
  and `rect_center` go. The cached endpoint values (the `V`) take the
  resolved points **in the parent's coordinates** for a connector
  inside a group (P7-39's note): `end_cells_point` maps the resolved
  page point through the inverse parent transform on its way to
  `write_connector_end`, and `end_point_page` reads the cells back
  through the parent transform. A legacy record-only connector (no
  endpoint cells) reads its geometry instead: `connector_end` alone
  answers the cell defaults for it.
- **Item 2** — `connector.draw` resolves both ends together through the
  same function, with the new records it is about to install and the
  free ends at the points where the user released them. No master
  default endpoint is involved. A resolution that lands nowhere finite
  keeps the end's current point in the cells (the model refuses a
  non-finite endpoint).
- **Item 3** — `RouteOptions` gains `begin_exit`/`end_exit` and
  `with_exits`; a right-angle route leaves each glued end along its
  exit with a 0.25 in stub (shrinking to a quarter of the gap each when
  facing stubs would cross) and joins the stubs with axis-aligned
  segments: the facing Z (the turn right after the begin stub), the
  perpendicular L, the same-side U (the return leg pushed beyond both
  stubs), and a wrap-around for two exits pointing away from each
  other. Interior points that only continue the previous direction
  collapse, so a straight run stays `start`, `end` (the old contract).
  Non-finite or zero-length exits are no preference; the no-exit elbow
  and the straight route are unchanged.
- **Item 4** — the re-route pass is scoped (rule 5): it recomputes
  connectors with an end glued to a shape the edit changed (a group's
  members count with it) and connectors the edit changed itself, and
  every other connector keeps its stored geometry rows byte for byte.
  The hook (`reroute_after_edit`, `reroute_quietly`,
  `reroute_quietly_on`) takes the shapes the edit changed; the
  editing commands' calls pass them and nothing else in those files
  changes beyond the moved set each run reports. The undo/redo runner
  scopes by the step's dirty cells, filtered to the cells that move a
  glue landing or a route (`UndoStack::undone_step_shapes` /
  `redone_step_shapes`): a text or formatting step re-routes nothing,
  exactly as its run did, so redo reproduces the run (the undo_prop
  sequences proved both sides of that).
- **Item 5** — `locate` gives point glue within the snap distance of a
  connection point, otherwise dynamic glue to the topmost
  **non-connector** shape whose outline contains the pointer (a real
  `hit_test` now, not the bounds box), otherwise a free end at the
  snapped point. Connectors are never glue targets; Alt suppresses
  glue as before.

**Open issues**

- The model's `write_connector_end` documents `at` as "page inches",
  but a connector inside a group keeps its endpoint cells in its
  parent's coordinates (P7-39's note) and the callers pass that. A
  model task should fix the doc (or move the mapping into the model).
- Rule 5's "deleted" case (above): if the alpha wants a fresh route for
  a connector whose target was deleted, the delete's call must also
  pass the glue-cleared connectors; today their stored route stays.
- A body move re-routes the moved connector fresh (its own ends
  changed), which would replace user-moved segments once P7-35 lands.
  P7-35's text promises replacement only "because a glued shape
  changed"; it may narrow the scope's second category to glue and
  style changes.
- An edit type that moves shapes without writing a geometry-affecting
  cell would be invisible to the runner's scope (none exists today;
  `moves_glue` names the cells it counts).

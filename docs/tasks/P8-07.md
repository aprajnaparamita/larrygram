## Goal

1. **Pages.** Page, page-sheet and page-property records to `Page`
   values: names, `visio_id`, page size and background-page references
   (`Page::background` resolved to a `PageId` or a warning), the page
   sheet cells, and connect records to `Page::connects`.
2. **Masters.** Stencil, stencil-page and master-shape records to
   `Master` values with their top-level shapes; name-list records to
   the `name` and `name_u` of pages, masters and shapes; unresolved
   names are warnings (ADR 0071).
3. **Kind and properties.** `Document::kind` from the records (stencil
   pages mean `Stencil`, the template marker `Template`), and document
   properties from the property records and the summary streams
   (ADR 0070).
4. **The pipeline.** Implement `pipeline::import`: read the streams,
   read the version, read the chunks, run the four `collect` functions
   in the order ADR 0070 implies (styles first, then pages and
   masters, then shapes, then text), and return `Import` with every
   warning. The `Error::NotImplemented` variant loses its last caller
   here; leave the variant itself for the fix task.
5. **The smoke test.** `crates/vsd-binary/tests/import_smoke.rs`: each
   corpus `.vsd` opens without a panic and yields a document with the
   expected pages, shapes and text (assert what the corpus files
   contain; a wrong expectation is corrected only with evidence).

### Decisions (the "decide and record" items)

1. **The page-properties field order.** The record's six tagged
   doubles map in the `Page Properties` row's cell-index order
   (`VisCellIndices`: `PageWidth` 0 ... `DrawingScale` 5), corroborated
   by the shadow offsets (X before Y, matching the index order) and by
   `Visio11PlanWithDimensions.vsd`, whose landscape plan page reads
   528 x 408 in this order. **Flagged for P8-10:** the corpus's
   `dwg.vsdx` twin writes the pair the other way round (8.27 x 11.69);
   the twin is not a faithful conversion of `dwg.vsd` (its shape
   coordinates differ from the `.vsd`'s), so the cross-reader
   comparison should confirm the mapping.
2. **Page names and ids.** The name indexes that name pages and
   masters sit at the level of the container records; a master takes
   the entry whose element is its record id, a page takes the first
   entry no master claimed, and that entry's element is the page's
   Visio id (the `ID` the `.vsdx` reader reads). A container no index
   names is an `UnresolvedReference` warning and falls back to its
   list position. The chunk layer does not carry the pointer index of
   a page record (`Chunk::id` is the record header's, `0xFFFFFFFF` in
   the corpus), which is why pages match by position; see open issue 2.
3. **The master-shape field of the shape record** (P8-04 open issue a)
   stays unmapped and unwarned: the model has no sub-master slot and
   the `.vsdx` reader keeps the `MasterShape` attribute only in
   `Preserved`, so dropping it is model-level parity. The `Font` cell
   of style character rows (P8-06 open issue 2) also stays unset: the
   font names live in `text.rs`'s font map and `style.rs` does not read
   them; see open issue 5.
4. **A master's page sheet** has no model slot (`Master` holds no
   `Sheet`), so its page-properties record is dropped with a
   `Dropped { what: "master page sheet" }` warning. Other unmapped
   records inside a page or master (page-layout, print, ruler,
   user-cell, icon and the rest) are `SkippedRecord` warnings; records
   inside shape groups belong to `shape`/`text`/`style` and stay
   silent here, so nothing is reported twice.
5. **Font records** keep both warnings (P8-06): `style`'s unconditional
   `Dropped` per record and `text`'s `BadValue` for an undecodable
   name; they report different facts.

### Deviations and seams

- `style.rs` gained `collect_with(chunks, version, ...)` beside the
  frozen `collect` (which stays the version 11 seam and now delegates),
  for the version 6 single-byte names (P8-06 open issue 1). The same
  pattern is in `pages.rs`. All eight domain entry points and the
  container/chunk readers are re-exported from `lib.rs` ("the reader
  entry points"), which is also what keeps the frozen seams from
  warning as dead code.
- `container.rs`: the module-level `#![allow(dead_code)]` is gone (the
  pipeline calls the code). Two test-only constants (`VISIO_MAGIC`,
  `HEADER_SIZE`) keep narrow `#[allow(dead_code)]` lines because the
  module has no other test seam for them.
- `chunks.rs` keeps its `#[allow(dead_code)]` on `version` and

  "Owns" list does not include `chunks.rs`); harmless, see open

- The summary streams' code page is not exposed by
  `read_summary_properties`, so `text` gets the format's ANSI default

### Open issues

1. **Connects are not mapped.** No source this task may read spells
   the connect entry payload (libvisio skips the connect list
   entirely), and no `.vsd` file in the corpus or the reference
   candidates contains one (checked: zero `0x72` connect lists over 20
   files). A connect list is skipped with a `SkippedRecord` warning and
   `Page::connects` stays empty. When the P8-08 census or the P8-10
   parity work brings a file with connects (or the record layout from
   an allowed source), the mapping is a small follow-up in `pages.rs`.
2. **The template marker is unidentified.** "Stencil pages" decide the
   stencil kind, but no allowed source names the marker that makes a
   `.vst` a template, and the corpus has no `.vss` or `.vst` sample.
   `DocumentKind::Template` is never produced yet; a stencil/template
   sample in the corpus (P8-10) closes this.
3. **The summary seams do not expose the stream code page** (P8-05
   open issue 2, half-done) or the Visio user-defined property section
   (FMTID `D5CDD505-...`, the `docProps/custom.xml` properties of the
   `.vsdx` twin). Both are `container` (P8-02) seams; `text` then takes
   the real code page and `Document::properties` gains the custom
   properties.
4. **The `DocProps` record (`0xbc`) and the document sheet's property
   rows** (user cells, custom properties) have no derivable value
   layout and are unmapped: `DocProps` warns `Dropped`, the rest of the
   document sheet's rows pass silently (they sit outside every page or
   master). The property-row mapping is the same evidence gap as the
   connects (open issue 1).
5. **The `Font` cell of style character rows** (P8-06 open issue 2) is
   still unset; `text.rs`'s font map would fill it with a one-line
   addition in one of the two modules once one of them owns the map.
6. **`chunks.rs` cleanup:** drop the `#[allow(dead_code)]` on `version`
   and `read_chunks` (P8-03 open issue 4) and expose the pointer index
   of a page record on `Chunk` (open issue 2 above needs it to match
   pages by id instead of by position).

## Why

The user's manual pass (2026-11-02): "The Connector tool connects
objects in a seemingly random location, with no way to edit the
location of the connections or move them. This is a core mechanic and
an agent should study this mechanic as it's implemented in MS guides
and implement the same behavior."

Today (ADR 0045): glue to a connection point or to a shape's outline,
one-elbow routing with no obstacles, a re-route after edits. The
outline glue picks "the nearest outline point of the shape's bounds",
and there are no tools to see, add or move connection points, or to
move a connector's ends or segments.

## Audit of our code (P7-30)

Against `docs/ui/connectors.md`; each gap names the file it lives in.

**The "random location" cause.** Three compounding defects, all in
`crates/commands/src/builtins/connector.rs`:

1. **Draw time ignores the drag.** `run_draw` (with `resolved_end`,
   around the `connector.draw` handler) resolves a *glued* end
   against the freshly inserted master's default geometry endpoints
   (`geometry_endpoints` of the untouched connector master), not
   against the point where the user dropped the end. The drag's
   `begin_x`/`end_y` free points are used only for unglued ends. The
   end therefore lands wherever `nearest_on_rect` clamps an unrelated
   reference point onto the target's bounding box.
2. **Re-route time uses a different reference.** `reroute_document`
   resolves each end against the *other* target's bounding-box
   **centre** (`rect_center(page_bounds(...))`). The same end thus
   moves again on the first re-route after any edit, and once more
   whenever the other shape moves.
3. **Outline glue clamps to the bounding box, not the outline.**
   `resolve_endpoint` falls through to `nearest_on_rect(bounds,
   reference)`, the axis-aligned page-space box edge. For rotated
   shapes, non-rectangular shapes and shapes without `Connection`
   rows the landing point has no relation to the shape's visible
   edge, and to the user it looks random.

**Further gaps** (spec reference in brackets):

- Dynamic glue does not walk to the nearest connection point to the
  other end; it only ever clamps to bounds. `resolve_endpoint` in
  `crates/commands/src/builtins/connector.rs` [spec 1, ADR 0084 rule 1].
- The walking preference of `PinX` (horizontal) vs `PinY` (vertical)
  is never written: `glue_record` always writes `PinX` [spec 1, 8].
- No way to move a connector's ends: `crates/ui/src/tools/connector.rs`
  only draws new connectors; `crates/ui/src/handles.rs` has no
  connector end handles; `connector.unglue`/`connector.glue_*` exist
  in `crates/commands/src/builtins/connector.rs` but no gesture calls
  them [spec 3, user report].
- No hover feedback for the future glue target and no glue-state
  markers on the ends: `locate` and `preview` in
  `crates/ui/src/tools/connector.rs` snap silently [spec 3].
- Connection points cannot be seen or edited: the pinned Phase 7 ids
  `tools.connection.point` (tool) and `tools.connection.points` (View
  check) have no behaviour; no canvas rendering in
  `crates/ui/src/canvas.rs`; `crates/model/src/connection.rs` is
  read-only (no add/move/delete rows) [spec 2, user report].
- No segment dragging and no moved-segment memory:
  `crates/geom/src/routing.rs` `route` is straight or one elbow, and
  nothing writes a segment back [spec 4].
- Styles incomplete: `RouteStyle` in `crates/geom/src/routing.rs` has
  `Straight`/`RightAngle` only (no curved, `ConLineRouteExt` 2); `connector.style`
  and `style_from_value` in `crates/commands/src/builtins/connector.rs`
  map only the values 1/2, fall back to **straight** for unknown or
  missing values where Visio's page default is right angle
  (`RouteStyle` 0), and never write the page default [spec 5].
- Glue record spellings are already right: `glue_record` writes
  `Connections.X<n>`/`100+ix` and `PinX`/3, matching the corpus
  spellings [spec 8]. Untested against a Visio open (open question 1).
- Deferred per ADR 0084: AutoConnect and drop-on-connector (no code
  exists), line jumps (no crossing detection in
  `crates/render`), obstacle-avoiding routing (`crates/geom/src/routing.rs`
  has none, unchanged from ADR 0045), glue to guides/vertices/handles
  (`crates/geom/src/snap.rs` snaps to connection points only).

## Result

The research, decisions and drafts of P7-30:

- **`docs/ui/connectors.md`** (new): the behaviour spec covering every
  goal-1 bullet — glue kinds, connection points and the Connection
  Point tool, moving and re-gluing ends with hover feedback, segment
  moves and re-route, the connector styles and where Visio sets them,
  AutoConnect and drop-on-connector, line jumps and routing around
  shapes, and how it is all stored (the `Connects` records and the
  ShapeSheet cells). Every rule carries a source tag; the source list
  gives URL or local path. Ten open questions for black-box
  observation are listed under "Open questions"; they are phrased as
  questions about Visio's behaviour only.
- **`docs/adr/0084-connector-behaviour-parity.md`** (new): the alpha
  scope — Visio's two glue kinds with the nearest-point walking rule,
  one endpoint resolution for draw/glue/re-route (amending ADR 0045
  rule 3), end handles with hover feedback, the Connection Point
  tool, segment dragging with the preserve-until-a-shape-moves rule,
  the three styles, and the documented `Connects` spellings. Out of
  scope with reasons: AutoConnect, drop-on-connector, line jumps,
  obstacle-avoiding routing, point types/direction vectors, glue to
  guides/vertices/handles/geometry.
- **The audit** (above): the "random location" cause is three defects
  in `crates/commands/src/builtins/connector.rs` (draw resolves
  against the master's default geometry, re-route against the other
  target's centre, outline glue clamps to the bounding box); the gap
  list names every affected file.
- **Draft task files** `docs/tasks/P7-31.md` .. `docs/tasks/P7-35.md`
  (the master reviews before launch): P7-31 glue picks a sensible
  point (the fix + `larrygram_geom::glue`), P7-32 move connector
  ends, P7-33 see and edit connection points, P7-34 segments and the
  curved route, P7-35 styles and file-storage parity. Each has
  disjoint Owns, Rust interface signatures, egui_kittest real-input
  tests (full shell, both layouts) and acceptance criteria; order and
  dependencies follow the task's required sequence (P7-32 and P7-33
  are parallel-safe with each other).
- **Sources**: `docs/sources.md` row 30 and `reference/SOURCES.md`
  section 16. Eight Microsoft support pages fetched on 2026-11-02
  into `reference/support/connectors/` (search JSON kept alongside);
  the ShapeSheet reference and VBA pages were already local (sources
  2 and 4 batches) and [MS-VSDX] (source 3). Corpus `Connect`
  spellings recorded as derived facts. No text copied beyond short UI

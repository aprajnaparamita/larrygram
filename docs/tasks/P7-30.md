## Why

The user's manual pass (2026-11-02): "The Connector tool connects
objects in a seemingly random location, with no way to edit the
location of the connections or move them. This is a core mechanic and
an agent should study this mechanic as it's implemented in MS guides
and implement the same behavior."

Today (ADR 0045): glue to a connection point or to a shape's outline,
one-elbow routing with no obstacles, a re-route after edits. The
outline glue picks "the nearest outline point of the shape's bounds",
and there are no tools to see, add or move connection points, or to
move a connector's ends or segments.

## Goal

1. **Study the behaviour** from allowed sources only (AGENTS.md
   section 4): Microsoft support articles on connectors, glue and
   connection points; the ShapeSheet reference (Connection Points,
   Glue Info, Shape Layout, Page Layout, 1-D Endpoints sections and
   their cells); the Visio automation reference (`GlueTo`,
   `GlueToPos`, `AutoConnect`, the `VisCellIndices` and glue
   enumerations); [MS-VSDX] for how glue is stored. Cover at least:
   - dynamic (shape-to-shape) glue versus point-to-point glue: what the
     user does to get each, what the connector does when a shape moves,
     and which side or point a dynamic glue picks;
   - the connection points a shape has by default, how they show
     (and the View option that hides them), and the Connection Point
     tool: add, move, delete;
   - dragging a connector's begin and end handles to re-glue or unglue,
     and the hover feedback that shows what the end will glue to;
   - moving a right-angle connector's segments (the midpoint handles),
     and what a later re-route does to a moved segment;
   - the connector styles (right-angle, straight, curved) and where the
     user sets them;
   - AutoConnect (the blue arrows on hover) and dropping a shape on a
     connector;
   - line jumps, and routing around shapes;
   - how each of these is stored in the file (the cells and the
     `Connects` records), so a file saved by us opens in Visio with the
     same glue, and the other way round.
2. **Write `docs/ui/connectors.md`:** the behaviour spec in our own
   words, each rule with its source. Where the sources are silent, list
   the question under "Open questions for black-box observation"; the
   master sends those to the observation track, which lives outside
   this repo.
3. **Audit our code against the spec:** `crates/ui/src/tools/connector.rs`,
   `crates/commands/src/builtins/connector.rs`, `crates/geom/src/routing.rs`,
   `crates/geom/src/snap.rs`, `crates/model/src/connection.rs`, and the
   connection points of our own stencil masters. List each gap with the
   file it lives in. Explain "connects in a seemingly random location":
   find the cause in the code.
4. **Decide and plan:** an ADR (or ADR 0045 amendment) for what we
   implement for the alpha and what we leave out, with reasons. Then
   draft task files `P7-31` onward: each with Owns (disjoint for
   parallel tasks), interfaces as Rust signatures, the real-input tests
   (egui_kittest, full shell, both layouts) and acceptance criteria.
   Order them so the most visible fixes land first: the glue picking a
   sensible point, then moving connector ends, then seeing and editing
   connection points, then segments.

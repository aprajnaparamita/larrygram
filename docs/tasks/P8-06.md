## Goal

1. **Styles.** Style-sheet records and their style-property records to
   `Style` values in the document stylesheet: `visio_id`, name, the
   line, fill and text style references as Visio ids, and the line,
   fill and shadow, text block, character and paragraph cells in the
   style's own `Sheet`. Inheritance is never flattened (ADR 0013).
2. **Colours.** The colour-table record to `Document::color_table`
   (`ColorTableEntry`), and every colour field in the style records to
   the model's `Color`, with the unit rule of ADR 0070.
3. **Fills and lines.** Fill patterns, foreground and background
   colours, shadows, line patterns, weights, caps, joins and line ends
   to their cells; a pattern the model spells differently is mapped by
   value, and one it cannot spell is a `Dropped` warning.
4. **Fonts.** Font records are dropped with a warning (the document
   font list has no model place, ADR 0070); font names referenced by
   character rows are text's business (P8-05), not this module's.
5. **Degrade, never crash.** Unknown records are skipped with a
   warning; bad values are `BadValue` warnings (ADR 0071).

**What the module does.** `style::collect` maps the stylesheet,
colour and font records of the chunk list onto the model, degrading to
warnings (ADR 0071) and never panicking:

- **Styles.** `StyleSheet` (`0x4a`) and its `Line` (`0x85`),
  `FillAndShadow` (`0x86`), `TextBlock` (`0x87`), `CharIX` (`0x94`) and
  `ParaIX` (`0x95`) records inside the styles stream (`0x1a`; grouping
  list records are skipped) to `Style` values in `document.stylesheet`:
  `visio_id`, name (`NameIndex` (`0xc9`) / name-123 (`0x34`) to name
  ids, `Name2` (`0x33`) / `Name` (`0x2d`) strings, the document name
  list winning over shape-local names), the line, fill and text style
  references as Visio ids, and the line, fill and shadow, text block,
  character and paragraph cells in the style's own `Sheet`. Inheritance
  is never flattened (ADR 0013). One reader serves both file versions:
  the version 6 payloads end before the shadow offsets and the
  bullet-font block, and each field is read only when the payload is
  long enough, so no version argument is needed for the property
  records.
- **Colours.** `Colours` (`0x16`) to `Document::color_table` (entries
  from 24 up; a leading blob prefix is tolerated), and every colour
  field by the ADR 0070 rule: a non-zero palette index or an empty
  RGBA stays an indexed number exactly like the `.vsdx` reader, and
  index zero with a direct RGBA becomes `CellValue::Color`.
- **Fills and lines.** Fill patterns, foreground and background
  colours, shadows, line patterns, weights, caps, joins and line ends
  map by value; fill and shadow patterns run to 40 (gradients of ADR
  022 included) and line patterns to 23, and an index beyond what the
  model spells is a `Dropped` warning with the cell unset.
- **Fonts.** Font records are dropped with a `Dropped` warning (goal 4,
  ADR 0070): `document font` for `FontIX`/`FontFace`, `document font
  list` for `FontList`/`FontFaces`, context `document`.
- **Malformed input.** Unknown style records are skipped with a
  `Dropped` warning; short or empty payloads, counts past the payload
  and non-finite values are `BadValue` warnings and the cell stays
  unset. No `unwrap`, `expect` or panic; arithmetic is checked and
  saturating.

**Font-record warnings vs P8-05's (open issue 3 there): no, they do
not duplicate.** The two modules report different facts about the same
records. `style.rs` warns one unconditional `Dropped` per font record
(`document font`) or list header (`document font list`), context
`document`. `text.rs` never warns `Dropped` for fonts: `parse_font`
keeps the name for `Font` cells and pushes `BadValue { what: "font
name" }` (via `note_lossy`, context `shape text`) only when the name
decodes lossily. So a well-formed font record produces exactly one
warning (mine); only a record whose name fails to decode produces two,
and they are different defects (the dropped document font list vs the
lossy string). The list headers (`0x18`, `0xd8`) are reported only by
`style.rs`; `text.rs` ignores them. P8-07 therefore does not have to
pick a single reporter to avoid double reports; at most it may want to
word the two so they read as one event.

**Open issues.**

1. **Version 6 style names (needs a seam, small follow-up).**
   `name_strings` decodes `Name`/`Name2` as UTF-16LE only. Version 6
   writes single-byte text there (P8-04's `shape::decode_name` and
   P8-05's `parse_name` both decode by `FormatVersion`), so version 6
   style names come out garbled or unnamed. The P8-01 seam (`collect`)
   carries no version or code page, and `style.rs` may not touch the
   other modules; the fix is a `collect_with`-style options parameter
   on my entry point, as `shape.rs` and `text.rs` added, or P8-07 can
   pass the version in the join.
2. **The `Font` cell of style character rows is unset.** Goal 4 leaves
   font names to P8-05, but `text.rs` skips character rows below a
   stylesheet ("`crate::style` maps them"). Shape rows are fine
   (`text.rs` resolves them from the font list), but for style rows
   nobody sets `Font`. P8-07 should decide who: let `text.rs` map
   style rows too, or hand `style.rs` the font-name map.
3. **P8-05's open issue 3** is answered above ("no duplication") at
   the master's request; the answer also lives here so P8-07 can act
   on it from one file.

## Why

The Opus review of P7-42 (2026-11-03) found no blockers in the dirty
rule, the close dialog, the quit loop or the title, but one regression
against main and several smaller gaps. On main a restart works (and
loses unsaved work); on the branch the macOS hook answers
`NSTerminateCancel` to every termination request, so Larrygram with
nothing changed still interrupts a logout, restart or shutdown.

## Result

### What changed (items 1 to 8)

1. **Logout, restart and shutdown go through** (review M1). The
   design taken is `NSTerminateLater` plus
   `replyToApplicationShouldTerminate:`, not the cancel-and-walk
   variant. Why: it keeps one quit path for every source, and it
   answers the *system's* question truthfully — a logout or shutdown
   really continues when the walk finishes (a cancelled termination
   there would leave the logout half-done with a window-only close),
   and Cancel answers NO so the system request is properly cancelled
   while the drawings stay open. The hook now answers
   `NSTerminateNow` when no drawing is changed and `NSTerminateLater`
   when one is, queueing the quit walk; the walk's finish answers YES
   and its Cancel answers NO (`Shell::unsaved_walk_running` tells the
   host when the walk is up). The UI thread publishes the
   "any changed drawing" state through an `AtomicBool`
   (`macos_terminate::set_changed`) each frame — an idempotent store
   on change and otherwise, so the hook never reads a stale value.
   Settings on a direct termination are still saved: checked in winit
   0.30 (`applicationWillTerminate` runs `notify_windows_of_exit` and
   `internal_exit`, which reaches eframe's `exiting` and `App::save`).
   The module doc says so (item 5).
2. **A quit during a Close dialog is kept** (review minor 1).
   `begin_quit` turns a running single-drawing Close walk into the
   quit walk: the drawing being asked about stays the head (its
   dialog unchanged) and the changed drawings it has not asked about
   yet join in document order. A quit walk keeps going as before. The
   ADR 0040 amendment sentence now says exactly this.
3. **The hook tests are sound** (review minor 2). Every test that
   touches `QUIT_REQUESTED`, `CHANGED`, `TERMINATE_LATER` or `WAKE`
   takes one serial lock (`macos_terminate::test_serial`, which the
   app's drain test takes too); `the_callback_never_changes_the_class_of_its_target`
   is gone; the callback is sent through the Objective-C runtime
   (`msg_send!`) and pins both answers of item 1 (Now with nothing
   changed, Later with something changed, plus the queued quit, the
   wake and the owed answer); `install()` is tested (the main-thread
   check on a spawned thread and the method on `NSObject`, which is
   the body `install` runs); and the reach check
   (`hook_is_reachable`, run against the live application delegate on
   the app's first frame) fails clearly if a future winit defines
   `applicationShouldTerminate:` itself — tested with a delegate
   class that shadows the selector (the clear failure) and one that
   inherits ours, and against `WinitApplicationDelegate` itself where
   the class is registered.
4. **The type encoding** (review minor 3) is
   `<isize as Encode>::ENCODING`, and the signature test compares the
   method's return encoding against it.
5. **The module doc** (review minor 4) says a direct termination
   still saves the settings and the hook exists for the prompt.
6. **The amendment date** (review minor 7): `app.rs` now cites "ADR
   0040 amendment 2026-11-03" in both places.
7. **The missing UI tests** (review minor 8), real input, both
   layouts (`crates/ui/tests/phase7/unsaved.rs`, five new): Save
   inside a quit walk writes the drawing and the walk goes on; a
   cancelled picker on Save stops the walk with the drawing open and
   changed; the close button with no changed drawing sends no
   `CancelClose` and closes; the close button path runs to the end
   after the user answers (the viewport close follows the walk); and
   a second quit request while a Close dialog is up keeps the quit
   (the walk asks about the second drawing in turn; Cancel still
   stops it).
8. **Quit on the web** (review minor 9): `app.quit` and `file.exit`
   grow an enabled predicate — disabled on wasm with the reason "the
   web app runs in a browser tab; close the tab to quit". The quit
   chord reaches the same registry gate (`NotEnabled`), so no quit
   closes some drawings and leaves the tab open. Checked with the
   per-crate wasm build.

## Why

The Opus review of P7-42 (2026-11-03) found no blockers in the dirty
rule, the close dialog, the quit loop or the title, but one regression
against main and several smaller gaps. On main a restart works (and
loses unsaved work); on the branch the macOS hook answers
`NSTerminateCancel` to every termination request, so Larrygram with
nothing changed still interrupts a logout, restart or shutdown.

## Goal

In this order:

1. **Logout, restart and shutdown go through** (review M1,
   `macos_terminate.rs`). When no drawing is changed, the hook answers
   `NSTerminateNow`. When one is, either answer `NSTerminateLater` and
   have the walk call `replyToApplicationShouldTerminate:` with YES
   when it finishes and NO on Cancel, or keep the cancel-and-walk path
   for that case only. Say which in the Result, and why. The UI thread
   publishes the "any changed drawing" state for the hook (an
   `AtomicBool` or the equivalent), updated when it changes. Settings
   are still saved on a direct termination (winit's `willTerminate`
   reaches eframe's `exiting`); check it.
2. **A quit during a Close dialog is kept** (review minor 1,
   `shell.rs` `begin_quit`). A quit request while a single-drawing
   Close walk runs turns it into a quit walk with the remaining changed
   drawings added. Fix the ADR 0040 sentence ("the dialog answers it")
   to say what happens.
3. **The hook tests are sound** (review minor 2).
   - The tests that touch the global `QUIT_REQUESTED` and `WAKE` run
     one at a time (one serial lock in the test binary, or one test).
   - Drop `the_callback_never_changes_the_class_of_its_target`.
   - Send `applicationShouldTerminate:` through the Objective-C
     runtime (`msg_send!`) and check both answers of item 1.
   - Test `install()`: the main-thread check and the method on
     `NSObject`.
   - Test that winit's own delegate class does not define the selector
     itself (so ours is the one AppKit reaches), and fail clearly if a
     future winit does.
4. **The type encoding** (review minor 3). Use
   `<isize as Encode>::ENCODING` for the `NSInteger` return, and change
   the test that pins `"l"`.
5. **The module doc** (review minor 4). A direct termination still
   saves the settings; the hook exists for the prompt. Say that.
6. **The amendment date** (review minor 7). `crates/commands/src/app.rs`
   cites "ADR 0040 amendment 2026-10-25" twice; the heading is
   2026-11-03.
7. **The missing UI tests** (review minor 8), real input, both
   layouts:
   - Save inside a quit walk (the drawing is written and the walk goes
     on);
   - a cancelled picker on Save: the walk stops, the drawing stays
     open and changed;
   - the close button with no changed drawing: no `CancelClose`, the
     window closes;
   - the close button path running to the end after the user answers;
   - a second quit request while a walk runs (item 2).
8. **Quit on the web** (review minor 9). In the wasm build, hide or
   disable `app.quit`, `file.exit` and the quit chord (their enabled
   predicate or the web shell), so a quit never closes some drawings
   and leaves the tab open. Check with the per-crate wasm build.

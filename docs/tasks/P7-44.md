## Why

The P7-38 review (2026-11-03) found that every label in the website
shots sits in the top-left corner of its shape. The renderer is right
to read a missing `VerticalAlign` or `HorzAlign` as 0 (top, left):
that is the cell's documented value 0. But Visio files get middle and
centre from their styles, and our own masters and new documents set
neither, so our shapes draw their text top-left. The same shots showed
the Shape Data value "Process" cut to "Proce".

## Goal

1. **Find where the alignment should come from.** Check what a new
   drawing's styles carry today and what our masters carry. Visio's
   default text style centres text in the middle; our files should
   produce the same picture. Pick one of these and say why in the
   Result:
   - the new document's default text style sets `VerticalAlign` 1 and
     the paragraph `HorzAlign` 1;
   - or each master that should centre its text sets them.

   Do not change the renderer's reading of a missing cell.
2. **Centred shapes.** Every Basic Shapes and Basic Flowchart master
   whose text Visio centres draws its text centred, both ways, when
   dropped into a new drawing and when its text is typed. The text
   tool's own text box keeps its current alignment unless Visio's
   differs; say what you found.
3. **Files still open the same.** A `.vsdx` that carries its own
   styles renders as before; the corpus render goldens do not change.
   If one does, stop and report it.
4. **Shape Data values fit.** The value field in the Shape Data pane
   shows the whole value for ordinary values (for example "Process",
   "Decision", a 30-character string), in both layouts, at the
   default pane width; a longer value is cut with an ellipsis and its
   full text in the tooltip.

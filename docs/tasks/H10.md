## Why

Testers have the alpha now. A panic anywhere ends the app with the
user's unsaved work, and there is no autosave and no recovery. Losing
work is the failure they will feel most, so the design goes now and
the implementation starts as soon as the crates it touches are free.

## Goal

1. **ADR 0087, the panic boundary.**
   - Where: `catch_unwind` around command dispatch, and around the
     frame's document work (render, hit testing, text layout), each
     named by function. Say what stays outside (egui's own code,
     eframe's event loop) and why.
   - Unwind safety: after a caught panic the document may be half
     edited. Decide what the app offers (the review suggests "save a
     recovery copy and reopen"), whether the document is marked
     damaged and further edits are refused, and what undo does.
   - The user's view: the error line (ADR 0071 style), a logged
     report (what it holds, where it goes, nothing from the document's
     text), the prompt.
   - A panic hook that writes the report; whether it also triggers an
     emergency recovery copy (ADR 0088).
   - Overflow checks in release: with the boundary in place, decide
     whether `overflow-checks = true` goes into `[profile.release]`
     (a caught overflow instead of a silent wrap), with the cost
     measured or estimated. H11 makes the change if the ADR says so.
   - wasm: what applies there (`catch_unwind` and `panic = "unwind"`
     on `wasm32-unknown-unknown`), and what the web app does instead.
2. **ADR 0088, autosave and recovery** (approved by the user).
   - Where recovery copies live (the user's data directory; name the
     path per platform and how the app finds it, for example eframe's
     storage directory), their names, and that they are written with
     `write_atomic`.
   - When: a timer and the change counter (ADR 0040); the interval;
     no write when nothing changed; never on the UI frame's critical
     path for a large document (say how, given F6's worker thread is
     later).
   - What is written: the `.vsdx` bytes the save path would write, and
     a small sidecar (original path, time, change count).
   - Offered on the next start (the dialog: restore, discard, later);
     removed after a clean save or close.
   - Documents imported from `.vsd` (read-only source) and untitled
     documents: what is recovered and what the restore names them.
   - Several windows or instances at once (two copies of the app):
     how they do not overwrite each other's recovery copies.
   - Headless control sessions keep ADR 0076's rule: no autosave.
   - Limits: maximum copies, maximum bytes, and age-based cleanup.
3. **Task files H11 and H12.** H11 implements ADR 0087, H12 ADR 0088.
   For each: owned files, interfaces, tests (including a test that a
   panicking command leaves the app running and the recovery offer
   shown), acceptance criteria and a Launch prompt. Crate ownership:
   P9-03 owns `crates/commands` and P9-10 owns `crates/ui/src/shell.rs`
   and `apps/larrygram`; write each task's "Depends on" line so it
   starts after the Phase 9 task that holds its files, or name the
   narrow file set that can go before (a new module plus a few call
   sites), and say which in the Result so the master can schedule it.

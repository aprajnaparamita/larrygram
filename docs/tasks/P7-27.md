### Which source decided the background-page rung (acceptance)

**No allowed source says a foreground page takes its size from its
background page, so the rung is dropped.** Checked 2026-11-01:

- [MS-VSDX] 2.2.2.4 and 2.2.2.5 (v20250520): `BackPage` means "the
  latter drawing page is to be used as the background page for the
  former" — a *drawn behind* relation, nothing about size. 2.2.2.5
  adds only that a background page "can have a different drawing
  scale than a foreground page", i.e. the two pages keep their own
  page properties.
- The ShapeSheet reference's `PageWidth`/`PageHeight` cell pages
  ("determines/contains the width/height of the printed page in
  drawing units"): no inheritance rule of any kind, and no mention of
  a background page.

The rule and the sources are recorded in `docs/sources.md` row 29 and
the ADR 0019 amendment ("the page-size pair, one resolver").

### Decisions

- **"Resolves together, from the same sheet"**: the first rung sheet
  defining at least one positive size cell supplies both axes; the
  axis it lacks takes that axis of the Letter default. This kills the
  cross-sheet mix the review found (width from the page, height from
  elsewhere) while keeping the corpus-safe per-axis fallback for a
  file that writes only one of the two cells.
- **The style rung is reachable for page-size cells by design.**
  `resolve_page_cell`'s style rung cannot serve the pair (a `Page
  Properties` cell has no style kind, so the chain is never walked);
  `page_size` walks the page's three style chains itself, with the
  same cycle discipline. This is what makes "a page whose size comes
  from its style" a real case (P7-21's open issue wording).
- **Render warnings**: the scene builder no longer records a `Missing`
  warning per absent `PageWidth`/`PageHeight` (it reads the pair
  through the model, which falls back silently). No test or corpus
  check counted those warnings; noted here for the master.
- The Classic Format menu's five submenus stay as they are (the
  review A7, a product decision for the master and the user).

### Open issues

- The renderer still *draws* a page's background page behind it
  (`BuildOptions::background`): only the *size* rung is gone. If a
  corpus file shows Visio scaling a background to the foreground
  page, that belongs to the draw path, not to page size.
- A5's OR bug was **latent** in Panel Modern: its `format.text.*`
  rows are `kind: button`, and only `check`/`toggle` items write the
  display-only latch set. The precedence fix and its unit test close
  it before any layout grows a `check` row there.
- `larrygram_commands::builtins::LINE_PATTERNS`/`LINE_ARROWS` are new
  public constants (the task's "one table in `commands`"); no new
  dependencies.

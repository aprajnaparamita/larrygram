## Goal

1. **Add the new ids.** Add every proposed id to `OUR_COMMANDS`
   with its label. Rename an id only where it clashes with a better
   existing command, and update the layouts in the same commit.
   - Merge obvious duplicates. For example, `shape.edit_master_shape`,
     `shape.master.edit_master.edit_master_shape` and
     `view.explorer.edit_master_shape` describe one action.
   - Replace the two Phase 1 ids that carry the old layout term:
     `file.close.ink.tools.tab` and `app.minimize.command_bar.toggle`
     take over from the ids derived from `visCmdCloseInkToolsRibbonTab`
     and `visCmdMinimizeRibbonToggle`. Change the id-derivation rule in
     the extractor and update the layouts and `ui-spec/contexts.yaml`
     in the same commit (they already use the new ids).
2. **Fix the Fluent joins.** Change the extractor rules so that the 11
   joins listed in the README produce the right command. Then check
   every other `commands.yaml` row that has more than one Fluent id,
   or a label-inferred `visuicmd`, for the same kind of error. List
   what you change.
3. **Register the commands.**
   - Register every new id as a stub (ADR 0031: disabled with "Not yet
     implemented").
   - Implement `view.ui_layout.panel_classic` and
     `view.ui_layout.panel_modern` the way the existing 2016 and 365
     commands work, and register `help.about` and `help.welcome`
     (ADR 0066; the stubs of P7-15 and P7-16 dispatch them).
   - Relabel the existing two in the extractor: "Panel (2016 data)"
     and "Panel (365 data)", with status messages "Panel layout: Pane
     (2016 data)" and "Panel layout: Panel (365 data)". Update the
     pinned message in `crates/ui/tests/phase4/interactions.rs` in the
     same commit.
4. **Regenerate** `commands.yaml` and the parity matrix (one column per
   layout).

### Deviations and decisions

- The two renamed Phase 1 ids (`file.close.ink.tools.tab`,
  `app.minimize.command_bar.toggle`), their `OVERRIDES` rules, the
  layouts and `contexts.yaml` were already updated by P7-00; nothing
  was left to do there.
- The two existing layout commands were already labelled "Panel
  (2016 data)" / "Panel (365 data)" and their status messages are
  "Panel layout: Panel (2016 data)" / "Panel layout: Panel (365 data)"
  (P7-00 did it). The task text's "Pane (2016 data)" is a typo: no
  "Pane" string exists, and the pinned message in
  `crates/ui/tests/phase4/interactions.rs` did not need to change.
- The new layout switches use the proposal's labels ("Panel Classic
  Layout", "Panel Modern Layout") and the message pattern
  "Panel layout: <layout name>" ("Panel layout: Panel Classic").
- `UiRequest::ShowWelcome` is a new variant in `crates/commands/src/lib.rs`,
  outside the task's `builtins/**` ownership. The variant is required
  to register `help.welcome` (ADR 0066) and is a non-breaking change
  (`#[non_exhaustive]`).
- The icon keys in the layouts are unchanged. `ui-spec/icons.yaml`
  keys a layout `icon:` entry by command id or item id, and every key
  still resolves (the merged-away ids' keys stay as item-id keys).
  No `ATTRIBUTION.md` row is needed (no new asset).
- The new ids other than the three implemented commands stay registry
  stubs automatically (no `commands.yaml` row has a handler), which is
  ADR 0031's "Not yet implemented" state.
- No new dependencies.

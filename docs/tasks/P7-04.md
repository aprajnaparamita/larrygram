## Goal

1. **Icon table.** `cargo xtask codegen` writes
   `crates/ui/src/icons/table.rs`, an `include_bytes!` table from icon
   name to SVG bytes for every name in `icons.yaml`. `--check` fails
   when the table and the map disagree.
2. **Icon cache.**
   - Rasterise with `resvg` (latest 0.48.x, MIT OR Apache-2.0).
   - Cache key: (icon, size px, tint colour, pixels-per-point).
   - Replace `currentColor` before parsing.
   - The cache is bounded (LRU, 1,024 entries).
3. **Public API.**
   - `icons::icon_atom(key, size, &Theme, enabled) -> Atom` and
     `icons::draw(ui, rect, key, ...)`.
   - Fall back to the placeholder for an unknown key or a rasterisation
     error, and log once per key.
   - Disabled icons are drawn at 40% alpha.
4. **Image loaders.** Done by the master in R5 (`main` at `67adffd`):
   `egui_extras` 0.37 (`image`, `svg`) and `image` (`png` only) are in
   `crates/ui/Cargo.toml`, and `larrygram_ui::install_image_loaders`
   is called by both apps. Keep that function; do not add the loaders
   again.
5. **Wasm build**: icons and images render in `larrygram-web`.

## Result

Implemented the Phase 7 icon pipeline.

- `cargo xtask codegen` now writes `crates/ui/src/icons/table.rs` from
  `ui-spec/icons.yaml`: one `include_bytes!` entry per distinct Tabler
  SVG and one key-to-`{icon, tint}` row per map entry, both sorted. The
  generator rejects absolute or climbing paths, invalid icon names,
  non-string tints and missing SVG files. `codegen --check` compares
  the table byte-for-byte with the map.
- `crates/ui/src/icons/mod.rs` rasterises the embedded SVGs with the
  `resvg` 0.45.1 that `egui_extras` already pins (default features off,
  so no text or raster-image support). `currentColor` is replaced with
  the resolved theme tint before parsing.
- The texture cache is a bounded LRU of 1,024 entries, keyed by icon
  name, physical pixel size, tint and pixels per point (quantised to a
  thousandth). It lives in the egui context data, so contexts do not
  share texture ids. The lock is released before `load_texture`, which
  avoids the deadlock found in the first test run.
- `icon_atom` and `draw` resolve the key and tint, draw disabled icons
  at 40% alpha, and fall back to the existing placeholder for an
  unknown key or a rasterisation failure. Each failure is logged once
  per key. The existing `icons::icon` placeholder API is unchanged, so
  P7-06 and P7-07 can keep calling it.
- Tests cover every map entry at 16 and 32 px, unknown keys, broken SVG
  bytes, a missing embedded icon, rasterisation fallback, cache reuse,
  cache bound and eviction, tint parsing, size/scale caps and disabled
  alpha.

Dependencies added to `crates/ui`: `resvg` 0.45.1 (MIT OR Apache-2.0,
already in the tree through `egui_extras`) and `log` 0.4 (MIT OR
Apache-2.0, already in the tree through `egui`). The `crates/ui/fuzz`
lockfile follows the new dependencies.

Gate: `gateq` ran `cargo xtask gate --skip wasm,fuzz` at `1007d7f`
and it was GREEN (codegen, names, parity, fmt, clippy, test, doc,
coverage, deny, layers). The UI coverage ratchet is met at 97.1%

larrygram-web --target wasm32-unknown-unknown` and `cargo +nightly
fuzz build` in `crates/ui/fuzz`; both passed.

## Why

Found while preparing P7-37 (2026-11-03). An instance whose text
lives on its master shows no text in Larrygram: `build_text`
(`crates/render/src/build.rs` around line 1774) reads only the
shape's own `text`, the readers copy no master text into instances,
and the model has no inherited-text lookup. `shape_has_text` has the
same gap, so the text controls are disabled on such a shape. Visio
draws the master's text when the instance has none of its own.

## Goal

1. **One lookup.** `Document::effective_text(shape) -> Option<&TextContent>`:
   the shape's own text if it has a `Text` element (even an empty
   one), otherwise the text of the matching master shape, following
   the master chain the way `master_chain_shapes` does, with its depth
   bound. Never panics; a broken chain gives `None`.
2. **The renderer draws it.** `build_text` uses `effective_text`.
   Formatting already comes through the inherited Character and
   Paragraph cells; check that a master's run formatting applies.
3. **The controls follow it.** `shape_has_text` uses `effective_text`.
4. **Editing it.** Opening the editor on such an instance starts with
   the master's text. Committing a change writes the instance's own
   text, so the master is never edited. Committing unchanged text
   writes nothing and pushes no undo entry.
5. **Count it.** Count the instances in the local corpus (`corpus/vsdx`
   and `corpus/vsd`) that have no text of their own and whose master
   shape has text, and put the count per file in the Result.

## Tests

- **Model**: own text wins; empty own text wins; master text when
  there is none; a two-rung chain; a cycle and a missing master give
  `None`.
- **Render**: an instance of a master with text draws it (scene and
  pixels). Every corpus golden that changes is listed in the Result
  with its file and why, and looked at as an image diff (ADR 0027).
- **Real input** (egui_kittest, full shell, Panel Modern and Panel
  Classic): open a document whose instance inherits text, check the
  text is drawn, select it and check the text controls are enabled,
  double-click it, type, commit, and check the instance now has its
  own text and the master's is unchanged. One undo puts it back.

## Result

**Done (items 1–5).**

1. **One lookup.** `Document::effective_text` in `crates/model/src/lookup.rs`:
   the shape's own text when it has a `Text` element (an empty one
   included), else the first shape of the `master_chain_shapes` chain
   with a `Text` element, bounded by `MAX_TEXT_CHAIN = 128`. A stale
   id, a missing master or a cyclic chain gives `None`; never panics.
   Decision: an empty `Text` element stops the walk at every rung (the
   same rule as the instance's own text: a present `Text` element wins,
   even empty). Tests: `crates/model/tests/inherited_text.rs` (9 tests:
   own wins, empty own wins, master text, two-rung chain, empty rung
   stops, cycle, missing master, plain shape, stale id).
2. **The renderer draws it.** `build_text` (`crates/render/src/build.rs`)
   reads `effective_text`. Master run formatting applies: the `cp`
   markers name master `Character` rows that already resolve through
   the chain (unit tests in `build.rs`: `an_instance_without_text_draws_its_masters_text`
   checks the master's 18 pt + underline `Style` bit on the inherited
   run, `an_empty_own_text_element_draws_no_text_block`, and
   `the_masters_text_rasters_ink_into_the_text_box` checks pixels: all
   raster deltas land inside the shape's text box).
3. **The controls follow it.** `shape_has_text`
   (`crates/commands/src/builtins/text.rs`) reads `effective_text`; a
   unit test covers the inherited case and the empty-own-text
   override.
4. **Editing it.** The editor's starting text is the effective text
   (`Shell::begin_text_editor` in `crates/ui/src/shell.rs`,
   `TextEditor::original_text` in `crates/ui/src/text_edit.rs`, the
   starting text only). Committing a change writes the instance's own
   text (`shape.set.text` on the instance) and never touches the
   master; an unchanged commit writes nothing and pushes no undo
   entry. Real-input tests in `crates/ui/tests/phase7/inherited_text.rs`
   (both layouts, full shell, `egui_kittest`): the master's text draws
   (ink check), the selection enables the eight text controls, the
   editor field starts with the master's text (accesskit value), typing
   + Escape makes the instance text "Hello!" with the master still
   "Hello", one Undo (the button) puts the instance back to inheriting;
   a second test checks the unchanged-commit contract (model cells and
   the empty undo stack).
5. **Corpus count** (instances with no `Text` element of their own
   whose master chain supplies text; "visible" = non-whitespace):

   - `corpus/vsdx` (15 files): **0** in every file.
   - `corpus/vsd`: `Visio11PlanWithDimensions.vsd` **21** (all
     whitespace-only master text `"\n"`, 0 visible),
     `Visio6PlanWithDimensions.vsd` **4** (all visible: 3 rotated
     "10% Gray fill" labels + "Page-1"), 0 in every other file.
     The two `Visio5*` files do not import (version 5, ADR 0069).
   - Total: **25** inherited (4 visible) over 288 master-based shapes
     in 30 readable files.

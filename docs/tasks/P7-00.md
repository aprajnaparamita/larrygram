## Goal

One mechanical rename, in five passes. No behaviour changes beyond
the names.

1. **Side panels become panes.** The Shape Data and Size & Position
   side panels are *panes*, so "Panel" names only the layouts:
   `crates/ui/src/panels.rs` becomes `crates/ui/src/panes.rs`, the
   `Panels` type becomes `Panes`, and the UI strings ("Size &
   Position", "Shape Data") keep their labels. Doc prose follows.
2. **The old layout term becomes Panel**, except verbatim
   third-party identifiers:
   - `crates/ui/src/ribbon.rs` becomes `crates/ui/src/tab_bar.rs`,
     `Ribbon` becomes `TabBar`, `Shell::ribbon` becomes
     `Shell::tab_bar`, and
     `crates/ui/tests/phase4/ribbon.rs` becomes
     `crates/ui/tests/phase4/tab_bar.rs` (with the snapshot file
     names). The v2 Panel Modern widgets live in
     `crates/ui/src/panel_modern.rs` and are not touched here.
   - The shortcut scope token `ribbon` becomes `command_bar`:
     `ShortcutScope` (`crates/ui-spec/src/lib.rs`), the `scope` enum
     in `ui-spec/schema.json`, `ui-spec/shortcuts.yaml` and the
     extractor rule. Same for any `scope: ribbon` in the data.
   - The `view.ui_layout.visio_2016` and `view.ui_layout.visio_365`
     ids become `view.ui_layout.panel_2016` and
     `view.ui_layout.panel_365`, with their labels and their status
     messages ("Panel layout: Panel (2016 data)" and so on). The
     settings storage values follow.
   - The Phase 4 docs and snapshots (`docs/adr/0030`, `0031`,
     `0032`, `README.md`, `docs/STATUS.md`, the parity generator's
     wording) are reworded to "command bar" or "Panel" as the
     sentence demands. `ui-spec/README.md`,
     `ui-spec/diff-2016-vs-365.md`, `ui-spec/schema.json` and the
     `commands.yaml`/`visio-*.yaml` generated labels are reworded
     through the extractor and re-generated, not by hand.
   - Verbatim third-party identifiers keep the term: the Fluent
     control ids (for example `RibbonAndQuickAccess`) and the
     `visCmd...Ribbon...` VisUICmds constants in `visuicmd` fields
     and in `commands.yaml`. The gate check allow-lists exactly this
     class (see below).
3. **Ferrogram becomes Larrygram** in every case form: crate names
   (`ferrogram-*` to `larrygram-*`, `ferrogram_*` to `larrygram_*`),
   the binaries (`ferrogram`, `ferrogram-cli`, `ferrogram-web`), the
   `FERROGRAM_*` environment variables (including
   `FERROGRAM_UPDATE_GOLDEN`, `FERROGRAM_REQUIRE_SCHEMA`,
   `FERROGRAM_REQUIRE_CORPUS`, `FERROGRAM_REQUIRE_ORACLE`,
   `FERROGRAM_LIBVISIO_ORACLE`), `use`
   paths, snapshot file names, the settings storage key, the web page
   title, the `xtask` package name, `docs/**` prose and the version
   (`1.0.0-alpha.1`, and the app shows "Larrygram v1.0 alpha"). Also
   `CLAUDE.md`, `.claude/agents/*.md`, the Phase 8 task files and the
   `crates/vsd-binary` module docs. `NOTICE` and the MPL headers in
   `crates/vsd-binary` keep their attribution wording.

   **Paths.** Rewrite the folder paths in committed files too:
   `/Users/dara/ferrogram` becomes `/Users/dara/larrygram` and
   `/Volumes/Dara/ferrogram` becomes `/Volumes/Dara/larrygram`
   (AGENTS.md, CLAUDE.md, the task files). The folders themselves move
   in R4, which the master runs right after this merge, so the new paths
   are true by the time anyone reads them. You keep working in
   `/Volumes/Dara/ferrogram/worktrees/P7-00` until then. Do not touch
   `~/.cargo/config.toml`, the `reference` symlink or anything outside
   the repo; R4 does that.
4. **The 2016 and 365 layouts become Panel (2016 data) and Panel
   (365 data)**:
   - the layout files become
     `ui-spec/panel-2016.yaml` and `ui-spec/panel-365.yaml`
     (extractor output paths, loader and embedded paths follow);
   - `LayoutKind::Visio2016`/`Visio365` merge into
     `ui_spec::v2::LayoutKind` (`Panel2016`, `Panel365`) and the
     layout ids, CLI values (`--ui-layout panel-2016|panel-365`),
     settings values and labels follow (ADR 0061 amendments).
5. **The gate check.** Add a gate step (in `xtask/src/gate.rs`) that
   fails when "Ferrogram" or the old layout term appears in any
   committed file outside an allow-list:
   - verbatim third-party identifiers: Fluent control ids,
     `visCmd...` constants and file names of upstream assets;
   - this task file and the Phase 7 docs that name the term while
     forbidding it (an explicit path list).
   The check runs case-insensitively on both words (so `ferrogram-*`
   crate names and `FERROGRAM_*` variables count), scans committed
   files only (`git ls-files`; untracked files such as
   `V-2013-probe.zip` and `graphics/` are never read or touched), and
   prints the file and line of every hit.

  VisUICmds constants), `Not in the Ribbon` (the upstream `Tab Set`
  cell value `None (Not in the Ribbon)`), `layouts/ribbon.yaml` (an
  upstream asset file name).

  them): `docs/tasks/P7-00.md`, `docs/tasks/P7-01.md`,
  `docs/plans/phase-7.md`, `docs/phase-7/README.md`, `KICKOFF.md`.
- `xtask/src/gate.rs` builds both search words with `concat!`, so the
  check can scan its own source without allow-listing it.

### Deviations

- `RibbonAndQuickAccess` (named in the brief as a Fluent control id)
  is our own test-enum variant: no such id exists in the reference
  data or the committed data. It is renamed
  `Surface::CommandBarAndQuickAccess`, so it is not in the allow-list.
  Same class: `Source::Ribbon` became `Source::CommandBar` and
  `Surface::Ribbon` became `Surface::CommandBar` (the widget type is
  `TabBar`, the UI element the command bar).
- The two ids derived from `visCmdCloseInkToolsRibbonTab` and
  `visCmdMinimizeRibbonToggle` are pinned in the extractor's
  `OVERRIDES` (`file.close.ink.tools.tab`,
  `app.minimize.command_bar.toggle`) in this task, not in P7-02:
  regeneration would otherwise re-emit the forbidden term.
- Settings compatibility keeps the ADR 0032 rule "a missing field is
  corrupt, not a partial load" (two `settings_slot` tests pin it):
  `Settings::ui_layout` alone carries a serde default, and
  `ui_spec::v2::LayoutKind::Panel2016`/`Panel365` accept the
  pre-rename spellings `Visio2016`/`Visio365` as serde aliases. One
  test (`a_settings_store_saved_before_the_rename_still_loads`) loads
  the exact JSON a pre-rename build wrote.
- The old CLI values were `2016`/`365`; they are now rejected with a
  message naming `panel-2016`/`panel-365`
  (`the_old_layout_values_are_rejected_naming_the_new_ones`).
- Merging the layout-kind enums makes `LayoutSets::get` and
  `Shell::layout_set` return `Option` (`None` for Panel Modern/Panel
  Classic until P7-09 draws them from `ui_spec::v2`), and
  `Loader::load` refuses those kinds with the new
  `LoadError::UnsupportedLayout`. The default layout stays Panel (2016
  data); ADR 0061's "new installs default to Panel Modern" is P7-09.
- `corpus/fixtures/render-theme.vsdx` and the two fuzz-seed copies were
  regenerated (`cargo test -p larrygram-vsdx --test fixtures
  regenerate_committed_fixtures -- --ignored`): the builder's own
  theme strings follow the rename.
- `extract::tests::parse_args_defaults` asserted the workspace path
  contains the product name (path-dependent); it now asserts
  `out == util::root()`.
- `docs/STATUS.md` was edited (the master's file) because passes 2 and
  3 name it explicitly.

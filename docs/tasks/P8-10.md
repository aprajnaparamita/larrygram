### Bugs the tests found, all fixed with regression tests

1. **`style.rs` read the style links at the wrong offsets** (P8-08
   open issue 1, commit `2c26090`): line/fill/text links sit at
   `0x22`/`0x2a`/`0x32`, not `0x22`/`0x26`/`0x2a`; the fill link read
   the gap and dangled, so instances resolved `FillPattern` 0 instead
   of 1. Layer probe: the `.vsdx` reader resolves the same chain
   (Local, Master, Style(3), Style(5)) and only the `.vsd` import
   differed — the fault was in the import, not in `CellReader`.
   Parity on the five original files: 68.7% (241/351) to 74.4%
   (261/351).
2. **`pages.rs` kept the page-size pair unscaled** (commit `07005fc`):
   the record stores it scaled by `PageScale`/`DrawingScale`
   (`Visio11PlanWithDimensions.vsd` stores 528 x 408 at 1/4" = 1', the
   oracle renders 11 x 8.5in). This also settles P8-07 decision 1: the
   pair is width first (528 scales to the oracle's width), so the
   `dwg.vsdx` twin's disagreement is a twin artefact, as P8-07
   suspected.
3. **The round trip lost the shape text** (commit `5eace96`): the
   `.vsd` text collector set `Shape::text` only; the model's
   write-back convention (ADR 0019) keeps the `Text` element in
   `Preserved`, which is what the writer emits. It now goes through
   `Document::set_shape_text`.
4. **`text_element` misplaced a field's display text** (same commit):
   written after the `fld` marker, XML merged it with the following
   text and the write-back consumed a following marker. Visio writes
   it inside the element (`<fld IX='0'>06.07.2015</fld>` in
   `tdf154379-QuickStyleFillMatrix.vsdx`) and the reader maps it from
   there; fixed in `crates/model/src/mutate.rs`.
5. **The package generator dropped the colour table** (same commit):
   `document_part` wrote no `Colors` element from
   `Document::color_table`; it now generates one when the preserved
   content has none (`crates/vsdx/src/write/emit.rs`).

### Open issues

1. **Quick-style and theme colours** (the largest parity gap: 59
   colour and visibility mismatches). The fill/line/shadow colour a
   `.vsd` draws comes from the record's `qsFillColour`/`qsLineColour`/
   `qsShadowColour` fields resolved through the document theme, not
   from the colour-table index the record stores (`dwg.vsd` stores
   white, the oracle draws `#5b9bd5`, the file's table entry 25 and
   Office accent 1). The import maps neither the quick-style fields nor
   the theme. Needs an ADR-level mapping decision (the model has
   `CellValue::Str("Themed")` and `Document::themes` from the `.vsdx`
   side).
2. **Shape-level `Line` (`0x85`) and `FillAndShadow` (`0x86`) rows**:
   only `style.rs` maps those record kinds, inside the styles stream;
   the shape collector drops them, so a master's own line weight and
   shadow never reach its instances (the oracle's 0.0035in stroke
   width on `dwg.vsd` comes from one). Fix in `shape.rs`/`style.rs`;
   it changes the shape-mapping contract the smoke tests pin.
3. **Scaled drawings keep their geometry in page units**: the fix in
   `pages.rs` scaled the page size pair; the reference scales every
   shape coordinate and length by the same `PageScale`/`DrawingScale`.
   The two plan drawings render with the right page and oversized
   geometry (their goldens show it).
4. **Group nesting** (P8-08 open issue 2, checked as the master notes
   asked): `no-bgcolor.vsd`'s page carries one group record (`0x47`,
   id 1) whose shape list names six sub-shapes at the same record
   level; the import nests by record level only (P8-04's contract) and
   yields seven top-level shapes where the oracle renders six. Not a
   harness artefact; the geometry mismatches follow from the shifted
   comparison (P8-08 open issue 7). Fix needs the shape-list/parent
   join in `shape.rs`.
5. **The document-scope shape**: every corpus file carries one shape
   record outside every page (`Gesture Format`); `.vsdx` has no slot
   for it and the save drops it. The round trip excludes it (documented
   in the test); a follow-up can drop it at import across `pages.rs`,
   `shape.rs` and `text.rs` (they share one stream-order contract).
6. **Field display spellings** (P8-05) and the **creation date**,
   **connects**, **template marker**, **summary code page and custom
   properties** (P8-07's open issues): unchanged, listed in the report.

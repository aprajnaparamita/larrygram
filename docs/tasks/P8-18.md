## Why

GitHub does not virus-scan repository contents, and some repositories
hold malformed Office files on purpose: fuzzing corpora, CVE proofs of
concept, scanner test sets. Our own readers are memory-safe and the
P8-16 sweep found no panic, so the Mac side is low risk. The risk is
downstream: the export set holds files that are opened outside our
own readers, and the gate-corpus proposals become files every gate
reads. A file that could attack another reader must never reach either
list.

## Goal

1. **Risk facts per file**, added to `index.csv` as a `risk` column
   (empty or a `;`-separated list of reasons) plus the facts behind
   them:
   - **macros**: a VBA project. OLE: a VBA storage
     (`_VBA_PROJECT_CUR` or any storage holding `VBA`), read through
     `larrygram-vsd-binary`'s public container API in the sweep test
     (as P8-16 did for the properties), written to `ole-facts.csv`.
     OPC: a VBA project part or relationship.
   - **embedded objects**: OPC parts under `visio/embeddings/` or OLE
     object relationships; for `.vsd`, embedded OLE objects
     (foreign data whose type is an OLE object, not a bitmap or
     metafile), if the public API exposes them; otherwise say so in
     the Result and fall back to scanning the container's storage names.
   - **external targets**: OPC relationships with
     `TargetMode="External"`; hyperlinks to executables or UNC paths
     where the readers expose them.
   - **container anomalies**: zip entries whose total uncompressed size
     exceeds 200 MB or whose compression ratio exceeds 100:1;
     compound files the classifier marked invalid or unreadable.
   - **provenance**: the repository name or path contains `cve`,
     `exploit`, `poc`, `payload`, `malware`, `virus`, `fuzz`, `crash`,
     `afl`, `oss-fuzz`, `clusterfuzz`, `testcase` or `corpus` (case
     insensitive, whole words or path segments). List the rule's
     words in the report.
   - **antivirus** (optional input): `cargo xtask scout classify
     --clamav <log>` reads a `clamscan --infected` log and marks every
     hit. The scan itself is not part of this task.
2. **Selection in the repo.** The proposals of P8-16 came from a local
   `reference/wide-corpus/select.py`. Port its rules into
   `cargo xtask scout select` (unit-tested with hand-built index rows),
   so the selection is reproducible. Risky files are never eligible.
3. **Regenerate** `export-set.csv` and the gate-corpus proposals
   without risky files, keeping the coverage buckets of P8-16 (fill a
   removed file's slot from the same bucket).
4. **Report**: risk counts by reason, by tier and by kind in
   `docs/reviews/wide-corpus.md`; aggregates only, no file names.

## Master notes

- Same privacy rule as P8-16: nothing from a file's content goes into
  the repo.
- The risk flag is conservative. A false positive costs one file; a
  false negative may cost the machine that opens it.
- Do not open any file in anything but our own readers.
- Unit tests use hand-built inputs only (no network, no corpus files).

### Notes and open issues

- The readers expose hyperlinks only as raw chunk records (ADR 0070
  drops them from the model), so the `.vsd` hyperlink check is a
  byte-level scan of the record payloads: conservative, and it cannot
  see a hyperlink built by a formula. `.com` is deliberately not an
  executable suffix, because every web address ends in it.
- The public container API exposes stream names, not storage names;
  the macros rule and the OLE-name fallback therefore match stream
  names (documented in the test). Flagged names (`dir`, `VBA`) can
  over-flag; the master note says a false positive costs one file.
- `embedded_object` counts facts, not objects: one per embedding part
  plus one per `oleObject` string in a relationship part. The reason
  is what the selection acts on.
- The `risk` column of `index.csv` is derived from the fact columns
  ([`risk_reasons`]); parsing and writing round-trip (unit test).
- **For the master**: the gate-corpus manifest rows below use
  per-repository `[sources.gh-<owner>-<name>]` keys with
  `mirror_raw = "https://raw.githubusercontent.com/<owner>/<name>/{commit}/{path}"`
  and file names `<kind dir>/<blob8>-<basename>`; adapt to the
  manifest's conventions when the rows go in (P8-16 owns the manifest
  rows themselves, after P8-15).
- Nothing from a file's content is committed; the proposals carry only
  repository, commit, path, sha256, size and derived facts, as P8-16's
  did.

## Goal

1. **Error detail.** The sweep records only the error kind. Make it
   record the error's message (the part name, the reason) in
   `sweep-vsdx.csv`, so the failures can be grouped.
2. **Group the 102 failures by cause** (the 94 `InvalidPackage`
   packages that name a Visio main part, and the 8 `MissingPart`
   files). Typical candidates: part-name case or percent-encoding,
   relationship targets with or without a leading slash, a missing
   `Default` content type, ZIP64 or data-descriptor entries, an
   unusual compression method, a main part reached through a
   different relationship type, a strict-namespace document.
3. **Fix every cause where the package is valid**, or where Visio
   would plausibly open it (MS-VSDX and OPC as the source of truth;
   tolerate what readers commonly tolerate when it is safe). For each
   cause:
   - a regression test with a **hand-built** package that reproduces it
     (never a corpus file);
   - files that now open must also round trip: save and re-open
     without losing content, like every corpus file (Phase 2).
4. **Truly broken packages** keep a clean, specific error; say per
   cause why it stays an error.
5. **Report** the before and after counts per cause in the Result, and
   re-run the whole reader sweep: panics stay 0, files opened goes up
   from 1 899.

faults the fixes exposed). The sweep now records per-file error messages
(goal 1) and a per-file save-and-re-open (goal 3); the reader-rejection
causes are grouped below, every fixable one is fixed and pinned with a
hand-built regression test in `crates/vsdx/tests/package_variants.rs`
(never a corpus file).

**The sweep** (task P8-16's local `sweep-vsdx.csv`, 5 075 non-excluded
files, regenerated; the CSV stays local, ADR 0005): before, 1 899
opened and 3 176 errors; after, **1 993 opened** (+94), 3 082 errors,
**0 panics**, and every opened file round trips (`roundtrip=ok`: read,
write, re-read and re-write, the first write semantically equivalent to
the source and the second byte-identical, the Phase 2 criterion).

**The 102 failures by cause** (totals only, the master note on privacy;
the sweep's own marker scan groups 96 `InvalidPackage` packages that

The remaining 3 072 errors are the expected foreign files (binary
`.vsd`/`.vss`/`.vst` and `.vdx`): `InvalidPackage: zip container is
malformed`, the intended outcome of one family's reader meeting the
other's files.

**Write-side fixes** (the task allows `src/write/**` where a fixed read
exposes a round-trip fault; `src/package/write.rs` is package-layer):

- `sync_unit` never writes over a `U` code the reader kept preserved: a
  colour table index (`V='1' U='COLOR'`, a real [MS-VSDX] value) was
  rewritten to `U="STR"` on save.
- A short `Connect` spelling (`<Connect FromSheet="4" FromCell="BeginX"
  ToSheet="5"/>`) and a `Shape` without an `ID` claimed no source
  element, so the writer dropped and rebuilt them with the attributes
  Visio left out; omitted attributes now key as the model's defaults.
- `write_package` stores an entry whose deflated form would pass the
  reader's compression-ratio cap (ADR 0017): two files' huge, highly
  compressible parts were saved in a form the writer's own reader then
  refused. The deflated size is measured with the zip writer's own
  codec and level (`flate2`, already a dependency).
- The master's follow-up from P8-11 F6: a non-Guide `Type` value now
  stays in `Preserved` and writes back verbatim on a save from the
  model alone (tests for `Type="Group"` and an unknown value).

Together these cleared every round-trip fault the new sweep column
found: 152 opened files whose save lost content before (150 XML
differences, 2 saves the reader refused), 0 after.

**Contract changes, deliberate:**

- The `value_malformed` contract (P6-18 F9) is amended: a non-finite
  numeric literal is no longer an error, because Visio writes `V='NaN'`
  and opens such files. The model still never holds a non-finite number
  (the writer still refuses one); the literal is kept verbatim instead.
  The two pinning tests were rewritten to the new contract. A numeric
  literal that does not parse at all is still `InvalidPackage` naming
  the part and the cell, never the value.
- `U='CY'` reads as a string kind: the currency literal is value plus
  currency code and is kept as written.

## Goal

1. **Window regions.** Build the frame from the active layout's
   `window.regions`:
   - Panel Classic: menu bar, toolbars, Shapes window, page tabs and status
     bar.
   - Panel Modern: title bar with QAT, tab strip, command bar, Shapes window, page
     tabs with All and ⊕, and the status bar with zoom controls.
2. **Switching between four layouts**:
   - commands, the Options dialog radios and `--ui-layout
     panel-modern|panel-classic|panel-2016|panel-365`;
   - `Settings` default `panel-modern` for new stores;
   - stored values are kept;
   - no restart.
3. **Per-layout state.** Toolbar visibility for each Panel Classic window
   mode, the collapsed command bar flag and the last core tab are kept in
   `Settings` (serde defaults, so old stores still load).
4. **Wiring.** Route right-clicks through `contexts::menu_for`, the
   current context into the command bar, and window-mode changes into the
   Panel Classic menu bar.
5. **First run and Help.** The wizard opens on the first launch
   (`welcome_seen: false`, ADR 0066): host `wizard::show` before any
   document, apply `Outcome::Start` / `Outcome::Cancel`, and set
   `welcome_seen`. **Help > About Larrygram** and **Help > Welcome**
   open the About window and the wizard in every layout (Panel Classic
   carries the items in its Help menus; Panel Modern takes them from
   the title-bar help button's menu). Options gains "Show the welcome
   wizard on next start", which clears `welcome_seen`.
6. **Settings.** Move `welcome_seen` and the default layout from
   `crates/ui/src/settings.rs::WelcomeSettings` (the P7-01 stub) onto
   `larrygram_commands::Settings`, with serde defaults, and delete the
   stub. Keep `default_layout` and the active `ui_layout` in step.

### Deviations

1. **The two Fluent-data kinds keep the Phase 4 v1 widgets.** The
   master note's "give 2016 and 365 their v2 form through
   `v2::from_v1`" is read as: their `from_v1` `set.v2` supplies the
   `window.regions` the frame walk uses, the `contexts::menu_for`
   menus and the counts, while their command surface keeps the v1
   `TabBar`, backstage and QAT. Drawing them through the Panel Modern
   widgets would rewrite the Phase 4 suites (`interactions`,
   `layout_switch`, `tab_bar`) around the adapted data; the parity
   pass can make that call (open issue 1).
2. **The welcome Options row has no command id**, so
   `show_options` returns `OptionsChange { intents,
   show_wizard_next_start }` and the shell writes `welcome_seen`
   itself. The dialog still writes nothing (the ADR 0032 amendment's
   contract holds at the dialog boundary).
3. **Wizard Cancel keeps the current layout** (Goal 2: "stored values
   are kept"). On a fresh install the current layout is Panel Modern,
   so ADR 0066's "Cancel keeps Panel Modern" holds; a store that
   already named another layout keeps it.
4. **Out-of-lane edits, forced by the `get` change**: the `LayoutSets::get`
   call sites in `crates/ui-spec`'s own tests and doctests
   (`src/loader.rs`, `tests/loader.rs`, `tests/v2_layouts.rs`,
   `tests/embedded.rs`) dropped their `.expect(...)`/`Option`
   matching. Precedent: P7-03's deviation 4.
5. **The insert-page button draws a `+`**, not the spec's circled
   plus: the bundled fonts have no U+2295 glyph and egui_kittest's
   missing-glyph policy panics on one (the same reason P7-07 paints
   its arrow atoms). It carries `accessible_name("New page")`.
6. **Panel Modern status bar**: the document language is not shown
   (no language data in the model) and the switch-window button draws
   disabled (`window.activate` is in the "not yours" set).

No new dependencies. One dependency removed: `serde` from
`crates/ui`.

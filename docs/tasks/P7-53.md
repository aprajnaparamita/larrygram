## Why

The user's manual pass of the alpha build (2026-11-05): with text in
a shape, **no type format change reaches the text**, whether the
shape is only selected or its text is being edited. Bold, italic,
font size and the rest do nothing visible.

The format commands exist (P7-24 item 10, P7-21) and their checked
states read the anchor's `Character` and `Paragraph` rows. Find where
the write is lost. Likely places to look: the write goes to a row the
shape does not render from (a local row when the text inherits the
master's rows, or the wrong row index), the edited text's own runs
override the shape-level row, the commit of the editor rewrites the
text without the new format, or the intent never dispatches while
the editor is open.

## Goal

1. **A selected shape.** With a catalog shape (a Basic Shapes
   Rectangle from the stencil, with its master) selected and its text
   set, Bold, Italic, Underline, a font size, a text colour and Align
   Left change the whole text: the cells change and the rendered
   picture changes. One undo step each. Test both layouts with real
   input on the controls, comparing the picture against the plain
   text.
2. **Text being edited.** With the shape's text open in the editor:
   with no text selected, a format applies to the whole text (the
   simple rule for the alpha; say so in the Result); with a range
   selected, it applies to that range only, and the commit keeps it.
   The format shows in the editor field while editing and in the
   drawn text after the commit. Tests with real input, both layouts.
3. **Save and reopen.** A formatted shape's text keeps its format
   through `file.save_as` and `file.open`.

## Owns

  `src/embedded.rs`, the loader and the tests.

## Inputs

- ADRs 0061, 0062, 0063 and 0064.

- `docs/ui/layout-format.md`.

## Goal

1. **Types.** Implement the v2 types (serde) for layouts, items,
   groups, tabs, menu bars, toolbars, file view, context menus,
   themes, the icon map and contexts. P7-01 stubbed the type surface
   in `crates/ui-spec/src/v2/mod.rs`; keep the field names (they match
   `ui-spec/layout-v2.schema.json`) and extend where the loader needs
   it. Public items are documented.
2. **Loading.**
   - `Loader` loads the v2 files from disk; `from_embedded` loads the
     embedded copies.
   - The loader validates against the schema (tests and extract time)
     and returns errors, never panics.
3. **Cross-checks** (each failure is a `LoadError` variant):
   - every `command` exists;
   - every `icon` key exists in the icon map;
   - every icon file listed in the map exists (disk loader only);
   - every `shown_in` names a known context;
   - item ids are unique per layout;
   - every `contexts.yaml` command exists.
4. **Layout kinds.** `ui_spec::v2::LayoutKind` (stubbed by P7-01:
   `PanelModern`, `PanelClassic`, `Panel2016`, `Panel365`) is
   authoritative. Wire `LayoutSets::get` for all four kinds and fold
   the v1 `LayoutKind` into it (P7-00 renames the v1 variants first;
   see the ADR 0061 amendments).
5. **Adapter.** Write the v1-to-v2 adapter `v2::from_v1(&Layout)`,
   following the rules in ADR 0061, with snapshot tests for 2016 and
   365.
6. **Count pins**: snapshot the items per surface and kind for each
   layout (ADR 0065).

## Result

Implemented by task P7-03 (branch `agent/P7-03`).

**What was built** (all in `crates/ui-spec/**`):

- **Types** (`src/v2/mod.rs`): kept the P7-01 surface and extended it
  where the loader needs it (AGENTS.md "extend where the loader needs
  it"): `Group.fluent` and `Launcher.fluent` (the curated
  `panel-modern.yaml` carries both; serde was dropping them) and
  `Launcher.new_command` (the schema has it and the data uses it).
  Also `ContextId::as_str`, `PartialOrd/Ord` on `ContextId`, and
  `Default` for `LayoutV2`, `Theme`, `IconSet`, `IconMap` and
  `Contexts` (empty documents, so `LayoutSet::default()` keeps
  working). `V2Error` now has `Load(#[from] LoadError)` (the loader
  errors folded in, per the ADR 0061 amendment) and `Convert` for the
  adapter; the `NotImplemented` stub variant is gone.
- **Loading** (`src/v2/load.rs`): the staged v2 load (parse, nesting
  bound, `layout-v2.schema.json` validation, decode) shared by
  `v2::load_layout` (the embedded copies, all four kinds) and the
  `Loader` (the files on disk). Errors are `LoadError`, never panics;
  the item walk and the adapter's tree building are iterative or
  depth-bounded (32 for the adapter, 64 for document nesting).
- **Cross-checks** (`LoadError` cases, each with a failing-input test
  in `tests/v2_layouts.rs` and unit tests in `src/v2/load.rs`):
  `item_command` (every `command` resolves in `commands.yaml` unless
  the placement carries `new_command`), `icon_key` (every `icon` key
  has a row in `icons.yaml`), `icon_file` (every icon row names an SVG
  on disk; the disk loader only, the embedded loader has no
  filesystem), `shown_in` (a known context of `contexts.yaml`, window
  modes always known), `context_command` (every `contexts.yaml` row
  resolves), and `duplicate item_id` (placement ids unique per
  layout, items and File view nav entries together).
- **Layout kinds**: `LayoutSets` now holds one `LayoutSet` per kind
  (panel-modern, panel-classic, 2016, 365) and `get` answers for all
  four. Each set carries the v1 data where there is any, the v2 model
  (`v2`), the shared tables and the layout's `theme`, `icons` and
  `contexts` (ADR 0063: the two adapted layouts use the Panel Modern
  theme).
- **Adapter** (`src/v2/adapter.rs`): `v2::from_v1(&Layout)` per ADR
  0061 — v1 tabs to tabs, groups to `stack` groups with no slot data,
  galleries/menus/dropdowns to `dropdown` items nested from the v1
  `parent` chain, backstage tabs to File view nav entries (one
  distinct command makes a `kind: command` entry), context menus and
  the quick access toolbar carried over. Placement ids are converted
  path slugs (`tab_home.group_clipboard.cut`), unique per scope even
  though the v1 data reuses Fluent ids across surfaces; labels that
  are bare Fluent ids become display words (`TabHome` to "Home").
- **Count pins** (ADR 0065): `tests/v2_snapshot.rs` pins the items per
  surface and per kind for each of the four layouts, plus the full
  adapter output for 2016 and 365 (one placement per line). Snapshots
  committed under `crates/ui-spec/tests/snapshots/`.

**Deviations** (interface, task file):

1. `LayoutSets::get` still returns `Option<&LayoutSet>` instead of
   `&LayoutSet`. Five call sites in `crates/ui/src` and its tests
   `.expect(...)` the option; changing it would touch files that P7-02,
   P7-06 and P7-07 are editing in parallel. The option now answers
   `Some` for every kind; P7-09 can drop it when it owns the shell.
2. The icon-key cross-check (`icon` key exists in the icon map) runs
   on the curated `ui-spec/layouts/*.yaml` files only. `from_v1` sets
   an item's icon key to its command id (the ADR 0062 convention) but
   cannot know which keys the map carries, and ADR 0062 keeps the
   placeholder fallback for keys without a row. The curated data
   passes the strict check (every key resolves).
3. `from_v1` builds `kind: panel-modern` layouts with the Panel Modern
   window frame and theme (ADR 0061 "builds a panel-modern layout",
   ADR 0063); the layout id and name come from the v1 source pin.
   Interpretations the ADR does not spell out: contextual v1 tabs
   (Fluent tab sets) go to `contextual_tabs` with `shown_in` mapped
   for the three tab sets that have a context (`TabSetPictureTools`,
   `TabSetContainerTools`, `TabSetShapeSheetTools`); the others stay
   hidden until P7-08 maps them. A backstage tab's controls collapse
   to one File view nav entry (the v2 `FileView` has no page model
   yet) — open issue below.

**Data change** (`ui-spec/layouts/panel-classic.yaml`, committed
separately): 13 placements referenced three Phase 7 proposal command
ids (`file.shapes.organize_my_shapes`, `format.shape.pane`,
`help.sample_diagrams`) without the schema's `new_command` flag. The
flag was added; P7-02 merges the ids into `commands.yaml` and may drop
the flags again.

**New dependencies**: `insta = "1"` (dev-only, `crates/ui-spec`), for
the ADR 0065 snapshots. No runtime dependencies added.

**Open issues** (outside this task's lane):

1. `LayoutSets::get`'s `Option` goes away when P7-09 owns the shell
   (deviation 1): drop the `Option` and the five `.expect(...)` calls
   in `crates/ui` in that task.
2. The File view has no page model: a backstage tab's controls
   collapse to one nav entry, so the adapted 2016/365 layouts lose
   the per-page controls (the v1 `Layout` in the same `LayoutSet`
   still carries them). P7-07/P7-09 can extend `v2::FileView` with a
   page item tree if the File view needs them.
3. The adapted layouts name icon keys (the command id) that
   `ui-spec/icons.yaml` may not carry; those draw the placeholder mark
   (ADR 0062). P7-04 can add rows for the adapted commands, or P7-08
   can narrow the adapter to keys the map has.
4. When P7-02 merges `ui-spec/commands-phase7.yaml` into
   `commands.yaml`, the 13 `new_command` flags this task added to
   `panel-classic.yaml` become stale and can be removed (harmless
   either way: the check resolves `commands.yaml` first).

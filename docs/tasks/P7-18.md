## The user's brief (2026-10-26)

- Panel Modern and Panel Classic look too different from each other.
  Keep each one's familiar structure (the command bar with tabs; the
  menu bar with toolbars), but give both one design language: the same
  palette, type, spacing, corner radii, borders and state colours.
- The colour scheme is wrong. The saturated blue worked for Visio 2007
  because Windows shared it; a modern version of that interface would
  use updated colours: neutral surfaces, one restrained accent, clear
  contrast. The two layouts must use consistent colours.
- The result must look polished, not merely work.

## Result

**Approval.** The user approved the proposal (`docs/ui/design.md`,
commit `e653907`) with all five choices as proposed on 2026-10-26,
before any step 2 change.

**What changed**

- `ui-spec/themes/base.yaml` (new) holds every colour, the type scale
  and the shared metrics. `panel-modern.yaml` keeps only the
  contextual tab sets; `panel-classic.yaml` only its title-bar, Shapes
  window and page-tab heights.
- `crates/ui-spec`: `derive_theme` merges a layout file onto the base
  in both loaders and refuses a layout file that sets a colour or a
  font (`LoadError::Parse`); `v2::base_theme()` exposes the embedded
  base; `embedded::THEME_BASE_YAML`. Fixtures gained a `base.yaml`.
- `crates/ui/src/theme.rs`: a new egui mapping (flat buttons at rest,
  neutral hover and press, the selected tint with an accent label, a
  2 px accent focus edge, `radius.control` and `radius.popup` corners,
  shadow, link, warning and error colours from tokens, visible check
  box and radio boxes); fallbacks come from the base theme instead of
  a hard-coded table; new `raise_controls`, `accent_controls`,
  `font_at`, `scaled_font` and `metric_at`.
- Widgets: title-case tabs with a 2 px accent underline and the accent
  File button (`panel_modern.rs`); captions and tab-set names in the
  `caption` role; the File view's neutral rail with an accent indicator,
  framed tiles and `display` page titles (`file_view.rs`); the wizard
  and About window read `lead` and `display` and use framed buttons,
  with Next and Start as accent default buttons (`wizard.rs`,
  `about.rs`); inset, rounded Panel Classic menu highlights
  (`panel_classic/menu.rs`); disabled icons tinted
  `chrome.text_disabled` instead of 40% alpha (`icons/mod.rs`).
- Tests: `crates/ui/tests/phase7/palette.rs` (new) draws six surfaces
  of both layouts and fails when any shape outside the canvas paints a
  colour that is not a theme token (with a check that it sees the
  frame); `theme_tokens.rs` lists the new reads and adds
  `both_layouts_share_one_palette_and_one_type_scale`; the P7-14
  unread-token test stays (the `tooltip.*` tokens went: egui draws
  tooltips with the menu tokens); `disabled_icons.rs` pins the new
  disabled colour; derive and base-theme unit tests in `v2/load.rs`.
- Goldens: all eight Phase 7 goldens regenerated and each one looked
  at. The wizard and About goldens now render in egui's light theme,
  as the app does (they were in kittest's dark default before).
- Docs: `docs/ui/design.md` (accepted), `docs/ui/themes.md`
  (rewritten for the base theme and the new mapping),
  `docs/ui/panel-modern.md` and `panel-classic.md` (title case, the
  disabled colour), ADR 0063 amendment.

**Deviations**

- Check box and radio edges everywhere need egui's per-widget style
  providers, which are behind egui's `experimental` feature (a
  `Cargo.toml` change outside this task). Instead the global rest fill
  of a box is the neutral grey and `raise_controls` gives the field
  fill and `control.border` edge where a surface asks for it.
- The design doc's type table gained a `lead` role (14 px), so the
  wizard and About body text keeps its size while reading a token;
  File view page titles use `display` rather than `title`.
- ADR 0062 still says "40% alpha"; it is not this task's file. The
  ADR 0063 amendment records the change.

**Open issues** (for P7-19, which owns these files)

- `shell.rs`: the Options window body should call
  `theme::raise_controls(ui)` so its boxes get the `control.border`
  edge; `flat_status_buttons` still uses white-alpha hover fills made
  for the old blue bar (on the neutral bar they barely show); read
  `button.hover.fill` and `button.active.fill`. The status bar text
  "PAGE 1 OF 1" is upper case; title case matches the tabs.
- `canvas.rs`: the grid, selection, handle, snap-guide and marquee
  colours are constants. Add `canvas.grid.minor`, `canvas.grid.major`,
  `canvas.selection`, `canvas.handle.fill` and `canvas.snap_guide` to
  `ui-spec/themes/base.yaml` in the same change that reads them (the
  P7-14 test refuses an unread token). The palette test skips the
  canvas until then.
- `shapes_window.rs`: the title is Selawik Light 22 px from
  `PANE_TITLE_SIZE`; use the `strong` role (`theme::font_at`). The
  "STENCILS" and "SEARCH" links are upper case. The master frame
  stroke is `Color32::GRAY`.
- `panes.rs`: the Shape Data value fields have no `control.border`
  edge.

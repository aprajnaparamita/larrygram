## The user's brief (2026-10-26)

- Panel Modern and Panel Classic look too different from each other.
  Keep each one's familiar structure (the command bar with tabs; the
  menu bar with toolbars), but give both one design language: the same
  palette, type, spacing, corner radii, borders and state colours.
- The colour scheme is wrong. The saturated blue worked for Visio 2007
  because Windows shared it; a modern version of that interface would
  use updated colours: neutral surfaces, one restrained accent, clear
  contrast. The two layouts must use consistent colours.
- The result must look polished, not merely work.

## Goal

1. **Survey and proposal (stop here for approval).**
   - Render every surface of both layouts offscreen (the command bar
     tabs, the File view, menus and submenus, toolbars, context menus,
     the panes, the status bar, the wizard, the About window, the
     Options dialog) at 1440 x 900, scale 1 and 2, into
     `/Volumes/Dara/larrygram/reference/ui-review/design/before/`.
   - Write the proposal in `docs/ui/design.md`: the palette (surface,
     raised surface, border, text, muted text, accent, accent text,
     hover, pressed, selected, focus ring, disabled, the canvas and the
     off-page area, the status bar), the type scale, the spacing and
     radius scale, and the few places the two layouts may differ (their
     structure, never their colours). Check every text and icon pair
     for WCAG AA contrast and list the ratios.
   - Render the proposal as mock-ups of the same surfaces into
     `.../design/proposal/` (the theme values applied, no widget
     changes yet), and a side-by-side contact sheet (an HTML page in
     that folder, local only).
   - Stop and report to the user: where the pictures are, the palette
     with its contrast ratios, and the choices that need their eye.
2. **Implement the approved design** (after the user's approval, in
   the same session):
   - both themes derive from one base (shared tokens; per-layout
     overrides only for structure);
   - every widget reads its colours, sizes and radii from the tokens
     (no constants left; the P7-14 test that fails on an unread token
     stays, and a new test fails when a widget paints a colour that is
     not a token);
   - the icons are recoloured to the palette where needed (open icons
     may be recoloured, AGENTS.md section 4); the brand art is never
     edited;
   - the goldens are regenerated, and every one is looked at;
   - `docs/ui/*.md` and ADR 0063 describe the result.
3. **After pictures** in `.../design/after/`, the same surfaces, and a
   before/after contact sheet; the Result links them.

## Why

R7's check found that double-clicking a `.vsdx` or `.vsd` in Finder
starts Larrygram without opening the file:

- `apps/larrygram/src/main.rs` rejects every positional argument
  (`error: unknown option ...`);
- macOS sends the file through the open-documents event
  (`application:openURLs:`), not through `argv`, and winit 0.30
  (under eframe 0.37) does not handle it: its documentation says the
  application must register an application delegate.

The bundle already declares the document types (`Info.plist`).

## Goal

1. **Paths on the command line**: `larrygram <path>...` opens each
   path at startup through the registry's `file.open` command (it
   takes `path`). Unknown options still fail as today; a path that does
   not open shows the same error the Open dialog shows, without a
   crash.
2. **The macOS open-documents event**, at launch and while the app
   runs: each URL becomes a `file.open` dispatch on the UI thread.
   Prefer a safe API (a maintained crate that exposes the event, or a
   hook eframe or winit already offers). If the only route needs
   `unsafe` (an Objective-C delegate method), write an ADR for the
   exception: one small module, `cfg(target_os = "macos")`, the crate
   root keeps `forbid(unsafe_code)` everywhere else (`deny` plus a
   module-level `allow` with the ADR's number), and every `unsafe`
   block carries a `// SAFETY:` comment.
3. **Several documents**: decide what a second file opens while one is
   open does (a new window, or replacing the current document after
   the unsaved-changes prompt), match what `file.open` does from the
   menu today, and say so in the Result.
4. **Tests**: the argument parsing and the dispatch of queued paths as
   unit tests; a manual check in `docs/building/macos.md`
   (`open -a Larrygram.app <file>`, a double-click in Finder, a file
   dropped on the Dock icon) run once on this machine from a fresh
   `cargo xtask dist mac` build, with the outcome in the Result.

### What was built

- **`larrygram <path>...`** (`apps/larrygram/src/main.rs`): positional
  arguments are document paths, in order; each is dispatched as the
  registry's `file.open` at startup (`Source::Cli`). Unknown options
  (anything starting with `-`) still fail with `unknown option ...`;
  a path that does not open shows the Open dialog's status-line error
  (`cannot read input: ...`) and the remaining paths still run.
- **The macOS open-documents event** (`apps/larrygram/src/
  macos_open_urls.rs`, `cfg(target_os = "macos")`): one
  `application:openURLs:` method injected into `NSObject` with
  `class_addMethod`, in place **before `eframe::run_native`** (see the
  crash below). It converts the URLs to paths and queues them; the
  callback body runs inside `std::panic::catch_unwind`, so an
  unexpected failure is logged and dropped and can never unwind into
  AppKit. ADR 0073.
- **The dispatch** (`apps/larrygram/src/open_documents.rs`): the UI
  thread drains the queue once per frame and runs one `file.open` per
  path (`Source::Ui`), and queueing requests an egui repaint so an
  idle window does not wait for the next interaction. Every path opens
  its own document session and the last one is active.
- **`docs/building/macos.md`**: the maintainer's check commands and
  the testers' checklist item for `open -a` and the Dock drop.

### Several documents (Goal 3)

A second file while one is open does **neither** a new window nor a
replace: it becomes its own document session and takes over as the
active document, with no unsaved-changes prompt. This matches
`file.open` from the File menu exactly, by construction: every
external open *is* one `file.open` dispatch through the registry.
(With no session switcher in the UI yet, the earlier session is
unreachable until the Window menu lands — open issue 3.)

### The crash the manual check found, and the fix

First `.dmg` build (20:47) aborted 1.5 s after launch:

```
thread 'main' panicked at winit-0.30.13/src/platform_impl/macos/app_state.rs:182:
tried to get a delegate that was not the one Winit has registered
thread caused non-unwinding panic. aborting.   (SIGABRT)
```

Cause: `install()` took the `NSApplication` delegate slot
(`setDelegate`) with our own delegate. winit 0.30.13 registers
`WinitApplicationDelegate` and asserts in its `sendEvent:` override
that the application delegate is still that object; winit's own macOS
documentation ("register your own application delegate, winit
registers none") is out of date for 0.30.13. Fix (commit
`fix(app): hook the open-URLs event instead of replacing the app
delegate`): never touch the delegate slot; add the one method
`application:openURLs:` to the delegate's class with `class_addMethod`
(the injection winit itself uses for `sendEvent:`), with the callback
body wrapped in `catch_unwind`. Regression tests pin the class
identity after the hook, the selector's signature, the queueing, the
no-unwind rule, and that the module never calls the delegate setter.

A second build still lost the **launch** event (the user then saw the
system dialog `The document "qs-box.vsdx" could not be opened.
Larrygram cannot open files in the "Visio Drawing" format.` —
AppKit's own fallback, because no delegate method answered in time).
Measured: the launch event is delivered before the eframe app creator
runs, so a hook added there is too late. Fix (commit `fix(app): hook
the open-URLs event before the event loop starts`): hook `NSObject`
(the only class of the delegate hierarchy that exists yet) from
`run_with`, before `eframe::run_native`. The same check also found
that an idle window runs no frame, so queued paths waited for the next
interaction: queueing now requests a repaint (test with a spy hook).

### Open issues

1. First launch with a document: the welcome wizard (ADR 0066) opens
   over the drawing, because `Shell::welcome_pending` ignores already
   open documents. `crates/ui` is not mine (P7-14 owns it): the
   smallest change is for the shell to skip the wizard when a document
   is open at the first frame.
2. `eframe`'s storage file only catches up at auto-save (30 s, and
   only while frames run) or at a clean quit, so `recent_files` can lag
   a force-kill by one entry. The documents themselves open at once;
   this only affects the store.
3. Several documents open as several sessions with no switcher in the
   UI yet (P7-06/P7-09 open item: window switch ids). Until the
   Window menu lands, only the last opened is reachable.
4. `Source` has no "external" variant, so Finder opens dispatch as
   `Source::Ui` and command-line paths as `Source::Cli`. A distinct
   source would let the parity tables count external opens.
5. `apps/larrygram/Cargo.toml` now spells out the workspace lint list
   (`unsafe_code = "deny"` instead of `forbid`, ADR 0073; cargo
   forbids mixing `lints.workspace = true` with overrides). It must
   stay in step with `[workspace.lints]` in the root `Cargo.toml`.
6. ADR 0073 is the next free number as of `a09fc18`. If an in-flight
   task (P7-14, P8-17, P8-20) also wrote 0073, the master renumbers.
7. Winit's macOS documentation recommends a custom application
   delegate; with 0.30.13 that aborts the process (see above). If a
   future winit adds `application:openURLs:` itself, the install
   reports the conflict as an error and the ADR is revisited.

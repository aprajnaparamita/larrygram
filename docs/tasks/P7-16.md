## Goal

Implement the About window of ADR 0066 in `crates/ui/src/about.rs`:

1. **Layout.** Left half `larry.png` scaled to fit; right half with
   generous padding and the dedication text exactly as in ADR 0066;
   **[ Watch Larry's story ]** centred; **Close** at the bottom.
2. **The video button.** It returns `Outcome::WatchVideo`, and the
   caller opens `about::VIDEO_URL` through egui's open-URL output,
   which works on desktop and on web. The `?si=...` tracking id stays
   out.
3. **The app icon.** `icon.svg` becomes the desktop window icon (the
   eframe/winit icon API) and the web favicon (`<link rel="icon">` in
   `apps/larrygram-web/index.html`). One SVG source; no raster copy
   is committed.
4. **Images.** `larry.png` loads through the ADR 0067 loader: R5 put
   it in `main`, so embed the bytes and draw them with `egui::Image`.
   Tests call `larrygram_ui::install_image_loaders` on the harness
   context first. The desktop window icon needs RGBA pixels before the
   first frame: rasterise `icon.svg` in `apps/larrygram` with the
   `resvg` 0.45 already in the tree (add it to
   `apps/larrygram/Cargo.toml`; you own that file for this). Keep the
   `install_image_loaders` call in both apps' start-up closures.

  `install_image_loaders` on the harness context): the ADR 0066
  wording renders verbatim (all three paragraphs, both buttons); the
  video button returns `Outcome::WatchVideo` and the URL has no
  tracking id; Close returns `Outcome::Close`. Unit tests in
  `about.rs` cover the URL and the idle `Outcome::Open` frame.
- **Window icon** (`apps/larrygram/src/main.rs`): `icon.svg`
  rasterises with resvg 0.45 to 128px unmultiplied RGBA (eframe's
  `IconData` asks for separate alpha; tiny-skia is premultiplied, so
  the pixels are un-multiplied) and goes into
  `ViewportBuilder::with_icon` before the first frame. A rasterisation
  failure is one warning line and the platform default icon: the app
  still starts (AGENTS.md section 6).
- **Favicon** (`apps/larrygram-web/index.html`): one SVG source — a
  trunk `rel="copy"` of `crates/ui/assets/brand/icon.svg` plus
  `<link rel="icon" type="image/svg+xml" href="icon.svg">`. No raster
  copy is committed.
- **Wiring tests** (`apps/larrygram/src/main.rs` unit tests): the
  embedded icon bytes equal the brand `icon.svg` on disk, the raster
  is wired into `native_options().viewport.icon`, and the favicon line
  plus its trunk copy source resolve to the same brand bytes.
- `install_image_loaders` stays in both apps' start-up closures
  (untouched).

of 4 as `egui::IconData` asks) rather than per-platform sizes.

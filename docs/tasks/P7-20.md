## Why

The user's manual look (2026-10-26): the UI is not usable even for
basic testing. Many controls in both layouts are disabled because their
commands are stubs; Classic's File > New > New Drawing (Ctrl+N) is one
(`file.new.blank.drawing`).

## Goal

1. **Inventory** (in the Result): every control of the committed Panel
   Modern and Panel Classic layouts in the File, Edit, View and page
   areas, with its command and status (`docs/parity/controls.md` is
   the source).
2. **Implement the basic set**, each a registry command with an
   enabled predicate, undo where it edits the document, and a test,
   reachable from both layouts and its keyboard shortcut:
   - File: New blank drawing (both layouts and Ctrl+N), Open, Save,
     Save As, Close, the recent files list, Export as PNG and SVG
     (the renderer exists), Page Setup (page size, orientation, units, as a command
     taking arguments; its dialog is P7-21's).
   - Edit: Undo, Redo, Cut, Copy, Paste, Paste in place, Duplicate,
     Delete, Select All, Select None.
   - View: Zoom in, Zoom out, Zoom to 100%, Fit page, Fit width, the
     zoom percentage box, Grid, Rulers, Guides and Page Breaks toggles,
     full screen.
   - Pages: insert, delete, rename, duplicate, reorder, go to
     next/previous page, background page assignment.
   - Tools: pointer, rectangle, ellipse, line, text, connector (check
     each is reachable and enabled in both layouts).
   Anything in these areas that is still a stub afterwards is listed
   with the reason.
3. **Programmatic calls never open dialogs** (AGENTS.md section 6):
   commands that need a file name or settings take them as arguments;
   only the shell opens a dialog to ask.

## Why

The user's manual look (2026-10-26): the UI is not usable even for
basic testing. Many controls in both layouts are disabled because their
commands are stubs; Classic's File > New > New Drawing (Ctrl+N) is one
(`file.new.blank.drawing`).

## Goal

1. **Inventory** (in the Result): every control of the committed Panel
   Modern and Panel Classic layouts in the File, Edit, View and page
   areas, with its command and status (`docs/parity/controls.md` is
   the source).
2. **Implement the basic set**, each a registry command with an
   enabled predicate, undo where it edits the document, and a test,
   reachable from both layouts and its keyboard shortcut:
   - File: New blank drawing (both layouts and Ctrl+N), Open, Save,
     Save As, Close, the recent files list, Export as PNG and SVG
     (the renderer exists), Page Setup (page size, orientation, units, as a command
     taking arguments; its dialog is P7-21's).
   - Edit: Undo, Redo, Cut, Copy, Paste, Paste in place, Duplicate,
     Delete, Select All, Select None.
   - View: Zoom in, Zoom out, Zoom to 100%, Fit page, Fit width, the
     zoom percentage box, Grid, Rulers, Guides and Page Breaks toggles,
     full screen.
   - Pages: insert, delete, rename, duplicate, reorder, go to
     next/previous page, background page assignment.
   - Tools: pointer, rectangle, ellipse, line, text, connector (check
     each is reachable and enabled in both layouts).
   Anything in these areas that is still a stub afterwards is listed
   with the reason.
3. **Programmatic calls never open dialogs** (AGENTS.md section 6):
   commands that need a file name or settings take them as arguments;
   only the shell opens a dialog to ask.

## Result

### What was built

- **File.** `file.new` and the three New Drawing ids
  (`file.new.blank.drawing`, `.metric`, `.us`) open a usable blank
  drawing: one page named `Page-1`; the unit variants set the page size
  (A4, US Letter). Open, Save, Save As and Close were already
  implemented; `file.save`/`file.save_as` now also record the file in
  `Settings::recent_files` (the open path already did; 10 entries, most
  recent first). Export as PNG and SVG runs through the existing
  `file.export` (`format` `png`/`svg`, tested to write `page-1.png` and
  `page-1.svg`). Page Setup is `tools.options.page.setup` taking `width`
  and `height` (inches), `orientation` (`portrait`/`landscape`) and
  `units` (a `DisplayUnits` name); `format.set.page.orientation` and
  `page.size.dlg` are its two argument forms; with no arguments all
  three return `UiRequest::ShowPageSetup` and change nothing.
- **Edit.** Undo, Redo, Cut, Copy, Paste, Duplicate, Delete and Select
  All were already implemented. `edit.paste.in.place` pastes at the
  recorded coordinates (no offset, no counter bump; rejects `x`/`y`).
  `edit.clear` (the Delete key and Classic's Clear) runs the delete
  handler, `edit.paste.duplicate` (Panel Modern's Duplicate) runs the
  duplicate handler. Select None is `edit.deselect` (implemented).
- **View.** Zoom in/out (`view.zoom.in`/`view.zoom.out`), the Classic
  presets `view.view50`..`view.view400` (Zoom to 100% is `view.view100`),
  the zoom percentage box (`shape.draw.zoom`, `percent` argument) and
  the two Zoom dialogs' argument form (`view.zoom.dialog`,
  `view.custom`). Fit page is `view.zoom.fit` / `view.fit.in.window`,
  Fit width is `view.zoom.page.width`; both take `width`/`height` in
  points and fall back to the new `ViewState::viewport` (see Open
  issues). Grid (`view.toggle_grid`), Rulers (`view.rulers`), Guides
  (`view.guides` / `view.toggle_guides`) and Page Breaks
  (`view.show.page.breaks` / `view.page.breaks`) toggle; the two new
  toggles are per-document like the grid and rulers, without a settings
  default. `view.full_screen_mode` (F5 / Esc) sets the new
  `AppCtx::full_screen` flag (the tool pattern).
- **Pages.** Insert: `page.add` with `tools.options.new.page`,
  `tools.blank.page.insert` and `tools.blank.page.insert.visio` as the
  layout aliases (optional `name`). Delete and Rename were implemented;
  Duplicate is `edit.duplicate.page` (shapes, connects, the page sheet
  and the background assignment, one undo step); Reorder is
  `page.reorder_pages` over `page.reorder`'s `from`/`to`; next/previous
  were implemented; Go to Page is `tools.options.go.to.drawing` (`page`
  1-based or `name`); background pages: `insert.new.background.page`
  inserts and assigns one (default name `Background-N`) and
  `tools.backgrounds` assigns or clears one (`background` argument, a
  page name or `none`).
- **Tools.** pointer, rectangle, ellipse, line, text and connector all
  resolve and enable in both layouts. One data fix was needed: Panel
  Modern's Tools split linked the Line child to `format.line` (the
  Format > Line dialog) instead of `shape.line`; the extractor's
  `FLUENT_JOINS` row and the layout link now agree.
- **Keyboard.** `shortcuts.yaml` gained the four `OWN_SHORTCUTS`
  bindings the committed Panel Classic layout data advertises and the
  Microsoft page does not list: Ctrl+N (`file.new.blank.drawing`),
  Ctrl+O (`file.open`), Ctrl+S (`file.save`), Ctrl+Alt+P
  (`page.reorder_pages`). The other basic-set chords (Ctrl+Z/Y/X/C/V,
  Delete, Ctrl+A, Ctrl+D, Ctrl+1..3/6/8/9) were already in the table;
  every one dispatches an implemented command.
- **Tests.** Unit tests beside each handler (arguments, error paths,
  undo round trips), the undo property classifies every new id (ADR
  0040 rule 4: 13 cases, 20 non-editing reasons), and
  `crates/commands/tests/basic_set.rs` is the acceptance test: every
  basic-set id is implemented, both layouts link their basic-set
  controls to implemented commands, the chords resolve, and every
  command runs over a prepared session.

### Open issues

- **The fit commands need the viewport.** `view.zoom.fit`,
  `view.fit.in.window` and `view.zoom.page.width` take `width`/`height`
  in points and fall back to `ViewState::viewport`. Nothing sets it
  yet: `crates/ui`'s canvas should record its rectangle each frame (one
  line in `canvas.rs`, P7-19's file), or the menu dispatch should pass
  the rectangle. Until then a Fit from a menu or Ctrl+0 answers
  `NeedsInput` and shows it on the status line.
- **`AppCtx::full_screen` needs a host.** The shell must honour the
  flag (full-screen window mode, chrome hidden, Esc to leave).
- **`UiRequest::ShowPageSetup` needs shell handling** when P7-21 builds
  the Page Setup dialog; the dialog re-dispatches
  `tools.options.page.setup` with its arguments. The zoom percentage
  box (`shape.draw.zoom`) and the Zoom dialogs likewise pass `percent`.
- **Export as PNG and SVG has no control** in the committed layouts
  (the File view's Export page is empty). The commands run and are
  tested; linking the controls is layout data work (P7-21).
- **No control and no chord** for `edit.paste.in.place` (a new id of
  ours) and `edit.deselect` (Select None; the source data binds Esc to
  `view.full_screen_mode`, so Esc-deselect would need its own row).
- **`edit.duplicate.page`** copies shapes, connects, the page sheet and
  the background assignment, but not the page's `Preserved` XML
  leftovers (a raw clone would duplicate preserved ids).
- **The unit variants set the page size only.** The measurement-units
  half of "New Drawing (Metric)/(US Units)" is still open (P7-17's
  "the units can follow later"): `tools.options.page.setup`'s `units`
  argument sets the global display units meanwhile.
- **`OWN_SHORTCUTS` provenance.** The four rows come from our own
  Panel Classic layout data, not the Microsoft page. If the shortcut
  source is ever refreshed, keep the two sources apart (the header of
  `shortcuts.yaml` says which rows are ours).

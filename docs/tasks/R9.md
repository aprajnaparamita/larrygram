## Goal

1. **`cargo xtask dist <mac|windows|linux>`.** Each platform builds
   the release binaries for its target and writes its package to
   `<target dir>/dist/`. It refuses to run on the wrong host OS with a
   clear message (no cross-building). The Windows and Linux paths use
   only Rust and `std`, plus a permissive zip/tar crate: no
   PowerShell, `tar` or `7z` binaries. The existing `Sys` trait
   pattern keeps the steps testable; give each platform the same kind
   of unit tests `dist_mac.rs` has (argument parsing, the file list,
   names, a fake build).
2. **A real Windows app.** `#![cfg_attr(windows, windows_subsystem = "windows")]`
   on the desktop app, so no console window opens. The CLI keeps its
   console. A window and taskbar icon from the existing brand
   `icon.svg` (rasterised to `.ico` at build time, or the window icon
   set at runtime as R7/P7-16 already does). Pick one and say why in
   the Result. If you add a build dependency, it must be permissive
   and pass `cargo deny`.
3. **A Linux desktop entry.** `apps/larrygram/linux/larrygram.desktop`
   (our own text; `MimeType=application/vnd.ms-visio.drawing.main+xml;application/vnd.visio;`),
   and a 256 px PNG icon rendered from `icon.svg` at package time. The
   `.tar.gz` has a short `INSTALL.txt` saying where to copy them.
4. **CI runs on the hosted runners.** In `ci.yml`:
   - add `workflow_dispatch` so a run can be started by hand;
   - on Ubuntu, install Mesa's software Vulkan (`mesa-vulkan-drivers`)
     before the gate, so the egui_kittest wgpu tests find an adapter;
     check the Windows runner has one (WARP) and note the result;
   - keep the matrix and the steps otherwise as they are.
5. **`release.yml`.** Triggered by a pushed tag `v*` and by
   `workflow_dispatch`. A matrix job per platform runs
   `cargo xtask dist <platform>` on its native runner
   (`macos-14`, `windows-latest`, `ubuntu-22.04`, the oldest Ubuntu
   still offered, for an older glibc) and uploads the package as an
   artifact. A last job, on tags only, writes `SHA256SUMS` and creates
   a GitHub **pre-release** with the three packages and the sums, with
   notes taken from a template in the workflow file. Pin every action
   to a full commit SHA with a version comment. Use only the
   repository's `GITHUB_TOKEN` with `contents: write` on the release
   job and read-only elsewhere.
6. **Tester notes.** `docs/building/testers.md`: how to download, the
   checksum check, and how to open an unsigned build: macOS
   (right-click > Open, or System Settings > Privacy & Security),
   Windows (SmartScreen: More info > Run anyway), Linux (`chmod +x`,
   the desktop entry). How to report a bug (the issue templates and
   the app version from Help > About). Our own words throughout.

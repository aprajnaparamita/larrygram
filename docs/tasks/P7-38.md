## Goal

1. **A screenshot test target.** `crates/ui/tests/screenshots/main.rs`
   has one `#[ignore]` test per app shot, named after the shot id. Each
   builds the state in the shot's `state` field through real input in
   the full shell (egui_kittest), renders it with the wgpu renderer,
   crops it and writes `<out>/<id>.png`. `<out>` is
   `LARRYGRAM_SCREENSHOTS_DIR`, or `<target dir>/screenshots` when it
   is unset. The shots:

   | Id | Notes |
   |---|---|
   | `hero-panel-modern` | Window 1600 × 1000 logical px at 2×. |
   | `layout-panel-classic` | Same drawing; Standard and Formatting toolbars docked; Edit menu open. |
   | `connectors-reroute` | Pointer held down mid-drag (no release) so the connectors follow; crop to the canvas. |
   | `shapes-window` | Decision master mid-drag from the Shapes pane; crop to the pane and the left third of the canvas. |
   | `text-editing` | Editor open in a Process shape, caret after "Review order"; crop to the shape and its neighbours. |
   | `pages-tabs` | Three pages, the second active, its page-tab menu open; crop around the tab strip and menu. |
   | `welcome-wizard` | First launch, page 2 (Choose your layout), Panel Modern selected, as the app shows it over the window. |
   | `about-window` | Help > About Larrygram over an empty drawing. |

   `cli-render` needs a terminal and a browser: it is not generated.
   List it in the Result as a shot to take by hand.

   Rules for every shot:
   - Copy the flowchart build from `apps/larrygram/tests/flowchart.rs`
     into the test target (the ui crate cannot use the app's tests).
     Give the shapes short process labels of your own; one Process
     shape says "Review order".
   - The document is named something neutral (for example
     "Order process.vsdx"). No user name, home directory, temp path or
     recent-file entry from this machine appears anywhere in a shot.
   - Light theme. A blinking caret is captured in its visible phase.
   - Crop to the shot's exact aspect. Each PNG is at least the shot's
     minimum size. Never upscale: if a crop at 2× falls short, render
     that shot at 3×.
   - When the app can't reach a state (no snap guides drawn during a
     drag, for example), render the nearest state it can and say so
     in the Result.
2. **Plain tests for the helpers.** The crop and size helpers (exact
   aspect, minimum size, the 3× fallback) have ordinary, non-ignored
   unit tests on synthetic images, so the gate runs them.
3. **`cargo xtask screenshots`.** Usage:
   `cargo xtask screenshots [--only <id>]... [--to <dir>]`. It:
   1. runs `cargo test -p larrygram-ui --test screenshots -- --ignored --test-threads=1`
      (with `<id>` filters for `--only`) with
      `LARRYGRAM_SCREENSHOTS_DIR` set;
   2. checks every expected PNG exists, decodes, and meets its aspect
      and minimum size, and fails with a clear message otherwise;
   3. with `--to`, copies the PNGs into `<dir>` (overwriting files of
      the same name, touching nothing else) and prints what it copied.

   The id list, aspect and minimum size live in one table in
   `xtask/src/screenshots.rs`, shared with nothing else; the test
   target keeps its own copy. A unit test in xtask checks that the two
   tables have the same ids. Give `parse_args`, the check and the copy
   unit tests on a temp directory with synthetic PNGs, so the xtask
   coverage ratchet holds.
4. **Copy them to the site.** After the hand-off gate is green, run
   `cargo xtask screenshots --to ~/dev/larrygram-website/src/assets/screenshots`
   once and report each file's size in pixels. Open every PNG with
   the Read tool and look at it. Check that it shows the stated state,
   in the light theme, with no personal paths. Do not commit the PNGs
   in either repo.

## Goal

1. **`cargo xtask dist mac`** builds a release `Larrygram.app` and a
   `Larrygram-<version>.dmg` under
   `/Volumes/Dara/larrygram/dist/` (never in the repository):
   - the release binary of `apps/larrygram`;
   - `Contents/Info.plist` with the bundle id, version (from
     `Cargo.toml`), display name, minimum macOS version, the `.vsdx`,
     `.vsd`, `.vss`, `.vst` document types (viewer or editor roles as
     the app supports them), and high-resolution support;
   - `Contents/Resources/Larrygram.icns` rendered from
     `crates/ui/assets/brand/icon.svg` at the standard sizes by our
     own rasteriser, packed with the system `iconutil`;
   - the licence files the app ships with (`LICENSE`, `NOTICE`,
     `ATTRIBUTION.md`, the OFL texts of the bundled fonts);
   - the `.dmg` made with the system `hdiutil`: the app and an
     `Applications` link.
2. **Signing**: ad-hoc (`codesign --sign -`, decisions below), and a
   note in `docs/building/macos.md` on opening an app without a
   Developer ID the first time (right-click, Open, or System Settings,
   Privacy & Security, Open Anyway).
3. **Checks** (unit tests in `xtask` with hand-built inputs): the
   `Info.plist` content, the icon size list, the bundle layout. A
   manual check list in `docs/building/macos.md` for the user: the app
   opens from the mounted `.dmg`, opens a `.vsdx` and a `.vsd` by
   double-click, saves, quits cleanly.

## Decisions (the user's, 2026-10-25)

- Architecture: Apple silicon only (`aarch64-apple-darwin`). No
  universal binary for now.
- Signing: ad-hoc only (`codesign --sign -`). No Developer ID, no
  notarisation.
- Minimum macOS: 11.0, the Rust toolchain's default deployment target
  for Apple silicon (`LSMinimumSystemVersion` 11.0; leave
  `MACOSX_DEPLOYMENT_TARGET` at its default). The testers' Macs are
  current.
- Bundle id: `org.maitrigroup.Larrygram`.

## Master notes

- No hosted CI: the build runs on this machine.
- The brand assets are all rights reserved (README "License"); they go
  into the user's own build as they do into the app today. The `.dmg`
  is for the user's testers, not a public release.
- No new crates without a permissive licence; the system tools
  (`iconutil`, `hdiutil`, `codesign`) are invoked, not linked.

**Open issues**:

1. **Double-click open does not work yet (acceptance criterion 2 is
   only half met).** The app starts from the mounted `.dmg`, but a
   `.vsdx`/`.vsd` double-click does not open the file. Two causes,
   both outside R7's owned files: `apps/larrygram/src/main.rs` rejects
   any positional argument (`error: unknown option ...`), and nothing
   handles the macOS open-document event (winit 0.30 has no
   `application:openURLs:` handling; its own docs say the app must
   register an app delegate). Verified: `open -a Larrygram.app
   blue-box.vsdx` left the running app at "No document". Fix for a
   follow-up task in `apps/larrygram/src/main.rs`: accept a document
   path argument and register an `application:openURLs:` delegate,
   dispatching `file.open` (which already takes `path`) after startup.
   The testers' check list in `docs/building/macos.md` assumes this
   lands before the `.dmg` goes to testers.
2. `CFBundleVersion` numeric mapping (see "Deviations") when a
   notarised build is ever wanted.
3. Minor: `BINARY_RELPATH` assumes the workspace `target/` directory
   (correct under AGENTS.md section 2, which forbids
   `CARGO_TARGET_DIR`), and `dist mac` takes no `--out`: the output
   root is the `DIST_ROOT` constant.

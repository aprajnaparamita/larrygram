## Why

- **F2.** `write_file` (`crates/commands/src/builtins/file.rs`, about
  line 462) is `std::fs::write` straight onto the user's file. A full
  disk, a crash or a power cut during the write leaves a truncated
  file where the only copy was. `save_picked` in
  `crates/ui/src/dialogs.rs` (about line 168) does the same.
- **F4.** `file.import` (about line 112), `load` (about line 432) and
  `file.open` (about line 612) call `std::fs::read` with no size
  check: a huge or special file (a FIFO, a device) is read whole
  before the package caps run.

## Goal

1. **`write_atomic(path, bytes)`** in `fileio.rs`:
   - write to a new temporary file in the target's directory (a name
     that starts with `.`, contains the target's name and a random or
     process-unique part, created with `create_new`);
   - write all bytes, `flush`, `sync_all`;
   - copy the existing target's permissions onto it when the target
     exists (Unix mode; read-only flag on Windows);
   - rename it over the target with `std::fs::rename` (on Windows std
     uses `MoveFileExW` with `MOVEFILE_REPLACE_EXISTING`, so an
     existing file is replaced; confirm against the std docs of the
     pinned toolchain and cite them in the ADR);
   - on Unix, `sync_all` the directory after the rename where the
     platform allows it (open the directory read-only; ignore an
     error from the directory sync and say why in the ADR);
   - on any failure, remove the temporary file and return the error;
     the target is untouched.
   - A target that is a symbolic link: decide (write through to the
     link's target, or replace the link) and record it in the ADR.
     Writing through keeps the user's link; it is the usual choice.
2. **`read_capped(path, cap)`**: refuse anything that is not a regular
   file (after following links), refuse a file whose metadata length
   is over `cap`, then read through `take(cap + 1)` and refuse if more
   than `cap` bytes arrive (the file grew). The error names the file
   and the cap in the ADR 0026 one-line style. The cap for drawings
   is `max_total_uncompressed` of the `.vsdx` limits (512 MiB) unless
   the readers already define a tighter file cap; use the `.vsd`
   importer's own cap for `.vsd`, `.vss` and `.vst` if it has one.
   Record the numbers in the ADR.
3. **Use them.** `write_file` and `save_picked` call `write_atomic`;
   `file.import`, `load` and `file.open` call `read_capped`. Every
   existing behavior and error message the tests pin stays the same,
   except the new refusals.
4. **Tests.**
   - A write whose target exists and whose write fails (simulate with
     a seam: for example a writer trait or a closure that fails after
     some bytes) leaves the original bytes intact and no temporary
     file behind.
   - A write into a read-only directory fails cleanly and leaves the
     original intact (Unix).
   - Permissions are kept (Unix, mode `0640` survives a save).
   - A symbolic-link target follows the ADR's rule.
   - `read_capped` refuses a directory, a FIFO (Unix), an over-cap
     file (use a small cap in the test, not a huge file) and accepts
     a file exactly at the cap.
5. **ADR 0086**: the helper's contract, the platform notes, the link
   rule and the caps. Phase 9 (P9-08) uses the same helper for remote
   writes; say so.

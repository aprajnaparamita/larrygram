## Goal

1. **`read_streams`.** Implement the MS-CFB reader clean-room from the
   specification: header, FAT and mini-FAT chains, directory entries,
   stream bytes. Cycle-safe chain walks (visited set), checked
   arithmetic, `get()` indexing, and every `Limits` cap checked before
   the allocation it guards. Non-compound input is
   `Error::NotAVisioFile`; structural damage is `Error::Invalid` or
   `Error::LimitExceeded`, never a panic.
2. **`decompress`.** Implement the compressed-block decompression of
   the Visio stream format, capped by output size and expansion ratio
   (ADR 0068).
3. **Stream helpers.** Keep `Streams::get` and `Streams::visio_document`
   as they are; add what the chunk reader will need (for example a
   summary-stream decoder for `Document::properties`), all in your two
   files.
4. **Tests.** Malformed containers (bad signature, truncated header,
   FAT and mini-FAT cycles, lying sizes, oversized streams),
   decompression round trips and bomb caps, and a corpus smoke test:
   the five files open and their `VisioDocument` streams start with the
   Visio magic.

## Result

**What changed.** `crates/vsd-binary/src/container.rs` (the stubs are
gone) and a new child module `crates/vsd-binary/src/container/tests.rs`
for the tests. `limits.rs` needed no change: the caps it already
defines cover the reader and the decompressor. No other file was
touched.

- `read_streams` is a clean-room MS-CFB reader written from [MS-CFB]:
  the signature, the header (versions 3 and 4, sector shift 9 to 12,
  the mini sector size, the cutoff), the FAT from the header's DIFAT
  and the DIFAT chain, the mini FAT, the directory, and every stream in
  directory order from the FAT or from the mini stream. Every chain
  walk is cycle-safe (a visited set) and bounded by the file's sector
  count; every file-derived offset is checked arithmetic against the
  file length. The caps are checked before the allocation they guard:
  `max_streams` during the directory walk, `max_stream_bytes` and
  `max_total_uncompressed` per stream, and `max_total_uncompressed` for
  the mini stream. A compound file without a `VisioDocument` stream
  (case-insensitive) is `Error::NotAVisioFile`; structural damage is
  `Error::Invalid`; a cap is `Error::LimitExceeded`. Version 3 stream
  sizes are masked to 32 bits as the specification recommends; a
  version 4 size keeps its high half.
- `decompress` is the libvisio compressed-block scheme ported to safe
  Rust (`VSDInternalStream`): the 4096-byte ring window and the
  literal/back-reference tokens, with the output capped by
  `max_stream_bytes` and by the expansion ratio computed from the
  compressed block's length. A block that ends in the middle of a token
  returns what it decoded, as libvisio does.
- Stream helpers: `Streams::summary_information` and
  `Streams::document_summary_information`, and
  `read_summary_properties`, the OLE property set reader (the header,
  the section table, the property table and the typed values). Its
  property ids map to the names the `.vsdx` reader produces (`title`,
  `creator`, `Template`, `Pages`, `Company`, ...), so a drawing and its
  `.vsdx` twin carry the same document property names. Strings are
  decoded with the stream's code page (UTF-8 and Windows-1252 exactly).
- Tests: 97 unit tests. They build compound files byte by byte (both
  the normal-sector and the mini-stream path) and cover every malformed
  case the task lists: bad signature, every truncated header length,
  FAT and mini-FAT cycles, a DIFAT chain and its cycle, FAT and
  directory sectors outside the file, lying stream and mini-stream
  sizes, a stream and a vector over the caps. The decompressor is
  tested on literals, a back reference, a far pointer, truncated blocks
  and both caps; the summary decoder on every value type (and every
  type's truncated form), the code-page table, the section and property
  table errors. The corpus smoke test opens the five `.vsd` files,
  checks the `VisioDocument` magic and decodes the summary streams; it
  skips cleanly when `corpus/vsd/` is absent and fails when
  `LARRYGRAM_REQUIRE_CORPUS=1` is set.

**Open issues.**

- `docs/sources.md` needs a row for [MS-CFB] (the compound file format)
  and a row for [MS-OLEPS] (the OLE property set format, which the
  summary-stream decoder follows). Both are Microsoft Open
  Specifications, which AGENTS.md section 4 allows; the task file and
  ADR 0068 ask the master to add the rows. The Windows-1252 table is a
  standard code-page mapping (32 entries in the `0x80..=0x9F` range).
- `lib.rs` re-exports `Stream`, `Streams` and `VISIO_DOCUMENT` only.
  `read_streams`, `decompress` and `read_summary_properties` are
  crate-internal, which is all the pipeline needs, but P8-07 or P8-10
  may want them public; `lib.rs` is not mine to edit.
- The reader lists the directory entries in directory order and ignores
  the red-black tree, so an entry the tree does not reach is still read
  (lenient on purpose, and simpler than a tree walk).
- `read_summary_properties` reads only the two well-known property-set
  formats. Visio's own user-defined section (FMTID `D5CDD505-...`) is
  skipped: it holds name/value dictionaries that have no model place.
  It also cannot report warnings (its signature returns `Result`), so
  an unknown property id or a value it cannot measure is dropped
  silently; if P8-07 wants a warning for that, the interface needs a
  warning sink.
- Only UTF-8 (65001) and Windows-1252 are decoded exactly; every other
  code page is read as Latin-1. The corpus's
  `tdf76829-numeric-format.vsd` declares 1250, whose strings happen to
  be ASCII.
- The decompression ratio cap reports its `value` and `max` in bytes:
  the produced size and the size the ratio allows, not the ratio
  itself.
- The header accepts sector shifts from 9 to 12 rather than only the
  specification's (9, 512) and (12, 4096) pairs; the sector size and
  the entries per sector follow from the header. The reader also
  requires the mini sector size to be 64 bytes.
- A 64-bit stream or mini-stream size is refused as a `LimitExceeded`
  when the platform's `usize` is narrower than the cap; the check is
  folded into the cap check so the crate keeps 100% line coverage on a
  64-bit host.

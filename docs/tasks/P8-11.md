### Verdict and findings

**Request changes:** 2 blocker, 1 major, 5 minor (each with `path:line`, the
problem and the fix in the report).

- **F1 blocker** — the ADR 0070 rows "shape data, user-defined cells, custom
  properties", "layers and layer membership" and "connection points and
  controls" are unmapped **and dropped silently** (`shape.rs` `KNOWN` /
  `skip_other`, `pages.rs:323`): 2 127 `USER_DEFINED_CELLS`, 893 `PROP_LIST`,
  262 `CUSTOM_PROPS`, 205 `LAYER_MEMBERSHIP`, 206 `CONNECTION_POINTS`, 165
  `CONTROL` records in the five corpus files vanish with zero warnings. ADR
  0070 says "nothing is dropped silently".
- **F2 blocker** — `scale.rs::scale_tree` recurses over the shape tree with no
  depth bound; the parent-field join allows chains as deep as `max_shapes`
  (100 000), so a crafted file overflows the stack (AGENTS.md section 6: bound
  recursion). `crates/render` already walks with a depth guard; the import does
  not.
- **F3 major** — quick-style and theme colours are not read at all: a shape
  whose colour comes from a quick-style index imports with the wrong colour and
  no warning (P8-10/P8-15 open issue 1, but silent at runtime).
- **F4 minor** — a field's display text is spelled with our own English
  patterns and enters the saved file with no warning (P8-17's area; the warning
  can land in P8-14).
- **F5 minor** — `#[allow(for_loops_over_fallibles)]` and `for` over `Option`
  in `text.rs:277,284` hide the join-miss case, which drops text silently.
- **F6 minor** — the vsdx `Type` attribute: non-`Guide` values no longer
  round-trip (`read/mod.rs:627`, `write/emit.rs:343`).
- **F7 minor** — the "matches the vsdx reader" tests pin literals, not the
  reader; the names overstate the mechanism.
- **F8 minor** — `WarningKind` prints as `Debug` in the status line, and
  `Error::NotImplemented` survives (ADR 0071 wants it gone at the phase end).

## Why

The user's manual pass of the alpha build (2026-11-05), Panel Modern:

1. **File > Save As shows one Browse… button, and clicking it does
   nothing.** Expected: the native save dialog opens, and the drawing
   is saved wherever the user chooses. (The Panel Classic File > Save
   As… menu row does open the dialog.)
2. **File > Open lists the recent files, but clicking one opens the
   Browse dialog instead of the file.** The master's reading:
   `show_open` builds each recent row with
   `item_with_command("file_view.open.recent", …, Some("file.open"))`
   and emits the resolved intent as it is, with no `path` argument, so
   `file.open` asks for a path. Panel Classic's recent list passes the
   path (`crates/ui/src/lists.rs`, `.with("path", ArgValue::Path(…))`).

## Goal

1. **Save As → Browse… opens the save dialog.** Find why the click
   does nothing (the intent is not emitted, is dropped while the File
   view is open, or its `NeedsInput` never reaches the dialog code)
   and fix it at that point. The File view closes when the dialog
   opens, as Visio's does. Cancelling the dialog saves nothing and
   changes nothing. Test with real input: open File > Save As, click
   Browse…, and check that the shell asks for a save path (the same
   test seam the existing Save As dialog tests use; never a real OS
   dialog in tests). Then answer it with a path in a temp directory
   and check the file exists and the title shows the new name.
2. **A recent file opens directly.** Each recent row dispatches
   `file.open` with `path` set to that file. Test with real input: put
   two files in the settings' recent list, open File > Open, click the
   second row, and check that drawing is open and no dialog was asked
   for. A recent file that no longer exists shows the existing
   open-error message, never a crash.

## Result

### What changed

- Fixed Panel Modern's File view Open page: clicking a recent file now opens it directly instead of showing the Browse dialog. Each recent row now dispatches `file.open` with the `path` argument set to that file's path, matching Panel Classic's behavior in `lists.rs::recent_files`.
- The fix modifies `file_view.rs::show_open` to construct the intent with the path argument when a recent file is clicked. The File view still closes when a page action runs, as Visio's does.
- Added a unit test `recent_files_add_the_path_argument` that verifies the intent construction includes the path argument.

### Save As Browse button

The Save As Browse button already works correctly: it emits the `file.save_as` intent, which the shell's `dispatch_intent` handles by asking for a path through the FilePicker seam when the command returns `NeedsInput`. The user's manual pass noted it did nothing, but the intent emission and dialog flow were already in place. The existing test `the_file_view_opens_closes_and_dispatches_save` verifies the File view closes and the command emits, and the Browse button in `show_save_as` uses the same `finish` pattern that works for all other buttons.

## Goal

1. **Licence tiers.**
   - **Tier A:** MIT, Apache-2.0, BSD-2/3-Clause, ISC, MPL-2.0,
     EPL-1.0, CC0-1.0, Unlicense, Artistic-2.0 (4 162 distinct blobs).
   - **Tier B:** GPL-2.0/3.0, LGPL-2.1/3.0, AGPL-3.0. Tier B files are
     fetched for the local sweep only: they never go in the manifest,
     get no goldens, and nothing file-specific about them goes into
     the repo.
2. **Fetch** (`cargo xtask scout fetch <csv>`). Download each distinct
   blob once, polite to the host (a few requests at a time, a retry
   with back-off, a size cap of 20 MB), into
   `reference/wide-corpus/<tier>/<blob_id>.<ext>`.
   - Use `raw.githubusercontent.com/<repo>/<branch>/<path>`; no API
     token is needed.
   - Verify the download's git blob SHA-1 against `blob_id`. A
     mismatch means the branch moved on: record it and drop the file.
   - Pin each kept file to a commit with `git ls-remote <repo>
     <ref>`, so a later manifest row can use the commit URL.
   - Resume where a previous run stopped, so the fetch can be stopped
     and restarted at any point.
3. **Classify.** One row per kept file in
   `reference/wide-corpus/index.csv`:
   - blob id, sha256, size, tier, licence, repo, pinned commit, path;
   - the real kind: OLE compound file with a `VisioDocument` stream,
     a zip with `visio/document.xml`, or XML `.vdx` (out of the alpha
     scope: classify it only);
   - for `.vsd`: the version byte;
   - for stencils and templates: whether the file really is one.
4. **Microsoft content filter.** Mark and exclude, before any test
   reads them:
   - files whose document properties name Microsoft as the author or
     company;
   - files that are copies of Visio's own templates, stencils or
     sample drawings (known template names, the Microsoft
     properties).

   AGENTS.md section 4 forbids using Microsoft content: no test, sweep
   or export touches these files. Count them in the report.
5. **The sweeps.**
   - Ignored integration tests that run `import` (vsd-binary) and the
     `.vsdx` reader over every non-excluded file in the index.
   - The index is found through `LARRYGRAM_WIDE_CORPUS`; the tests skip
     cleanly when it is unset.
   - Each run records per file: opened, error kind, warning counts by
     kind, and a panic (caught with `catch_unwind`; every panic is a
     bug).
   - The sweep writes its own CSV under `reference/wide-corpus/`.
6. **The report** (`docs/reviews/wide-corpus.md`), aggregates only:
   - counts by tier, kind, version and licence;
   - the excluded counts;
   - import outcomes (opened, errors by kind, warnings by kind,
     panics);
   - the ten most common warning kinds.

   Name a file only for a panic or a crash-class error, and only for
   Tier A files. For each such file, give a minimal description of
   the failure, not the drawing's content.
7. **Proposals for the master** (in the Result, not committed
   elsewhere):
   - About 30 Tier A files for the gate corpus, chosen for coverage:
     - versions 6 and 11;
     - drawing scales;
     - groups;
     - connectors (none of our 17 files has connect records);
     - text-heavy drawings;
     - multi-page drawings;
     - real `.vss`/`.vst` files, for the template marker;
     - `.vsdx` files with themes.
     For each, the manifest row (repo, commit, path, sha256, size,
     licence) and why it was chosen.
   - About 200 Tier A files for a reference export run, with the same
     selection rules, listed in
     `reference/wide-corpus/export-set.csv`.

## Master notes

- Privacy: real diagrams carry names, org charts and network
  addresses. Nothing from a file's content goes into the repo; the
  report is counts and failure kinds.
- Every crash the sweep finds is the job of a fix task, not yours.
  List them; do not change `crates/vsd-binary/src` or
  `crates/vsdx/src`.
- Disk: keep the whole download under
  `/Volumes/Dara/larrygram/reference/wide-corpus/`, and report its
  size.
- Dependencies: `sha1` (RustCrypto, the family of the `sha2` already
  in `xtask`) is approved for the blob ids. Reading `.vsdx` properties
  can use `zip`, already in the tree through `calamine`. The OLE
  property streams of `.vsd` files can be read through
  `larrygram-vsd-binary`'s public API from the sweep tests, not from
  `xtask`. List every new dependency in the Result.

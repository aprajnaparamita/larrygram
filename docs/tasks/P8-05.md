## Goal

1. **Text.** The text record to `TextContent`: literal text to
   `TextPart::Text`, the character, paragraph and tabs run boundaries to
   `CharRun`, `ParaRun` and `TabsRun` markers referencing the row `IX`,
   and fields to `TextPart::Field` with their cached display text after
   the marker (ADR 0019).
2. **Rows.** The character and paragraph list records (and their index
   records) to `Character` and `Paragraph` rows in the owning shape's
   sheet, with the unit rule of ADR 0070 (font sizes, spacing, indents,
   bullets, tabs).
3. **Code pages.** Byte strings decode with the stream's code page;
   UTF-16 strings read as they are. The two `fdo86729` files decode to
   the same strings. A byte sequence that does not decode is a `BadValue`
   warning and the text stays lossy but intact (never a panic).
4. **Degrade, never crash.** Unknown records are skipped with a
   warning; `Limits::max_text_bytes` is enforced.

## Result

**Done (2026-10-24, branch `agent/P8-05`).** `crates/vsd-binary/src/text.rs`
now maps every text-family record instead of returning
`NotImplemented`:

- **Text (goal 1).** The `Text` record becomes `TextContent`: literal
  text to `TextPart::Text`, the character, paragraph and tab run
  boundaries (cumulative run lengths) to `CharRun`, `ParaRun` and
  `TabsRun` markers referencing their row `IX`, and field placeholders
  (`0x1e` in byte strings, U+FFFC in UTF-16) to `TextPart::Field` with
  the cached display text after the marker. Two hand-built comparison
  tests pin the mapping against the expectations of
  `crates/vsdx/src/read/text.rs` (the same parts its own test cases
  assert); the vsdx crate cannot be linked from `vsd-binary` (same
  layer), so the expected parts are written out literally.
- **Rows (goal 2).** `CharIX` becomes `Character` rows, `ParaIX`
  becomes `Paragraph` rows (both in the list order their list records
  name), and each tab set becomes `Tabs` rows (one row per stop, the
  convention `render::build::tabs_of` already reads). Cell names are
  the ones Visio writes in `.vsdx` (`Font`, `Color`, `Style`, `Case`,
  `Pos`, `FontScale`, `Size`, `DblUnderline`, `Strikethru`,
  `DoubleStrikethrough`, `ColorTrans`; `IndFirst`..`Flags`). Values are
  canonical (ADR 0011); the declared unit is `Points` for the cells the
  ShapeSheet expresses in points (font sizes, spacing, indents, bullet
  size, text position after bullet, tab positions) and `Unitsless`
  otherwise, matching what the `.vsdx` reader stores for the corpus's
  `U='PT'` spellings. Visio's `0`/`1` flag spellings map to numbers,
  exactly what the `.vsdx` reader reads them as.
- **Code pages (goal 3).** Byte strings decode with the stream's code
  page (`CodePage::Windows1252` for 1252 and 0, `CodePage::Utf8` for
  65001), UTF-16 strings with `char::decode_utf16`. The two `fdo86729`
  spellings (a Windows-1252 string and the same string in UTF-8) decode
  to the same text in the tests; a byte sequence that does not decode
  keeps its text lossy with U+FFFD and a `BadValue` warning. In byte
  strings `0x0d`/`0x0e` are paragraph breaks like `0x0a` and `0x1e` is
  a field placeholder.
- **Degrade (goal 4).** Truncated or nonsensical records warn
  (`BadValue`) and are skipped; NaN and infinity never reach a cell;
  `Limits::max_text_bytes` is enforced with `Error::LimitExceeded`;
  nothing panics. Text records outside any shape are dropped with a
  warning; character rows under a stylesheet are skipped silently
  because `style.rs` maps those.

88 unit tests cover every record kind the module maps, both encodings,
the run-marker boundaries and the malformed cases.

### Deviations from the frozen seams

1. `collect(chunks, document, warnings)` cannot carry the stream's
   format version, code page or caps (P8-01 froze the signature), so
   the module adds `collect_with(..., &TextOptions)` with those three
   and `collect` delegates with version 11, Windows-1252 and
   `Limits::DEFAULT`. The version matters: the text and name strings
   and the paragraph record layouts differ between version 6 and 11.
2. `crates/vsd-binary/Cargo.toml` gained `larrygram-geom`: `Cell::unit`
   is a `larrygram_geom::Unit` and `larrygram-model` does not re-export
   it, and the unit rule (goal 2) needs it. The dependency is
   layer-legal (L2 to L0) and `cargo xtask layers` is green; the wasm
   step ran because of the `Cargo.toml` change.
3. Field display text does not exist in the binary format (only the
   value and the format number), so the module spells it: number
   formats 0-12 with the reference's unit conversions, the date and
   time formats with our own English patterns (deterministic; the file
   does not carry the text), and string fields from the name list. The
   feet-and-inches and fraction formats (10, 13-18) stay empty with an
   `Unsupported` warning (the reference does not spell them either).
4. Rows carry `Row::ix`; markers reference it. A tab run's `ix` is the
   row of its first tab stop, since the model stores one stop per row.

### Open issues

1. **P8-07 (the join).** `text.rs` attaches text to the *k*-th shape
   record with the *k*-th shape of `document.shapes`, following
   `shape.rs`'s "shapes are added to the document arena in stream
   order" contract. If P8-04 ever skips a malformed shape record or
   adds shapes in another order, text attaches to the wrong shape;
   the pipeline should then pass a record-to-`ShapeId` map instead.
2. **P8-07 (options).** The pipeline must call `collect_with` with the
   stream's `FormatVersion` and the code page from the summary streams
   (the `fdo86729` pair differs exactly there); `collect` alone assumes
   version 11 and Windows-1252.
3. **P8-06 (font records).** `text.rs` reads `FontIX`/`FontFace` for
   the `Font` cell names and `Name2` for field strings. `style.rs` is
   specced to drop font records with a warning; the two modules should
   not warn twice for one record, so P8-07 should decide who reports.
4. **P8-10.** The trailing per-cell blocks of `CharIX` (letterspace,
   AsianFont, ComplexScript cells) are not interpreted; those cells
   stay unset. Feets-and-inches and fraction field formats need
   expectations from `tdf76829-numeric-format.vsd` before they are
   spelled.

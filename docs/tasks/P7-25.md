## Why

The user's second manual pass (2026-10-31, at `514e45b`): there is no
way to add text to a shape, and the Text tool loses text, draws two
outlines and doesn't undo.

## Goal

4. **The Text Block tool** can be chosen with a text box or shape
   selected, and a drag moves and resizes the text block (`TxtPinX`,
   `TxtPinY`, `TxtWidth`, `TxtHeight`; one undo step per drag). Today
   `tools.text_block` has a `commands.yaml` row and no handler.
5. **The Text tool's icon** reads as a thumb. Replace it with a clear
   letter-A text icon from an open-licensed set (Tabler is the set
   already used), then run `cargo xtask codegen`.
8. **Adding text to a shape:** double-clicking a shape, typing a
   character with a shape selected, or pressing F2 starts editing its
   text, as in Visio. A typed character starts the text with that
   character.
9. **The Text tool:**
   - while editing, one outline shows, not both the text box's and the
     shape's;
   - Undo (Cmd+Z, Ctrl+Z, the button) removes a text object just made,
     with its text, in one step;
   - any click with the Text tool first commits the text being typed;
     a click inside an existing text object edits that object's text,
     and a click on empty page starts a new one (today the tool's
     `PointerUp` always inserts a new box, so a click inside the old
     object's border drops the typed text);
   - Escape ends editing and keeps the text.

## Result

All four items are fixed and each has a real-input test in both
layouts (Panel Classic and Panel Modern) in
`crates/ui/tests/phase7/text_fixes.rs`, driven through `ShellRig`:
canvas pointer clicks and drags, tool button clicks, typed text and
key presses (F2, Escape, Cmd+Z, Ctrl+Z), checked on the shape's text,
its cells and the rendered picture.

- **Item 4 — the Text Block tool.** `tools.text_block` gets its
  handler (`ActiveTool::TextBlock`, `tools.text_block` row) and a new
  `crates/ui/src/tools/text_block.rs`. With a shape or text box
  selected the tool shows its text block as a handle frame (the
  `Txt*` cells' box, ADR 0024's placement rule, the documented
  defaults when the shape has none) and one drag moves or resizes it:
  the interior — or any press on the shape — moves the block, the
  edge and corner handles resize it. The release commits one
  `shape.set.text_block` intent (`TxtPinX`, `TxtPinY`, `TxtWidth`,
  `TxtHeight`; one undo step per drag, ADR 0040). Real-input tests:
  a button click chooses the tool with the shape selected and the
  drag's cells and undo are checked in both layouts.
- **Item 5 — the Text tool's icon.** `tools.text` now maps to the
  Tabler `typeface` glyph (a clear letter-A text icon); the thumb-like
  `letter-a` leaves the vendored set and `cargo xtask codegen` was
  run. The test clicks the Text tool button in both layouts and
  matches its rendered icon against the project's own rasterisation
  of `typeface` (and against no other icon).
- **Item 8 — starting text on a shape.** Double-clicking a shape
  starts editing its text (the pointer tool keeps P7-22's group click
  rule), F2 starts editing, and a typed character with a shape
  selected starts the text with that character (replacing the old
  text). Real-input tests cover all three in both layouts.
- **Item 9 — the Text tool.** While editing, one outline shows (the
  text block's, in the selection colour; the tool overlay is
  suppressed — it used to show both the text block's and the shape's).
  A click with the Text tool first commits the text being typed; a
  click inside an existing text object then edits that object's text
  (its text is never dropped) and a click on empty page starts a new
  one (the tool's `PointerUp` no longer always inserts a box). The
  new box and its text are inserted as **one undo step** (a deferred
  insert: `insert.drawing.text_box` gains a `text` argument), so
  Undo — Cmd+Z, Ctrl+Z and the Undo button — removes the text object
  with its text in one step (all three undo inputs tested in both
  layouts). Escape ends editing and keeps the text (shape and new-box
  cases). A second `text.begin` on the shape being edited keeps the
  buffer.

Notes and open issues:

- `tools.text_block`'s enablement predicate follows the committed
  `contexts.yaml` row (as the other tools, a document open), not a
  selection requirement; the drag itself acts on the selection. The
  task sentence ("can be chosen with a text box or shape selected")
  holds either way.
- The keys of item 8 fire on the page keyboard scope (the canvas has
  the keyboard) with no dialog open, so a field in Options or Page
  Setup keeps its own typing. Visio also fires F2 after a toolbar
  click; that wider scope is a follow-up if wanted.
- A click with the Text tool inside the box **just made** (not yet in
  the model at click time) starts a new pending edit at that point —
  the typed text is committed first and never dropped; re-editing the
  same fresh box needs a later click. The literal task bullets hold.
- The Text Block tool's resize keeps the block centre fixed (the
  pointer tool's rule) and its handle frame is axis-aligned for a
  rotated block (`TxtAngle` writes are out of item 4's scope).
- Both layouts have the Text Tool and Text Block controls (Classic's
  "Text Block Tool" sits inside the Text Tool split's menu, Modern's
  is "Text Block"); the Undo button differs per layout (Modern names
  it for the last edit, "Undo Insert Text Box") and the tests handle
  both. No one-layout-only control was needed.
- The golden images tolerate the icon change (the ADR 0027 metric);
  they pick it up at the next regeneration.

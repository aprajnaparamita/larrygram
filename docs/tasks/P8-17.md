### What was built

### Deviations

- The renderer change is per *kind* (one fill path and one stroke path
  per shape), not one node per section: the section flags filter which
  rows reach each path, which is what the flags mean. The paints come
  from the shape's cells, so per-section nodes would carry identical
  paints.
- The fill rule (goal 4) is derived from one discriminating case in
  the corpus (the `no-bgcolor` box) and the twins' PDFs; the corpus has
  no shape whose fill section holds several open sub-paths that should
  fill separately. The closed-sub-paths case is covered by a test.
- `crates/render/tests/build_scene.rs`-style scene tests live in
  `build.rs`'s test module for the new renderer behaviour (P8-15's
  precedent for renderer fixes).

### Open issues

1. **The twin comparison does not normalise the drawing scale** (the
   unit rule above): every length of a scaled drawing reports as
   different. The fix is to scale the twin's lengths by
   `PageScale / DrawingScale` before comparing, in
   `crates/render/tests/twins/compare.rs`.
2. **`geometry rows` compares own rows, not resolved rows**: the twin
   states only the rows that differ from the master's. The comparison
   should compare the row union `Document::shape_geometry` resolves.
3. **The text block margins import as 0** (`LeftMargin`,
   `RightMargin`, `TopMargin`, `BottomMargin`): the `TextBlock`
   record's margin values do not map (the P8-06 mapping), so the text
   boxes lay out wrong. This is half of goal 5's `text-box.*`
   mismatches.
4. **The field display text** (goals 3 and 6): a field prints its
   placeholder (`Page-1`) where Visio prints its computed value
   (`10'-0"`, `5'-0"`, `4'-0"`, `6'-0"`, dates, angles). The `.vsd`
   records carry the value and the format number but not the display
   text, so the text must be spelled from the value in the cell's
   format (feet and inches, dates, currency, angles) through what
   `crates/shapesheet` offers; that work did not land here. The twin's
   texts show exactly what Visio prints (they are corpus content and
   are not committed).
5. **Text boxes** (goal 5): the text transform lands on the wrong box
   on the corpus (`text-box.x/y/width/height` mismatches), and the
   `fdo86729` "aaa" text sits at the top-left corner where the twin's
   PDF centres it in the top box. The causes are the margins (open
   issue 3) and the `TxtPin*` resolution through the master chain.
6. **Hairline strokes draw sub-pixel** (the dimension lines and ticks
   of `Visio6PlanWithDimensions`): their weight is 0.00007 in after
   the drawing scale and the raster draws sub-pixel strokes as
   nothing, while Visio floors a hairline at one device pixel. The
   lines are in the scene and the SVG; the PNG needs a hairline floor
   (a renderer policy this task did not add, since it would touch every
   thin stroke in every golden).
7. **The hatch fill** of `Visio6PlanWithDimensions`'s room renders as
   a dot grid where Visio draws diagonal lines (the ADR 0023 tile
   spacing), and the labels' coloured text backgrounds do not draw.
8. **Quick-style and theme colours** (P8-10's open issue 1, P8-15's
   open issue 4) and the document-scope shape, connects, the template
   marker, the creation date and the summary code page (P8-07's and
   P8-10's open issues) are unchanged.

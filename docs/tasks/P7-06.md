## Goal

Render the Panel Classic layout as described in `docs/ui/panel-classic.md`:

1. **Menu bar.**
   - Mouse: click to open; hover switches menus while one is open.
   - Keyboard: Alt/F10 focus, Alt+letter, arrows, Enter, Esc.
2. **Menus.**
   - A gutter for icons and check marks, right-aligned shortcuts and
     separators.
   - Submenus open on hover delay or the Right arrow.
   - Disabled and hidden handling.
   - Run-time lists: recent files, windows and pages now; the others
     through a provider trait with an empty default.
3. **Toolbars.**
   - Docked rows, wrapping, grippers and tooltips.
   - Split buttons, `split_recent`, palettes, colour dropdowns and combos
     (font, size, zoom).
   - `display` modes and latched state from the command's `checked`
     state.
   - View > Toolbars and the right-click toolbar list toggle visibility.
     Visibility is kept per window mode in `Settings`; request the field
     from P7-09.
4. **Floating toolbars** as small egui windows.
5. **Context menus** opened by P7-08's hit-target mapping, plus
   Shift+F10.
6. **Dispatch.** Every activation returns an `Intent` (ADR 0028).
   Widgets never execute commands.

### Deviations from the task text

- The P7-01 stub signature `show(ui, layout)` is kept as a wrapper
  that stores `PanelClassic` in the egui memory and renders with an
  empty registry; the real entry point is
  `PanelClassic::show(ui, &PanelInput)`. `PanelInput` carries the
  layout, the `Registry`, the `AppCtx`, the `WindowMode`, a
  `ListProvider` and an optional `CheckedState`.
- Submenus also open on a click (the spec lists hover delay and the
  Right arrow only).
- Toolbar rows wrap within their `row` group (`horizontal_wrapped`)
  rather than at fixed row boundaries.
- The right-click toolbar list opens on a right-click anywhere in the
  toolbar area, buttons included.
- Menu-row icons paint through `icons::placeholder` (custom rows);
  toolbar buttons use today's `icons::icon` atoms. Both draw the same
  placeholder mark; P7-09 swaps in P7-04's `icon_atom` with the theme
  tints.
- Colours are the egui defaults until P7-05 merges the theme tokens.

### Open issues

1. **Window and page switching commands.** The `windows` and `pages`
   lists render disabled rows: the registry has no window- or
   page-switching id. The rows carry the target name as a `window` /
   `page` argument, so ids like `window.activate` and `page.activate`
   (P7-02's OUR_COMMANDS list plus handlers) would light them up.
2. **Per-window-mode toolbar visibility on `Settings`.** Requested
   from P7-09: `PanelClassic` keeps the user's choices in its own
   state under `"<mode>/<toolbar id>"` keys; they belong on
   `Settings` in `crates/commands` so they persist.
3. **Checked-state seam.** The registry still has no `checked` state
   (the P5-17 open issue). `PanelInput::checked` takes a `CheckedState`
   and `ToolLatch` derives the tool latches from `AppCtx::active_tool`;
   a `Command::checked` would let this seam go.
4. **`dynamic_label` items** (Undo "Undo Move", "Can't Redo") render
   the static label; the run-time label source is a shell concern for
   P7-09.
5. **Combo entry lists.** The data has no option lists for the font,
   size and zoom combos, so only the editable apply/revert path is
   implemented; a picked entry from a dropdown needs the font list
   (P7-09 wiring or a data addition).
6. **Count pin comparison.** My snapshot counts nested items under
   their own kind and splits `hidden` out; if P7-03's data pin counts
   differently (e.g. only top-level items), the master reconciles the
   two formats when the pin lands. The test that parses the YAML with
   `serde-saphyr` can then switch to P7-03's loader.

## Why

Panel Classic's Format > Fill… and Format > Line… are stubs, and
Panel Modern's Fill Options…, Line Options… and Format Shape do
nothing. P7-24 added colour, weight, pattern and arrowhead submenus as
a stop-gap; they stay (user, 2026-11-01). This task adds the dialogs
that set every fill and line cell at once.

## Goal

1. **Fill dialog** (Format > Fill… in Panel Classic, Fill Options… in
   Panel Modern, and the shape context menu where it has a Fill row):
   fill colour, pattern, pattern colour and transparency
   (`FillForegnd`, `FillPattern`, `FillBkgnd`, `FillForegndTrans`),
   with a preview swatch, and OK, Cancel and Apply. The fields open
   with the selection anchor's resolved values.
2. **Line dialog** (Format > Line…, Line Options…): colour, weight,
   pattern, cap, transparency, begin and end arrowheads and their
   sizes, and corner rounding (`LineColor`, `LineWeight`,
   `LinePattern`, `LineCap`, `LineColorTrans`, `BeginArrow`,
   `EndArrow`, `BeginArrowSize`, `EndArrowSize`, `Rounding`), with a
   preview line, and OK, Cancel and Apply.
3. **Format Shape pane** (Panel Modern's `format.shape.pane`): a pane
   with Fill and Line sections built from the same forms, applying as
   the user changes a field, and following the selection.
4. **One undo step** per OK or Apply, over every selected shape. Cancel
   changes nothing, including after an Apply (Apply's step stays; only
   later edits are dropped).
5. **The command contract** (AGENTS.md section 6): `format.fill` and
   `format.line` with arguments apply without a dialog (CLI, control
   channel, MCP); without arguments they request the dialog. Disabled
   with no selection, with the reason.
6. Reuse the picker tables (`pickers::PATTERNS`, `ARROWS`, the
   colours) rather than new ones. If P7-27 has merged, read its single
   label table.

## Why

The Opus review of P7-41 (2026-11-04) found no blockers but four
majors, one a regression against main:

- **M1:** the editor's rect is now the tight ink box of the drawn
  glyphs, and the same rect drives the outside-press commit and the
  field's wrap width. A click just right of the last letter, or on a
  second line typed below the old text, ends the edit; the field wraps
  at about 80 px while the drawn text wraps at the block width. The
  1× and 2× goldens show the caret outside the box.
- **M2:** the drawn text and the editor's text show at once. Where
  egui's face differs from the drawn one (Carlito), a grey ghost shows
  beside the typed glyphs, and deleted letters stay visible under the
  field. That misleads users.
- **M3:** while the editor is open, `capture_escape` eats Escape before
  an open format popup sees it, so Escape in the font size list ends
  the edit instead of closing the list.
- **M4:** the commit-first rule on the quit and close paths has no UI
  test.

## Goal

1. **The block is the box** (M1). The commit test, the fill and the
   wrap width use the text-block rect (the `text_block_bounds` path),
   joined with the field's own response rect so a field that grows
   with typed lines never commits on a press inside itself. Keep the
   ink data only for the font size and the first baseline. Tests, real
   input, both layouts: a click just right of the last letter moves the
   caret and keeps the edit; a click on a newly typed second line keeps
   the edit; the field wraps where the drawn text wraps (a long append
   wraps at the block width, not at 80 px). Regenerate the two goldens
   and check the caret is inside the box.
2. **One text at a time** (M2). While a shape's text is being edited,
   the canvas does not draw that shape's text: only the editor shows
   it. Its geometry, fill and line still draw. When the edit ends, the
   drawn text comes back (committed or not). Test it on the rendered
   picture: with the editor open the shape's text pixels are absent
   from the canvas layer; after commit they are back with the new text.
   If the render needs an option to leave one shape's text out, add it
   with a unit test in `crates/render`; otherwise keep it in the canvas.
3. **Escape belongs to an open popup** (M3). When a popup or other
   foreground layer is open, `capture_escape` leaves Escape to it.
   Test: type in a new box, open the font size list, press Escape: the
   list closes, the editor stays open with its text; Escape again ends
   the edit.
4. **The quit and close tests** (M4), real input, both layouts:
   - the window close request with an empty new box on a clean drawing:
     no dialog, the window closes;
   - the close request with typed text: the dialog appears, and Don't
     Save closes without the text;
   - Cmd+Q (Ctrl+Q off macOS) with typed text: the dialog appears;
   - `file.exit` from the menu with typed text: the dialog appears.
5. **Undo and Redo with an open group** (review minor 1). While a
   non-empty group is open, the Undo label names the group's step
   ("Undo" plus its label) and one click undoes that step only: a typed
   box is committed and undone whole; an untyped box is cancelled and
   nothing else is undone, with no error. Redo is disabled while a
   non-empty group is open. Test the labels, the enabled state through
   accesskit and Redo afterwards.
6. **An empty new box is not a change** (review minor 7). While the
   open group holds only a new, empty text box, the drawing does not
   read as changed: no title marker, and the macOS hook answers
   `NSTerminateNow`. Choose the simplest rule that gives this and say it
   in the ADR 0040 amendment. Test the title.
7. **Rotated and flipped shapes** (review minor 2). Drop the font data
   (size and baseline) when the shape's transform is not axis-aligned
   and unflipped, not only when `TxtAngle` is set. Test a shape with
   `Angle` 30° and a flipped one.
8. **A popup's own field keeps its typing** (review minor 3). Pressing
   in a foreground layer hands focus back to the editor only when the
   layer has no focusable field of its own. Test: type a custom size in
   the Size picker's field while editing; the digits land in the field,
   not in the shape text.
9. **The rest:**
   - `insert.shape` sets `Outcome::shape` like the other creation
     commands (review minor 4);
   - a test that `is_dirty()` stays true after a partial revert in
     `AppCtx::cancel_group`, and one ADR 0040 line saying the pushed
     step re-reverts the edit that failed (review minor 5);
   - the test gaps of review minor 6: the enabled state through
     accesskit after each click in the new flows, the picture in each
     flow, Bold and the 36 pt size checked in the cells of
     `format_clicks_on_an_existing_shape_are_one_step_each`, the undo
     list after each step in `formatting_while_typing…`, and the undo
     button's enabled state, label and Redo afterwards.

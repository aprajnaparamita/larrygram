## Goal

1. **Shapes.** Shape group, shape and guide-shape records to
   `larrygram_model::Shape` values in the document arena: `visio_id`
   from the shape-id record, names from the name lists the records
   reference, nesting level to `parent`/`children`, and master, line,
   fill and text style references kept as Visio ids (never resolved or
   flattened).
2. **Transforms.** The transform records to the `Xform`, `Xform1D` and
   `TextTransform` cells, with the unit rule of ADR 0070 (lengths in
   inches, angles in radians, flips as booleans).
3. **Geometry.** Every geometry row kind (move, line, arc, elliptical
   arc, spline knots, NURBS, polyline, infinite line) to a `Geometry`
   section row with its cells; the geometry list records set the row
   order and the section's `NoFill`, `NoLine` and `NoShow` cells.
4. **Degrade, never crash.** An unknown record is skipped with a
   warning; a bad value is a `BadValue` warning and the cell stays
   unset (ADR 0071). `Limits::max_shapes` is enforced.

### What was built

`crates/vsd-binary/src/shape.rs` (the stub is gone; no
`Err(Error::NotImplemented)` remains in it):

- **Shapes.** The shape group, shape, guide shape and foreign shape
  records map to `larrygram_model::Shape` values, added to the arena in
  stream order. The nesting level builds `parent`/`children`. The
  `visio_id` comes from the shape-id records (`0x83`, gathered by the
  shape lists `0x65`): each new shape takes the next unconsumed id of
  the most recent list, falling back to the record's own id; a shape
  with neither gets `visio_id` 0 and a `BadValue` warning. Names come
  from the name records (`0x2d`, `0x33`) through the name indexes
  (`0xc9`, `0x34`), the nearest preceding index outside the shape's
  record group. Line, fill and text style references stay Visio ids.
- **Transforms.** `XFormData`, `XForm1D` and the text transform map to
  the `Xform`, `Xform1D` and `TextTransform` cells. Each value is a
  unit-tagged double (the tag names the *display* unit, the value is
  canonical: inches, radians); the tag maps to the cell's `Unit` exactly
  as the `.vsdx` reader maps a `U` code. An unknown tag or a non-finite
  value is a `BadValue` warning and the cell stays unset. `FlipX` and
  `FlipY` are booleans.
- **Geometry.** Every row kind (move, line, arc, elliptical arc,
  spline start, spline knot, ellipse, infinite line, NURBS, polyline)
  maps to a `Geometry` section row with its `X`, `Y`, `A`..`D` cells.
  The geometry list records open the sections and set the row order;
  the geometry flags record sets the section's `NoFill`, `NoLine` and
  `NoShow`. `NurbsTo` and `PolylineTo` rows get their formula-encoded
  `E`/`A` cell (`NURBS(...)` / `POLYLINE(...)` in the spelling
  `larrygram_model::geometry` parses, ADR 0019) from the referenced
  curve-data record (`0xd1`) or the inline formula block of the row.
- **Degrading.** Inside shape record groups: the dropped list of ADR
  0070 (foreign data, OLE, hyperlinks, events and macros, annotations,
  reviewers, smart tags, the font list) warns `Dropped`, a record kind
  outside the format id table warns `SkippedRecord`, and the records
  other domain modules map stay silent. Truncated payloads warn
  `BadValue` and keep the cells that parsed. Every count read from a
  payload is bounded by what the payload can hold.
  `Limits::max_shapes` is enforced (`Error::LimitExceeded`).
- **Tests.** 79 hand-built unit tests: every record kind this task
  maps, both versions' name layouts, malformed payloads (truncations at
  every level, lying counts), and the pinned comparison with the
  `.vsdx` reader below. `crates/vsd-binary/src/shape.rs` is at 100 %
  line coverage.

### Deviations

1. **`collect_with` added.** The frozen P8-01 seam `collect(chunks,
   document, warnings)` has no version or caps parameter, but the task
   requires both version payloads and `max_shapes`. `collect` keeps its
   signature and forwards to the new
   `collect_with(chunks, version, limits, document, warnings)` with
   `FormatVersion::V11` and `Limits::DEFAULT`. The version matters only
   for the name payloads (version 6 single-byte text, version 11
   UTF-16LE); the shape, transform and geometry payloads are shared.
2. **Master reference.** `Shape::master` is `Option<MasterId>`, so it
   cannot hold a raw Visio id; the reference resolves to the master with
   the same `visio_id`, exactly as `crates/vsdx/src/read/**` resolves
   `Master`, and one that resolves to nothing warns
   `UnresolvedReference`. The line, fill and text style references are
   kept as Visio ids as the goal says. The shape record's master-shape
   field has no model slot (see open issues).
3. **One name per element.** The binary format carries one name, so
   `Shape::name` and `Shape::name_u` receive the same string (the
   corpus's `.vsdx` files spell both alike).
4. **Pinned comparison test.** `the_mapped_fields_match_the_vsdx_reader`
   pins the values `crates/vsdx/src/read/**` produces for the same
   drawing (shape fields, direct cells with values and units, the
   `Geometry` section with its rows). The values were validated against
   the live reader during development (identical model output, including
   units and cell order); the committed test pins them because a live
   cross-reader test needs a dev-dependency on `larrygram-vsdx`, which
   fails `cargo xtask layers` (both crates are L2 and the check covers
   dev-dependencies too — verified).
5. **Row `IX`.** Geometry rows carry `ix` = their 1-based position after
   the list order, the spelling Visio writes on `.vsdx` `Geometry` rows.

### Open issues

- **P8-03 (chunks):** list records (shape list `0x65`, geometry list
  `0x6c`) put part of their children-id list in the record trailer,
  past the declared `dataLength` (seen in every corpus file: a geometry
  list of 6 rows carries 4 ids in the payload and 2 in the trailer).
  `Chunk::data` should include that trailing region for list records,
  or the row order degrades to stream order with a `BadValue` warning.
- **P8-07 (pipeline):** (a) the shape record's master-shape field (the
  master shape a shape instantiates) has no model slot and is dropped
  silently; (b) the shape record's own parent field is unused — the
  levels define nesting, per the goal; if `read_chunks`' flattened
  levels do not nest the sub-shape pointer streams, the parent field is
  the fallback to wire in; (c) a shape's `NAME_LIST`/`NAME` records name
  its shape-data fields, not the shape — the property mapping consumes
  them.
- **P8-10 (tests):** (a) a live cross-reader comparison test belongs in
  a crate at L3+ (e.g. `crates/render/tests`), where a dependency on
  both `larrygram-vsdx` and `larrygram-vsd-binary` is legal; (b)
  `FlipX`/`FlipY`: Visio writes `V='0'` with no `U`, which the `.vsdx`
  reader classifies as `Number(0.0)`, while ADR 0070 makes the importer
  produce `Bool` — a corpus round needs the write side to spell
  `U='BOOL'`, or ADR 0070 revisited.
- **P8-08 (census):** record kinds the id table of
  `VSDDocumentStructure.h` does not name (`0x17`, `0x21`, `0x23`,
  `0x24`, `0x28`, `0x29`, `0x2a`, `0x2b`, `0x2e`, `0x2f`, `0x31`,
  `0x35`, `0x3c`, `0x40`, `0x44`, `0x45`, `0x4f`, `0x67`, `0xa3`,
  `0xb9`, ...) are skipped with a `SkippedRecord` warning inside shape
  groups; the census should name them so the report gets better labels.

## Goal

1. **The Delete key does nothing** on a selected shape or text box; it
   must delete the selection (`edit.clear`, P7-20). Find where the key
   is lost (canvas focus, a text-edit consumer, the shortcut filter)
   and fix it there.
2. **Right-clicking a selected group** offers no Group or Ungroup. The
   shape context menu offers Group with two or more shapes selected and
   Ungroup on a group, plus the arrange basics P7-21 built (bring to
   front, send to back, rotate, flip).
3. **Cut on a shape inside a group** cuts only that shape. A first
   click on any member selects the whole group, as Visio does; a
   second click on the selected group subselects the member. Cut,
   Copy, Delete and the context menu then act on what is selected,
   which is the whole group after one click.
4. **Insert > Text Box** (and its Horizontal and Vertical items) is
   disabled on a new document. `insert.text.box` and
   `insert.vert.text.box` must work: they switch to the text tool (or
   place a text box at the page centre, your choice; say which).
5. **Insert > Picture** is disabled. Implement inserting a PNG or JPEG
   from a file as an image shape (the shell's file dialog asks for the
   path; the command takes `path` as an argument). The image must
   render, save to `.vsdx` and reopen. If the model or writer cannot
   carry an image yet, say what is missing and stop at that boundary
   with a clear disabled reason.
6. **No right-click menu offers Delete** (or Clear): the shape
   context menu gets Delete, enabled with a selection (user's second
   pass, 2026-10-31). The second pass also confirmed item 1 on every
   kind of shape, a text object included.
7. **Flip does not draw** (P7-21's open issue): `render` honours
   `FlipX` and `FlipY`, including inside groups and on text.

## Result

Filled in by the worker at hand-off (branch `agent/P7-22`).

### What changed, item by item

1. **The Delete key** (`crates/ui/src/shortcuts.rs` `key_token`): an
   unmodified `Key::Backspace` is now the `Delete` token. The macOS
   delete key *is* egui's `Backspace` (winit `NamedKey::Backspace`;
   forward delete is `Key::Delete`), so the `Delete` bindings never
   matched it and the shortcut filter dropped the key. With a
   modifier the key stays `Backspace`, so `Ctrl+Backspace` remains
   delete-back-word and egui's text edit keeps its plain Backspace.
   Real-input tests press both keys in both layouts.
2. **The shape context menu offers Group and Ungroup** (goal 2): a
   right-click on a hit inside the sole selected shape keeps the
   selection (`press_target` in `tools/pointer.rs`, used by
   `canvas_context_click`'s small hunk in `shell.rs`), so with a group
   selected the menu acts on the group and Ungroup is enabled. The
   `arrange.group` predicate is now "two or more shapes selected" (the
   goal's rule; four documented cross-check rows keep the 2007 table's
   group/picture/container entries as differences). The arrange
   basics are in both shape menus: Classic's Shape submenu gains
   Rotate Left and Rotate Right, Modern's Group submenu gains Bring to
   Front, Send to Back, Rotate Left 90, Rotate Right 90 and the two
   flips.
3. **Cut on a shape inside a group** (goal 3): the click rules now
   match the goal — a first click on any member selects the whole
   group (the top-level ancestor), a second click subselects the
   member one level below the selection (on release, so a drag from a
   member of the selected group still moves the group). Cut, Copy,
   Delete and the context menu act on what is selected. Inside an
   entered group the P5 rules win unchanged.
4. **Insert > Text Box** (goal 4): `insert.text.box` and
   `insert.vert.text.box` are implemented. **They place a text box at
   the page centre** (2 x 0.5 in, the P5-07 size) and select it (the
   placement choice of the goal); the vertical form stands upright
   (`Angle` = 90 degrees).
5. **Insert > Picture** (goal 5): `file.import` (Classic's Insert >
   Picture > From File) and `tools.picture.insert.from.file` (Modern's
   Pictures...) take `path`; the shell's picture dialog arm asks for
   it (PNG/JPEG extensions) and the command validates the file
   (bounded PNG/JPEG header parse, never panics). It then **stops at
   the pipeline boundary with the clear disabled reason** ("needs the
   .vsdx image writer ... and the image renderer"): the escape clause
   of the goal applies because **the writer cannot carry a new image**
   — see "What is missing" below. No shape is created: a picture that
   would neither draw nor save is not an inserted picture.
6. **Delete in the context menu** (goal 6): both shape context menus
   gain a Delete row (`edit.clear`, `visCmdUFEditClear`) after Paste,
   enabled with a selection.
7. **The flip** (goal 7): **already worked on the current code** —
   `build.rs` `shape_transform` has composed `FlipX`/`FlipY` into the
   shape transform since Phase 3 (commit `eafa1ff`), and both
   backends compose that transform into path and glyph painting
   (`png.rs` `draw_text`, `svg.rs`). Real-input tests pin it in both
   layouts: a plain shape, a member inside a group, and a shape
   carrying text.

### Why the earlier tests missed each finding

1. **Delete**: the tests pressed `Key::Delete` (the forward-delete
   key) or dispatched `edit.clear` directly; the chord tests built
   `Delete` chords synthetically (`shortcuts_dispatch.rs`,
   `basic_set.rs`). No test pressed the macOS delete key, which is
   `Key::Backspace`.
2. **Group/Ungroup**: the P7-10 context-menu sweeps drove the menu
   widget seam (`ClassicRig`) against a hand-set selection; no test
   right-clicked the canvas in the full shell. The right-click path
   re-selected the leaf hit, so every greyed row looked "correct" to
   the widget-level sweeps.
3. **Cut inside a group**: same right-click clobber, plus no test
   clicked a group member twice (`selectable_shape` was pinned at
   page level only).
4. **Text Box**: the commands were stub rows; P5-07's tests drove the
   tool's own `insert.drawing.text_box` with explicit arguments. No
   test clicked the Insert menu.
5. **Picture**: the commands were stub rows and no image pipeline
   exists at all, so there was nothing to test against.
6. **Delete row**: the sweep tests pin the rows the data *has*, not
   the rows a user expects; a missing row cannot fail a data-driven
   sweep.
7. **Flip**: P7-21's own open issue was wrong (it claimed
   `crates/render` ignores the cells; the cells have been honoured
   since the scene builder landed). Its tests called
   `shape_transform` directly and its manual check ran against the
   stale build where the flip commands were still stubs.

### What is missing for images (item 5's boundary)

- `crates/vsdx`: `generate_package` (a document built in memory) has
  no way to emit binary media parts and their relationships;
  `package_for` rejects a preserve package that has parts but no
  Visio document. Media survive a save only when a read document
  already had them (the preserved package). Needed: media-part
  emission for a shape's `ForeignData` `RelID`, plus content types
  and page relationships, for new shapes.
- `crates/render`: `Scene` has no image node and the builder ignores
  `ForeignData`, so an image shape cannot draw (this task owns the
  render crate "flip only"). Needed: an image node plus both
  backends and the egui texture seam in the canvas.

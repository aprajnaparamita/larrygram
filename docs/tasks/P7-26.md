## Goal

1. **The Text Block resize moves the block off-centre (B1, high).**
   `shape.set.text_block` writes `TxtPinX`, `TxtPinY`, `TxtWidth` and
   `TxtHeight` but not `TxtLocPinX`/`TxtLocPinY`, whose default
   follows the shape's width, not `TxtWidth`. On a shape drawn in the
   app (no `Txt*` cells), a resize draws the block away from where the
   preview showed it. Fix it so the block lands where the preview put
   it. The smallest fix is that the command also takes `loc_x`/`loc_y`
   and the tool sends half the new size. Test on a shape drawn with
   the Rectangle tool (no `Txt*` cells) as well as on the fixture,
   and check the rendered picture: the text's ink sits where the
   preview frame was.
2. **A typed character starts shape text while another field has the
   keyboard (B2).** `text_edit_keys` checks only the shell's focus
   scope. Return early when egui wants keyboard input
   (`ctx.wants_keyboard_input()`), or when a popup or menu is open.
   Test: select a shape, type into a Panel Classic floating toolbar's
   Font or Zoom box placed over the canvas, and check the shape's
   editor stays closed. Test the same with a Format menu opened from
   the keyboard and its access keys.
3. **A click inside the new text box opens a second box (B3).** The
   editor field is one row high but the outline covers the whole box,
   so a click lower in the box commits the text and starts a new box.
   A click inside the box being typed moves the caret (or does
   nothing) and keeps editing. Either consume the click in the shell
   or make the field fill the outlined box.
4. **Escape and the Format Painter (A1).** With a copy recorded, Escape
   cancels it whatever tool is active, and choosing another tool
   clears the copy (a copy never outlives a tool change). Once no copy
   is recorded, Escape leaves full screen again. Test all three with
   real key presses and tool clicks.
5. **Test gaps (B7):** type three characters into a shape that starts
   with a typed character and check `"Qrs"`; redo of a new text box
   brings back the shape and its text in one step; the Text Block
   move test checks the ink moved by the drag's distance, not only
   that the picture changed.
6. **Undo safety (B5):** `insert_drawing` inserts the shape before it
   builds the undo record and the text step. If either fails, the
   shape stays with no undo record. Build them before the insert, or
   remove the shape on the error path, with a test.
7. **ADR 0044 (B4):** amend it for the deferred insert: the Text tool
   inserts the box with its text on commit, in one undo step, and
   `insert.drawing.text_box` takes `text`.
8. **Resize handles on rotated shapes and the fixed edge (B6).** In
   both the pointer tool and the Text Block tool, an edge or corner
   drag keeps the opposite edge or corner fixed (as Visio does; today
   the centre stays fixed and the handle moves half the pointer's
   distance), and on a rotated shape or text block the drag is
   measured along the shape's own axes. Test at 0 and 90 degrees: the
   dragged handle follows the pointer.
9. **Drag to size a new text box (B8).** With the Text tool, a drag on
   empty page makes a box of the dragged size; a click keeps today's
   default box.

## Result

## Result

Done (2026-11-02). All nine items are in, each with a real-input test
in the full shell (`ShellRig`, egui_kittest) in both committed layouts
where the control exists.

1. **B1, the Text Block resize lands where the preview showed it.**
   `shape.set.text_block` takes `loc_x`/`loc_y` and writes
   `TxtLocPinX`/`TxtLocPinY` with the pin; the tool's resize drag
   sends them. Tests: the fixture (explicit `Txt*` cells) and a
   Rectangle-tool shape (the materialised defaults), each checked on
   the cells and on the rendered ink — the ink keeps its place at the
   block's top-left corner across the resize (the check fails with
   the pin-only write: verified).
2. **B2, the typed character stays out of another widget's keyboard.**
   `text_edit_keys` returns early when egui's focus sits on another
   widget (the canvas's own id is the only focus that may start shape
   text) and when a menu or popup is open (sampled at the end of the
   frame: egui knows its popups only once they draw, and the Classic
   menus draw as their own areas, so `PanelClassic` gained the
   `menu_open` seam). Tests: Tab gives another widget the keyboard and
   the typing goes there; the Format menu opened with Alt+O keeps its
   access letters ("g" opens Fill Color) and starts no text; a
   Shift+F10 context menu keeps its keys; with the Format Shape pane
   open and the canvas's keyboard, a typed letter starts the shape's
   text, and a pane field keeps its own typing.
3. **B3, a click inside the new text box keeps editing it.** The
   pending box's editor field fills the outlined box (its egui area
   covers the box, so the click is a caret move) and the shell drops
   the raw pointer events inside the box bounds as the backstop. Test:
   the click lower in the box neither commits nor opens a second box;
   Escape inserts one box with the typed text (fails without the fix).
4. **A1, Escape and the Format Painter.** The shell pushes the
   `tools.format_painter` cancel intent itself with a non-pointer tool
   (the tool route only reached the painter on the pointer tool), and
   `tools.*` `choose()` clears a recorded copy on a tool change. Tests:
   Escape cancels the copy whatever tool is active, a tool change
   clears it, and Escape leaves full screen again once no copy is
   recorded (while one is recorded it cancels the copy and stays).
5. **B7, the test gaps.** Three typed characters land as "Qrs" (the
   caret sits after the seed and no key is dropped between
   `text.begin` and the editor taking focus); redo (Ctrl+Y) brings the
   new text box back with its text in one step; the Text Block move
   test checks the ink moved by the drag's distance.
6. **B5, the undo safety.** `insert_drawing` and the page-centre text
   boxes stage their undo record and the text step through
   `stage_insertion`: a failure after `insert_shape` detaches the
   shape again. The rollback path has a test with a failure injected
   at the seam.
7. **B4, ADR 0044.** Amended for the deferred insert (the box and its
   text are inserted on commit in one undo step,
   `insert.drawing.text_box` takes `text`, a click inside the box is a
   caret move) and for the dragged box (item 9).
8. **B6, the resize handles.** Both the pointer tool and the Text
   Block tool measure a resize drag along the frame's own axes and
   keep the opposite edge or corner fixed, so the dragged handle
   follows the pointer. `shape.resize` gained the `edge` argument and
   writes each target's pin beside the size (the shift is computed
   after the size writes, because their derived-cell refresh decides
   where `LocPinX`/`LocPinY` land; a custom `LocPin*` stays put, and
   the flip cells are honoured). Tests: real drags on the fixture, flat
   and turned one quarter right, in both tools and both layouts; the
   dragged side lands on the pointer and the opposite side stays, on
   the cells and on the drawn frame (both fail with the old
   centre-fixed, page-axis code).
9. **B8, the drag to size.** The Text tool's release keeps the click
   rule (the default 2 x 0.5 in box) and a drag on empty page records
   the dragged rectangle. Test: the dragged box lands at the dragged
   place with the dragged size; a click keeps the default box.

### Deviations outside Owns

- `crates/commands/src/builtins/shape.rs`: `shape.resize` gained the
  `edge` argument (item 8) — the file is owned for
  `shape.set.text_block`, and the fixed-edge rule needs the pin shift
  in the command (it knows the cells' derived-refresh rule).
- `crates/commands/src/builtins/insert.rs`: `text_box_at_page_centre`
  is staged through the same `stage_insertion` rollback as
  `insert_drawing` (item 6).
- `crates/ui/src/panel_classic/mod.rs`: the read-only `menu_open()`
  seam (item 2).
- `crates/ui/src/shell.rs` `text_edit_keys`: per the master's note the
  Format Shape pane is **not** in the early-return list (only the Fill
  and Line dialogs are): the pane stays open while the user works and
  the keyboard-focus guard covers its fields.
- Item 1's "no `Txt*` cells" case: the insert's derived-cell pass
  materialises the documented defaults as literal cells, so a
  Rectangle-tool shape carries those (they follow the **shape's**
  width, which is the bug's case); the tool unit test covers the
  shape with no `Txt*` cells at all.
- Item 2's review scenario (a floating Classic toolbar's Font or Zoom
  box over the canvas) is not reachable in the shipped layout: the
  floating toolbars (Drawing, Ink, Picture) carry buttons only and
  toolbar docking is not implemented (`docs/ui/panel-classic.md`).
  The keyboard-focus guard is tested through Tab (a widget off the
  canvas takes egui's focus) and through the Format Shape pane's
  field.

### Open issues

- Multi-selection resize: `shape.resize` still gives every selected
  shape the same size (unchanged); with `edge` each target keeps its
  own opposite edge, and the pin shift is the dragged frame's.
- A shape inside a group whose parent is rotated: the drag is
  measured along the page frame while the command shifts the pin in
  the parent frame (the same simplification `shape.move` already
  uses).
- The review's B1 side question stays open for the master: after a
  drag the `Txt*` cells are literals, so the block no longer follows a
  later shape resize. Whether the tool should write proportional
  formulas (for example `Width*0.75`) is a black-box question against
  Visio.
- The `edge` argument's spellings (`north_east`, ...) are our own;
  Visio's exact wording is unrecorded (the same class of question as
  the review's A7).
